## 话题一：LockSupport 与线程阻塞机制（12分钟）

**面试官：Java 里线程阻塞和唤醒有哪些方式？**

你回答（wait/notify、LockSupport.park/unpark、Thread.sleep、Lock的await/signal）...

**追问1：** LockSupport 的 park 和 unpark 和 Object 的 wait/notify 有什么区别？

你回答（park不需要获取锁、unpark可以先于park调用、wait必须先获取对象锁、unpark是许可模式不会累积）...

**追问2：** unpark 先于 park 调用会怎样？为什么说"许可不会累积"？

你回答（unpark给线程发一个许可、park检查许可有则返回不阻塞、连续unark两次只有一个许可、许可不累积）...

**追问3：** AQS 里面用的就是 LockSupport 来阻塞线程的，你能说说 AQS 获取独占锁的流程吗？

你回答（tryAcquire尝试获取、失败则addWaiter入队、acquireQueued自旋检查前驱、park阻塞、被unpark后重试获取）...

**追问4：** 线程被 park 阻塞后，除了被 unpark 唤醒，还有什么情况会自动醒来？

你回答（线程被中断interrupt、虚假唤醒spurious wakeup、所以park返回后要重新检查条件）...

**追问5：** 你在实际项目中有没有用过 LockSupport 或者 AQS 相关的工具？CountDownLatch 和 CyclicBarrier 底层都依赖什么？

你回答（CountDownLatch依赖AQS的共享模式、CyclicBarrier依赖ReentrantLock的Condition、await/doawait）...

**追问6：** Semaphore 也是基于 AQS 的，它的许可是怎么实现的？release 一定对应一个 permit 吗？

你回答（AQS的state表示许可数、acquire减state、release加state、release可以不配对调用手动增加许可）...

## 话题二：MySQL undo log 与 MVCC（10分钟）

**面试官：昨天聊到 binlog 和 redo log，MySQL 还有一个 undo log，你了解吗？它的作用是什么？**

你回答（回滚日志、事务回滚时用、MVCC的核心、记录修改前的旧数据）...

**追问1：** undo log 和 MVCC 是什么关系？MVCC 是怎么实现读不加锁的？

你回答（通过undo log构建历史版本链、ReadView决定读哪个版本、非锁定读、读操作不加锁不阻塞写）...

**追问2：** ReadView 是什么时候生成的？RC 和 RR 隔离级别下 ReadView 有什么不同？

你回答（RC：每次SELECT都生成新ReadView、RR：事务第一次SELECT时生成后续复用、所以RR可重复读、RC每次读到最新已提交数据）...

**追问3：** 一个数据行的 undo log 版本链是怎么构建的？多个事务同时修改同一行，怎么找到正确的版本？

你回答（每行有隐藏字段trx_id和roll_pointer、roll_pointer指向undo log、ReadView中有活跃事务列表、对比trx_id判断版本可见性）...

**追问4：** undo log 会不会无限增长？什么时候清理？

你回答（purge线程定期清理、只有没有活跃事务依赖的undo log才能清理、长事务会导致undo log积压）...

**追问5：** 长事务为什么危害大？它对 undo log、redo log、binlog 分别有什么影响？

你回答（undo log无法清理导致回滚段膨胀、占用连接池资源、可能导致主从延迟、锁持有时间长影响并发）...

## 话题三：手写代码 - 删除链表倒数第N个节点（8分钟）

**面试官：写一道链表题。给你一个单链表，删除倒数第 N 个节点，要求只遍历一次。**

```java
public class ListNode {
    int val;
    ListNode next;
    ListNode(int val) { this.val = val; }
}

// 删除倒数第N个节点，返回头节点
public ListNode removeNthFromEnd(ListNode head, int n) {
    // 你来实现
}
```

**追问1：** 你用的是什么方法？为什么要用双指针？快指针先走几步？

你回答（快慢指针、快指针先走n步、然后快慢一起走、快到尾时慢正好在倒数第n个的前一个）...

**追问2：** 如果要删除的是头节点，你的代码能处理吗？有没有什么边界问题？

你回答（需要dummy头节点、避免删除头节点时head变化、或者先走n+1步）...

**追问3：** 如果 n 大于链表长度怎么办？你的代码会报错吗？

你回答（快指针先走时如果提前到null说明n超过链表长度、可以返回原链表或抛异常）...

你回答（O(L)时间L是链表长度、O(1)空间只需要两个指针）...

## 话题四：Spring @Async 与异步任务（10分钟）

**面试官：Spring 的 @Async 注解了解吗？它实现了什么效果？**

你回答（方法异步执行、调用后立即返回、在另一个线程中执行、需要加@EnableAsync）...

**追问1：** @Async 底层是怎么实现的？它用的线程池从哪来？

你回答（AOP代理、拦截@Async方法、提交到TaskExecutor、默认使用SimpleAsyncTaskExecutor每次新建线程）...

**追问2：** SimpleAsyncTaskExecutor 有什么问题？生产环境应该怎么配置？

你回答（每次新建线程没有复用、线程数不可控可能OOM、应该自定义ThreadPoolTaskExecutor配置线程池参数）...

**追问3：** @Async 标注的方法如果抛异常了，怎么捕获？有没有返回值怎么处理？

你回答（异步方法不能try-catch、用AsyncUncaughtExceptionHandler处理无返回值异常、有返回值用AsyncUncaughtExceptionHandler或CompletableFuture.handle）...

**追问4：** @Async 方法内部调用同类中的另一个 @Async 方法，会异步执行吗？为什么？

你回答（不会、内部调用走的是this不是代理对象、和@Transactional一样失效、需要通过AopContext.currentProxy()或注入自己）...

**追问5：** 你们项目里用 @Async 做过什么？有没有遇到过问题？

你回答（异步发通知、异步写日志、注意线程池满时拒绝策略、上下文传递问题ThreadLocal丢失）...

## 话题五：Redis 主从复制原理（10分钟）

**面试官：Redis 的主从复制是怎么实现的？全量复制的过程说一下。**

你回答（SLAVEOF命令、主节点BGSAVE生成RDB、从节点加载RDB、主节点发送缓冲区增量数据）...

**追问1：** 全量复制非常消耗资源，哪些情况会触发全量复制？

你回答（首次连接、主从断连时间过长repl_backlog被覆盖、从节点请求全量同步）...

**追问2：** 增量复制是怎么实现的？ repl_backlog 是什么？

你回答（主节点维护一个环形缓冲区repl_backlog、记录最近写入命令、从节点断连重连后上报offset、主节点从offset开始发送增量数据）...

**追问3：** 如果 repl_backlog 的大小不够，从节点断连后重连会发生什么？

你回答（offset对应的偏移量已经被覆盖、无法增量复制、触发全量复制、所以backlog要设大一些）...

**追问4：** 主从复制是异步的，这会带来什么问题？对数据一致性有什么影响？

你回答（主从延迟、主节点宕机可能丢失未同步数据、读写分离读到旧数据、金融场景主从延迟敏感要评估）...

**追问5：** 哨兵机制是怎么做故障转移的？怎么判断主节点挂了？

你回答（主观下线单个哨兵判断、客观下线多数哨兵确认、选举leader哨兵执行故障转移、选最优从节点提升为主）...

## 话题六：项目深挖 - 路由下沉方案（10分钟）

**面试官：你简历上写了"路由下沉方案"，具体是什么问题？为什么要做这个？**

你回答（接入层路由耦合在业务代码中、新增接口要改多处、路由下沉到基础设施层、业务只关注业务逻辑）...

**追问1：** "下沉"具体下沉到哪一层了？是 Gateway 还是自己实现的？为什么这么选？

你回答（下沉到接入层、当时没有用Gateway、自己实现轻量级路由、按业务域配置路由规则、后面可平滑迁移到Gateway）...

**追问2：** 路由规则是怎么配置的？动态更新还是写死在代码里？

你回答（配置中心管理路由规则、动态刷新不重启、规则变更灰度验证、本地缓存兜底）...

**追问3：** 切换路由方案时怎么做的灰度？怎么保证不影响线上流量？

你回答（新老路由并行、按比例切流量、先切非核心接口验证、监控错误率逐步全量切换、保留回滚开关）...

**追问4：** 切换过程中遇到过什么问题？有没有踩过坑？

你回答（路由规则配置错误导致404、缓存和配置不一致、部分服务还没注册导致路由失败、逐步暴露问题逐步修复）...

**追问5：** 如果现在让你重新做这个方案，和 Spring Cloud Gateway 比，你觉得有必要自己实现吗？

你回答（不需要自己实现、Gateway已经成熟、但当时项目背景不一定能引入Gateway、自己实现也验证了可行性、现在迁移到Gateway更好）...

## 二面话题一：DDD 领域驱动设计理解（12分钟）

**面试官：你简历上写了"DDD领域驱动设计"，说说你对 DDD 的理解？它解决了什么问题？**

你回答（复杂业务建模方法论、统一语言、领域边界、从需求分析到代码实现的一致性、解决贫血模型和业务逻辑散落的问题）...

**追问1：** DDD 里的"限界上下文"是什么意思？你们项目里怎么划分的？

你回答（一个业务边界内的模型是一致的、不同上下文之间通过防腐层交互、营销域、用户域、交易域各自独立）...

**追问2：** 你说的"组件化"和 DDD 是什么关系？是不是就是 DDD 的落地？

你回答（组件化是DDD落地的一种方式、组件对应领域、组件接口对应领域服务、但当时没有严格按DDD规范做）...

**追问3：** DDD 里的实体和值对象有什么区别？你在代码里怎么区分的？

你回答（实体有唯一标识、可变、有生命周期、值对象无标识、不可变、描述属性如Money、Address）...

**追问4：** 很多人说 DDD 太重了，不适合中小项目，你怎么看？什么时候该用什么时候不该用？

你回答（看业务复杂度、简单CRUD不需要DDD、复杂业务规则和多个子域适合DDD、过度使用DDD反而增加复杂度）...

**追问5：** 如果让你重新用 DDD 设计营销活动系统，你会怎么划分？聚合根是谁？

你回答（活动是聚合根、奖品和规则是聚合内实体、渠道是独立上下文、通过领域事件交互、防腐层隔离外部系统）...

## 二面话题二：秒杀系统设计（10分钟）

**面试官：假设让你设计一个金融产品的秒杀抢购系统，比如限量发售一款理财产品，你怎么设计？**

你回答（前端限流、CDN静态化、网关限流、Redis预扣减库存、异步落库、消息队列削峰）...

**追问1：** Redis 预扣减库存，如果一瞬间10万请求同时打到 Redis，Redis 扛得住吗？怎么进一步优化？

你回答（Redis单线程10万+QPS没问题、可以用Lua脚本原子扣减、或者本地缓存先过滤、分段库存减少热点）...

**追问2：** "分段库存"是什么意思？怎么实现？

你回答（把1000个库存分成10段每段100个、不同请求路由到不同段、减少单key竞争、汇总时合并检查）...

**追问3：** 用户抢到了但是不支付怎么办？库存怎么释放？超时时间设多久？

你回答（预扣减后锁定库存、设超时时间15-30分钟、超时自动释放库存、延迟消息或定时任务扫描释放）...

**追问4：** 如果超时释放的库存再卖出去，但之前的用户又回来支付了，怎么处理？

你回答（释放前二次确认订单状态、已超时则拒绝支付、给用户友好提示、防止超卖和重复支付）...

**追问5：** 秒杀结束后系统怎么恢复正常状态？怎么防止有人在秒杀结束后还在刷接口？

你回答（活动结束后关闭入口、网关层拦截、Redis标记活动结束快速拒绝、前端隐藏按钮、日志审计异常请求）...
