|#|知识点|重要度|笔记三层建议|跨模块关联|
|---|---|---|---|---|
|2.1|**正向代理 vs 反向代理**|🔴 必背|① 正向代理：客户端←代理→目标（客户端感知，翻墙/VPN）；反向代理：客户端→代理←服务端（客户端无感知，负载均衡）② 反向代理的作用：隐藏真实 IP、SSL 卸载、负载均衡、静态资源缓存 ③ 面试：解释正向代理和反向代理的区别和应用场景？|→ M5 HTTPS（SSL 卸载在 Nginx 做）|
|2.2|**upstream 七种负载均衡策略**|🔴 必背|① **轮询(round_robin)** — 默认，按顺序分发；② **加权轮询(weight)** — 按权重；③ **ip_hash** — 同一 IP 固定到同一台（会话保持）；④ **least_conn** — 最少连接；⑤ **random** — 随机（两参数版）；⑥ **url_hash** — 第三方，按 URL 哈希；⑦ **fair** — 第三方，按响应时间 ③ 面试：你们用的哪种策略？为什么选这个？ip_hash 有什么坑？（某台挂了怎么办）|→ Spring Cloud Ribbon/Nacos 负载均衡策略（对比学习）|
|2.3|**健康检查机制**|🔴 必背|① **被动检查**：Nginx 内置，请求失败后 max_fails 次，fail_timeout 秒内标记为不可用；**主动检查**：需要第三方模块 nginx_upstream_check_module ② 健康检查接口设计：返回 200 + 可加探针逻辑（查 DB/Redis 连接）③ 面试：如何实现 Nginx 上游服务的健康检查？被动和主动的区别？|→ Spring Boot Actuator /health 端点|
|2.4|**proxy_pass 转发规则**|🟡 应掌握|① 绝对路径 vs 相对路径：`proxy_pass` [`http://upstream/`](http://upstream/)`;`（带 `/` 截断 location 路径）vs `proxy_pass` [`http://upstream`](http://upstream)`;`（不带 `/` 完整转发）② Header 处理：proxy_set_header Host/X-Real-IP/X-Forwarded-For/Proxy ③ 面试：`proxy_pass` 带 `/` 和不带 `/` 的区别？（经典坑题！）|→ M3 Location 匹配（location 和 proxy_pass 的配合规则）|
|2.5|**会话保持方案**|🟡 应掌握|① **ip_hash**：最简单但有 NAT 问题（多用户同一出口 IP）；② **Sticky Cookie**：nginx-sticky-module，首次响应 Set-Cookie 后续带 cookie；③ **应用层 Session 共享**：Spring Session + Redis（最推荐）④ 面试：分布式环境下怎么保持会话？各方案优劣？|→ Redis（Session 存储）、→ Spring Cloud（Session 共享）|
|2.6|**upstream 容错与故障转移**|🟡 应掌握|① backup 标记（备用节点，其他全挂时启用）、down 标记（手动下线）；② max_fails/fail_timeout 参数含义；③ proxy_next_upstream（失败自动切换下一个上游）④ 面试：某个 upstream 服务挂了，Nginx 怎么处理的？有延迟吗？|→ M7 高可用（Keepalived 层面的容错）、→ M8 排障（502 分析）|

> **🏗️ 架构追问**：在 K8s 环境（Service + Ingress）下，Nginx 的负载均衡角色被弱化了。如果让你设计云原生时代的流量入口层，你会怎么取舍 Nginx Ingress Controller vs API Gateway（如 Spring Cloud Gateway）？
