|知识点|笔记时重点写什么|
|---|---|
|**SqlSession 工作原理**|热 SqlSession 是 MyBatis 的核心接口，代表一次数据库会话。**它不是线程安全的**，每个线程应该有自己的实例。通过 `SqlSessionFactory.openSession()` 创建，内部持有一个 `Configuration`（全局配置）和 `Executor`（执行器）|
|**四大核心对象**|热 **SqlSession**（会话入口）→ **Executor**（执行器，真正执行 SQL 的）→ **StatementHandler**（语句处理器，和 JDBC Statement 打交道的）→ **ParameterHandler**（参数处理器，设置 SQL 参数的）→ **ResultSetHandler**（结果集处理器，JDBC ResultSet → Java 对象）。**面试常要求画出这个调用链**|
|**Executor 三种实现**|核 SimpleExecutor（每次执行都创建新 Statement）、ReuseExecutor（复用 Statement，基于 Map<String, Statement>）、BatchExecutor（批量执行）。默认是 SimpleExecutor。二级缓存开启时会被 CachingExecutor 装饰|
|**Mapper 接口代理生成机制**|核 你只写了 Mapper 接口没有写实现类——MyBatis 用 JDK 动态代理为接口生成实现类。核心类 `MapperProxy`：invoke() 方法内根据方法名找到 `MappedStatement`，然后交给 Executor 执行。这就是为什么你调用 `userMapper.selectById(1)` 就能跑 SQL|
|**Configuration 全局配置对象**|整个 MyBatis 只有一个 Configuration 实例（单例）。里面存储了所有信息：mappedStatements、resultMaps、sqlFragments、typeAliases、typeHandlers、plugins、environments。它是 MyBatis 的「注册中心」|

> **笔记技巧**：四大核心对象的调用链建议画成纵向流程图：`SqlSession.selectList()` → `Executor.query()` → `StatementHandler.prepare()` → `ParameterHandler.setParameters()` → `StatementHandler.query()` → `ResultSetHandler.handleResultSets()`。这张图覆盖了 MyBatis 面试题的 60%。
