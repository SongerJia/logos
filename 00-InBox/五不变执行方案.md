# 五不变执行方案

> 配套「三根柱子落地计划」使用。三根柱子教你"怎么学"，五不变教你"面试时怎么用出来"。
>
> 不变的东西能应对万变的问题。

---

## 五不变 vs 六块地基

六块地基是**知识领域**（要学什么），五不变是**应答能力**（面试桌上怎么用）。

| 六块地基（你的计划） | 五不变（本方案） |
|---------------------|-----------------|
| 数据结构与算法 | → 数据结构模型 |
| 编译与运行时 | → JVM |
| 分布式系统 / 数据库原理 | → 并发三模型 |
| 柱子二的"追问为什么" | → 溯源思维 |
| 柱子一的"口述"步骤 | → 说人话能力 |

**五不变中的后两个（溯源思维、说人话能力）在你的六块地基里没有独立存在**，但它们才是面试时真正的分水岭。

## 不变一：数据结构模型

**目标**：5 种核心结构，每种能脱稿回答两个问题：「底层是什么」+「为什么这个场景用它不用另一个」。

### 执行节奏

| 周次 | 结构 | 输出物 |
|------|------|--------|
| 第 1 周 | 哈希表 | 手写一个简单 HashMap（put/get/resize），50 行 |
| 第 2 周 | 跳表 | 画一张 Redis ZSet 的层级图，标注每层为什么这么设计 |
| 第 3 周 | B+Tree | 用 EXPLAIN 跑 5 条不同 SQL，解释每条的 type/rows/key |
| 第 4 周 | LSM Tree | 对比一个追加写文件和一个随机写文件的耗时差异 |
| 第 5 周 | 布隆过滤器 | 写一个 20 行的布隆过滤器，3 个 hash 函数 |

### 检验标准

关掉所有资料，在白板上画 B+Tree 的插入过程，边画边讲。卡住 = 没会。

### 关键认知

```
你不需要背 HashMap 的源码
你需要理解「哈希表这个数据结构的通用模型」
  → 散列函数 + 冲突解决（拉链法/开放寻址） + 扩容 + 负载因子

理解了哈希表模型，等于同时理解了：
  HashMap / ConcurrentHashMap / Redis Hash / HashSet / 布隆过滤器（空间换时间的同一思想）
```

## 不变二：并发三模型

**目标**：锁模型、CAS 模型、消息模型，每个能讲清「底层机制 + 一个典型 bug + 一个你在项目里怎么用的」。

### 执行节奏

| 周次 | 模型 | 做什么 |
|------|------|--------|
| 第 1-2 周 | 锁模型 | 手写 DCL 单例 → 手写一个简单 ReentrantLock（30 行）→ 画 AQS 的 CLH 队列 |
| 第 3-4 周 | CAS 模型 | 读 AtomicInteger 源码 → 手写 CAS 自旋实现计数器 → 讲 ABA 问题 |
| 第 5-6 周 | 消息模型 | 手写简单的 BlockingQueue（wait/notify 版）→ 画出线程池从提交到执行的完整链路 |

### 检验标准

面试官问「CountDownLatch 的原理」，你能从 AQS 共享锁模型讲起，30 秒说清楚。

### 关键认知

```
所有并发问题不出这三种模型：

锁模型    → 互斥访问，排队等待
           synchronized / ReentrantLock / 读写锁 / 行锁 / 间隙锁
           
CAS模型   → 无锁，自旋重试，乐观
           AtomicInteger / ConcurrentHashMap.sizeCtl / 无锁队列

消息模型  → 生产者-消费者，队列缓冲
           BlockingQueue / 线程池任务队列 / RocketMQ / Kafka

CountDownLatch = AQS 共享锁模型
Semaphore      = AQS 共享锁模型（容量控制）
ThreadLocal    = 线程隔离（不涉及锁，用的是"每个线程一份"）
```

## 不变三：JVM

**目标**：能默画 JVM 内存结构图 + 能从 GC 日志还原问题。

### 执行节奏

| 周次 | 做什么 | 验证方式 |
|------|--------|----------|
| 第 1 周 | 画堆结构图（新生代/Eden/S0/S1/老年代），标尺寸比例 | 白板默画 |
| 第 2 周 | 跑一段代码，用 jstat -gc 观察，理解每列含义 | 能解释 S0C/S1C/EC/OC/YGC/FGC 的关系 |
| 第 3 周 | 故意写一个 OOM，用 jmap dump，MAT 打开找到泄漏对象 | 能说出「哪个对象占了最多内存」 |
| 第 4 周 | 了解 G1 的 Region、Mixed GC、SATB，和 CMS 对比 | 能说 G1 为什么适合大堆 |

### 检验标准

面试官说「我们线上 FGC 频繁」，你能问出 3 个定位问题（堆多大、什么对象多、GC 日志里什么阶段耗时最长）。

### 关键认知

```
JVM 是 Java 面试里唯一的「元知识」
它解释了所有其他知识：

synchronized 为什么能锁住？      → 对象头里的 Mark Word
线程池的 Worker 为什么继承 AQS？ → 需要独占锁保护线程状态
DCL 为什么加 volatile？          → 字节码重排序
@Transactional 怎么起作用的？    → AOP → CGLIB → 生成字节码 → 类加载
```

## 不变四：溯源思维

**目标**：任意一个框架设计，能往下追 3 层到不变原理。

### 唯一训练方法

在 Obsidian 里开一个文件叫 `溯源链.md`，格式如下：

```markdown
## 2026-06-12：Spring @Transactional 为什么在同类方法调用时失效？
@Transactional → Spring AOP → 代理对象 → 同类方法调用走的是 this 不是代理
→ 代理的本质是拦截器模式 → 所有 AOP 框架都有这个限制 → 这是「代理模式」的不变特性

## 2026-06-13：Redis 集群为什么是 16384 个槽？
16384 → 心跳包大小（2KB）→ 每个槽 1bit 的位图 → 超过 16384 心跳包会超过 2KB
→ 单节点能承载的槽数不需要太多 → 这是「网络传输效率」的不变约束
```

### 规则

- 每天至少新增一条
- 不追求字多，追求「最后一句话停在一个不会变的基础规律上」
- 停在「XXX 就是这样设计的」= 不够深，继续追

### 检验标准

翻你的溯源链，看最后一句是不是停在了一个「不会变的基础规律」上。如果不是，继续补。

## 不变五：说人话能力

**目标**：任何知识点能在 30 秒内讲给一个非技术人员听。

### 唯一训练方法

1. 每天晚上，从当天学的东西里抽一个点
2. 打开手机录音，对着讲 30 秒，假设对面是一个不懂 Java 的产品经理
3. 回听录音，划掉所有「这里就是这样的」「这个东西比较复杂」「你懂吧」
4. 再讲一遍，直到没有废话

### 检验标准

能让你老婆听懂你在说什么。

### 为什么这个最重要

```
面试时对方的耐心有上限。
你说得明白 → 面试官觉得你懂 → 追问方向变友好
你说得混乱 → 面试官觉得你在背 → 追问方向变刁钻

30 秒能说清楚的东西，说明你真的懂了。
```

## 面试题目的正确用法

你的 InBox 里有 Day1-Day14 的面试模拟题。这些题目是用来**检验**的，不是用来**学习**的。

### 正确流程

```
1. 先用流水线（六步 SOP）学会一个知识点（比如 HashMap）
2. 用不变五（说人话）把学的东西讲出来
3. 然后翻开面试题目，找到对应的题，检验自己能不能答
4. 答不出来的 → 补溯源链 → 回到第 1 步
```

### 错误流程

```
翻开面试题目 → 看到不会的 → 记下来 → 直接搜答案 → 以为会了
（这是背答案，不是学会）
```
