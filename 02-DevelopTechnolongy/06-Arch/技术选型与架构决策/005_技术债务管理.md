|**8.5.1**|**技术债务分类**|**无意债务**：赶工期临时方案没来得及重构 → **有意债务**：为了速度故意欠债(需记录!) → **战略性债务**：MVP阶段接受低质量换取上市时间|Martin Fowler债务分类 Quadrant|"有意债务和无意债务的处理方式一样吗？"|FlowPulse V1.0 有意识接受的"债务"：先用单机部署(V1.0不加K8s) / 先不做ES搜索(V1.0用MySQL LIKE) / 先不做多租户|
|**8.5.2**|**技术债务度量**|SonarQube(代码坏味道+漏洞+覆盖率) / Code Coverage(单元测试覆盖率) / Cyclomatic Complexity(圈复杂度) / Tech Debt Ratio(偿还工时/总工时)|`债务比率 = 修复所有问题的估算时间 / 重写整个项目的估算时间`|"你们项目的技术债务率是多少？多少算健康？"|目标：SonarQube A级评级 / 单元测试覆盖核心域 >60% / 圈复杂度方法<15|
|**8.5.3**|**偿还策略 Refactor vs Rewrite**|**渐进重构**：每次迭代分配15-20%容量还债(推荐!) / **大规模重构**：集中一个Sprint专门还债 / **重写**：只有当改造成本 > 重写成本时考虑|Ward Cunningham原话："一点技术债务就像财务债务，完全没问题时会痛苦，但能让你更快交付"|"什么情况下该重写而不是重构？重写的风险？"|FlowPulse策略：**每个Sprint预留20%还债额度** / 重大重构配合ADR记录原因|
