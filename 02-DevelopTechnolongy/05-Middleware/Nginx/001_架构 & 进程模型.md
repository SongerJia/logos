|#|知识点|重要度|笔记三层建议|跨模块关联|
|---|---|---|---|---|
|1.1|**Master-Worker 进程模型**|🔴 必背|① Master 负责管理（加载配置、管理 Worker、不处理请求），Worker 处理连接（每个 Worker 独立 epoll）② 为什么这样设计？避免锁竞争 + 平滑重启（reload 不丢连接）③ 面试：Master 和 Worker 各自职责？Worker 数量怎么设？|→ M6 性能调优（worker_processes / worker_connections）|
|1.2|**epoll 事件驱动机制**|🔴 必背|① epoll 是 Linux I/O 多路复用，LT/ET 两种触发模式，Nginx 默认使用 epoll_et（边缘触发）② 为什么比 select/poll 快？O(1) vs O(n)，不需要每次遍历全部 fd ③ 面试：epoll 和 select 的区别？Nginx 用的是哪种模式？为什么选 ET？|→ Java NIO（Selector/epoll）、→ Redis IO 模型（同是 epoll）|
|1.3|**异步非阻塞 I/O 模型**|🔴 必背|① Nginx 的 Worker 单线程处理大量并发，靠的就是非阻塞 I/O + 事件通知 ② 与 Apache prefork 对比：Apache 一个连接一个线程，Nginx 一个进程处理万级并发 ③ 面试：Nginx 为什么能支持 C10K？和 Node.js 的事件循环有什么异同？|→ Java 并发（线程池对比单线程事件驱动）|
|1.4|**C10K / C100K 问题**|🟡 应掌握|① C10K = 1 万并发连接的挑战（文件描述符限制、内存、CPU上下文切换）；C100K = 更极致优化 ② Nginx 如何解决：worker_connections + sysctl 内核参数调优 ③ 面试：你的系统遇到过 C10K 问题吗？怎么解决的？|→ M6 性能调优、→ M8 排障（ulimit / sysctl）|
|1.5|**模块化架构（HTTP/Stream/Mail）**|🟢 了解|① 三大模块层次：Core（核心）→ Events（事件驱动）→ HTTP/Stream/Mail（应用层）② 常用内置模块：ngx_http_proxy_module / ngx_http_upstream_module / ngx_http_rewrite_module ③ 面试：你用过哪些 Nginx 第三方模块？（如 lua-nginx-module/OpenResty）|→ M2 反向代理（proxy_pass/upstream）|
|1.6|**平滑升级 & 热加载原理**|🟡 应掌握|① `nginx -s reload` 流程：Master 接收信号 → 新配置校验 → 启动新 Worker → 旧 Worker 优雅关闭（不再接收新连接，处理完现有再退出）② 平滑升级：替换二进制 → USR2 启新 Master → WINCH 关旧 Worker ③ 面试：线上 Nginx 配置变更怎么做才安全？reload 和 restart 区别？|→ M7 高可用（不停服部署）|
