**追问1：** HikariCP 为什么是最快的连接池？它做了哪些优化？

→ 你回答...（提示：FastList 替代 ArrayList 避免范围检查 / ConcurrentBag 无锁获取连接 / 字节码优化 `StateMachine` 用 `MutUtil` 字节码注入 / 连接生命周期管理精细 / 代码量少 130KB vs Druid 2MB+）

**追问2：** Druid 的 SQL 监控和防火墙功能你用过吗？HikariCP 有这些功能吗？

**追问4：** 连接泄漏你们遇到过吗？什么情况会导致连接泄漏？连接池怎么检测？

**追问5：** 连接池里的连接是物理连接还是逻辑连接？MySQL 的 `wait_timeout` 默认 8 小时，连接池里的连接长时间空闲会怎样？

→ 你回答...（提示：物理连接 / 空闲连接被 MySQL 断开后连接池不知道 / 借出时发现已断 → 报错 / HikariCP 有 `maxLifetime` 和 `idleTimeout` 主动回收 / `connectionTestQuery` 心跳检测 / `keepaliveTime` 保活）

> 💡 **今日重点提示**：
> 1. **数据库连接池**第一次系统考察。HikariCP 快的核心：FastList（避免范围检查）+ ConcurrentBag（无锁获取）+ 代码精简。连接池大小"不是越大越好"是高频追问——连接太多反而因上下文切换变慢。`maxLifetime` 和 `idleTimeout` 是解决"MySQL 断了空闲连接但连接池不知道"问题的关键配置
> 2. **Sentinel 原理**在 Day6/Day14/Day19/Day21 提过限流和熔断，今天深入底层。滑动窗口 LeapArray 是核心——时间轮分成多个窗口，比固定窗口更平滑。规则持久化是生产必须——Dashboard 挂了不影响客户端，但规则变更需要 Nacos/ ZooKeeper 做数据源。`@SentinelResource` 底层是 AOP 切面
> 3. **环形链表检测**是经典快慢指针题（Floyd 判圈法）。核心记忆："快指针走两步慢指针走一步，有环必相遇"。找环入口的数学证明要能讲：相遇后慢指针回头部，两个同速走再次相遇就是入口。空间 O(1) 是快慢指针优于 HashSet 的核心优势
> 4. **Elasticsearch**第一次系统考察。倒排索引是核心——"关键词→文档列表"和 MySQL 的"文档→关键词"方向相反。match vs term 的区别是高频题：match 分词查询，term 不分词直接查。深分页问题（from+size > 10000）的解决方案 search_after 是面试加分项。ES 和 MySQL 数据同步方案（双写/Canal/Logstash）各有优劣
> 5. **分布式 ID**第一次出现。雪花算法 64 位分配（1+41+10+12）是必背。时钟回拨是高频追问——机器时间被 NTP 回调可能导致重复 ID。数据库号段模式（美团 Leaf）是替代方案——批量取 ID 减少数据库访问。选型：小项目用 ShardingSphere 内置雪花，大项目用 Leaf
> 6. **银行营销活动平台设计**是结合你实际项目经验的核心设计题。重点准备：①组件化抽象（规则/权益/通知/统计四类组件）②防超发（Redis DECR 预扣减）③规则动态生效（配置中心+规则引擎）④活动效果分析（埋点+ES/ClickHouse）。追问6"重新设计会做什么不同"是反思题——要体现你从经验中学到了什么
> 7. **DevOps/CI/CD**是城商行面试的务实题。城商行不像互联网公司有专门的 SRE 团队，开发要兼顾运维。核心追问是数据库 DDL 回滚——加字段容易删字段难，分步发布（先加兼容字段→上新代码→稳定后删旧字段）。自动化测试覆盖率是 CI/CD 的根基——没有测试覆盖的自动化部署等于"盲发"
> 8. **城商行业务**是小微金融特色。"三品三表"是泰隆的特色风控模型，了解这个能体现你对目标公司的研究。城商行技术选型务实——不要盲目微服务化，人少更重工具化思维，这是和大行面试的差异化卖点
