|#|知识点|核心内容|实践技巧|面试追问|FlowPulse 案例|
|---|---|---|---|---|---|
|**7.7.1**|**什么是统一语言**|专家和开发者共享同一套词汇表；代码中的类名/方法名/变量名 = 需求文档中的术语 = 会议讨论时的用语；消除"翻译损耗"|①建立术语表(Glossary) ②代码评审检查命名是否一致 ③禁止使用技术术语替代业务术语(如用`process`不用`flow`)|"如果业务专家说的术语和技术实现有冲突怎么办？"|FlowPulse术语对照：`流程定义`=ProcessDefinition / `流程实例`=ProcessInstance / `待办`=Task(PENDING) / `驳回`=Reject / `会签`=CounterSign|
|**7.7.2**|**语言发酵(Bounding Language)**|统一语言是在迭代中不断演进的；早期粗糙没关系，随着对领域理解的加深不断精炼|早期允许模糊术语存在 → 随着建模深入逐步精确化 → 重命名重构是健康的信号|"统一语言变了之后，已命名的代码和数据库字段怎么办？"|迭代过程中：`Workflow`(太泛) → `BusinessProcess`(好一些) → `ProcessDefinition`(最终确定) — 这就是语言发酵过程|
