|---|---|---|---|---|---|
|**1.3.1**|**适配器 Adapter**|将一个接口转换成客户端期望的另一个接口|类适配器 vs 对象适配器 vs 接口适配器(双分派)；双向适配器|"Spring MVC的HandlerAdapter是什么？"|Gateway层协议转换(HTTP→Dubbo RPC) / 不同MQ消息格式适配|
|**1.3.2**|**装饰器 Decorator**|动态给对象添加额外职责，比继承灵活|装饰器 vs 代理的区别(关注点增强 vs 控制)；Java IO流是经典案例|"BufferedReader装饰了谁？"|MyBatis-Plus的拦截器Plugin(包装SqlSession) / Servlet Filter链|
|**1.3.3**|**代理 Proxy**|为其他对象提供代理以控制访问|静态代理 vs JDK动态代理(接口) vs CGLIB动态代理(子类)；性能对比|"Spring AOP默认用哪种代理？"|**Seata AT模式的数据源代理**(DataSourceProxy) / Gateway路由代理|
|**1.3.4**|**外观 Facade**|为子系统提供统一的高层接口，隐藏复杂性|外观 vs Mediator的区别(单向封装 vs 多向协调)|"Facade模式和API网关的关系？"|**Gateway本身就是各微服务的Facade** / SLF4J是日志门面|
|**1.3.5**|**桥接 Bridge**|将抽象部分与实现部分分离，使二者独立变化|桥接 vs 策略的区别(维度拆分 vs 算法替换)；JDBC是经典案例|"JDBC Driver为什么是桥接模式？"|流程引擎：流程定义(抽象) ↔ 执行引擎(实现)解耦|
|**1.3.6**|**组合 Composite**|树形结构，一致对待单个对象和组合对象|透明式 vs 安全式的区别；文件系统是经典案例|"MyBatis的SqlNode是组合模式吗？"|**菜单权限树**：Permission(叶子) + MenuFolder(容器)统一处理|
|**1.3.7**|**享元 Flyweight**|共享细粒度对象，大幅减少对象数量|内部状态(共享) vs 外部状态(传入)；Integer缓存(-128~127)|"String常量池是享元吗？"|流程定义中的条件表达式缓存 / Redis连接复用|
|**1.3.8**|**Spring AOP架构**|代理+责任链+适配器的综合运用|Pointcut(切点) / Advice(通知) / Aspect(切面) / JoinPoint(连接点)；织入时机|"Around Before AfterReturning AfterThrowing执行顺序？"|全局异常处理 / 日志审计 / 权限校验 / 事务边界都用AOP|
|**1.3.9**|**MVC架构模式**|Model-View-Controller三层分离|Front Controller / View Resolver / HandlerMapping；MVC vs MVP vs MVVM|"Spring MVC请求处理完整流程？"|FlowPulse前端Vue3(API层) → Gateway(Controller) → Service(Model)|
