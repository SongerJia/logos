|7.1|场景一：接口响应慢的链路定位|用户反馈"订单页很慢" → 打开 SkyWalking UI → 按 Endpoint 排序找慢接口 → 查看 Trace 详情 → 发现某个 Span 耗时占比最大（比如 SQL 慢查询或 RPC 超时）→ 定位根因；**完整的排查步骤**|🔥🔥🔥🔨 **实战必考场景题**|
|7.2|场景二：跨服务故障定位|A 服务调用 B 服务超时 → 从 A 的 Exit Span 看到 B 响应慢 → 切换到 B 服务的视角 → 发现 B 内部调用了 C 且 C 有大量 Error Span → C 服务数据库连接池耗尽 → **逐层下钻的排查思路**|🔥🔥🔥|
|7.3|场景三：异常流量分析|突然收到告警"某接口错误率飙升" → 按时间范围过滤 Trace → 只看 Error 级别的 Span → 分析错误分布（是某个特定参数触发的？还是某个下游服务挂了？）→ 结合 Tag 自定义标签快速筛选|🔥🔥🔨|
