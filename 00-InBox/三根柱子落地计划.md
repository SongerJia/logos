## 柱子一：学习流程

### 目标

把以下六步流程练到"不需要思考，自动执行"的程度。每条流水线跑完一个知识点，约 40 分钟。

### 六步 SOP

| 步骤 | 做什么 | 时长 | 关键规则 |
|------|--------|------|----------|
| 1. 看主干 | 只看核心路径，跳过所有分支和边界处理 | ≤5 分钟 | 不允许抄代码，只用眼睛看 |
| 2. 空手写 | 关掉所有资料，打开空白文件从头写 | ≤15 分钟 | 卡住 >2 分钟才能偷看 |
| 3. 回看 | 仅看刚才卡住的那个点，不看其他 | ≤2 分钟 | 看完立刻关掉，不能顺手抄 |
| 4. 再写 | 关掉资料，从空白文件重写一遍 | 不限 | 必须完整写对，中间不能看 |
| 5. 追问"为什么" | 针对每个设计决策追问到底层原理 | 10 分钟 | 必须落到六块底层知识之一 |
| 6. 口述 | 对着空气/录音，用白话讲一遍整个知识点 | 5 分钟 | 不能有"这里就是这样的"——每句话都得有因果 |

### 第一周练习目标：建立流水线肌肉

第一周不追求掌握任何知识点，只追求把这条流水线跑熟。

**周一 ~ 周五**：每天挑一个极小的知识点，跑一趟完整流水线。

推荐练习素材（都是 10 分钟内能看完主干的）：

| 日期 | 练习素材 | 目的 |
|------|---------|------|
| Day 1 | 饿汉式单例 | 最简单的，建立流水线信心 |
| Day 2 | 懒汉式单例 + synchronized | 加一个分支（线程安全） |
| Day 3 | 双重检查锁 | 加两个分支（volatile + 两次判空） |
| Day 4 | 静态内部类单例 | 换一种实现思路 |
| Day 5 | 枚举单例 | 验证流水线可以处理不同风格的代码 |

每天完成后，在日记里记两句话：
1. 今天哪个步骤最卡？（比如"空手写的时候忘了 volatile"，"口述的时候语无伦次"）
2. 这个卡点下次怎么改进？

### 后续维护

- 每个新知识点都用这条流水线
- 每跑完 10 趟，回顾一次：哪个步骤已经不需要刻意注意了？哪个还在拖后腿？
- 目标是 30 趟之后，六步变成本能

## 柱子二：底层原理

### 目标

在六块底层知识上建立"追问链"能力——从任何一个上层框架的某个设计，能一层层追问到不变的底层原理。

### 六块基石 + 对应的上层映射

#### 1. 数据结构与算法（30 年未变）

**你真正需要内化的不是实现，是 trade-off：**

| 结构 | 核心 trade-off | 上层映射 |
|------|--------------|----------|
| 哈希表 | O(1) 查询，空间换时间 | HashMap, HashSet, Redis Hash |
| 跳表 | O(log n)，实现简单，支持范围查询 | Redis ZSet, ConcurrentSkipListMap |
| B+Tree | 磁盘友好，范围查询高效 | MySQL InnoDB 索引 |
| LSM Tree | 写入极快，读取稍慢，适合写多读少 | RocksDB, LevelDB, HBase |
| 布隆过滤器 | 可能存在误判，一定不会漏判 | Redis 缓存穿透防护 |

**练习方式**：每个结构做一次"为什么是这个"的追问链。例如：
> Redis ZSet 为什么用跳表不用红黑树？
> → 跳表实现简单（红黑树旋转复杂）
> → 跳表支持范围查询（ZRANGE），红黑树需要中序遍历
> → 跳表的插入层级随机化，天然适合并发

#### 2. 操作系统（50 年未变）

| 概念 | 核心理解 | 上层映射 |
|------|---------|----------|
| 进程 vs 线程 vs 协程 | 隔离成本递减，调度粒度递减 | Java Thread → Go goroutine → Kotlin coroutine |
| 虚拟内存 | 每个进程有独立地址空间 | OOM、堆外内存、mmap |
| 文件 IO：阻塞/非阻塞/多路复用 | 一个线程等一个连接 → 一个线程管多个连接 | BIO → NIO → Netty |
| 零拷贝 | CPU 不参与数据搬运 | Kafka sendfile, NIO transferTo |
| CPU 缓存行 | 伪共享导致性能暴跌 | Disruptor, @Contended 注解 |

**练习方式**：从你每天用的东西往下追一层。比如：
> Netty 为什么快？→ NIO 多路复用 → epoll → OS 内核中断处理 → DMA

每周追一条"为什么链"，追到不能再追为止。记在同一个文档里，六块知识各建一个条目。

#### 3. 计算机网络（40 年未变）

| 概念 | 核心理解 | 上层映射 |
|------|---------|----------|
| TCP 三次握手/四次挥手 | 为什么是三次不是两次？防止旧连接请求 | 所有基于 TCP 的协议 |
| TCP 拥塞控制 | 慢启动、拥塞避免、快重传 | 长连接 vs 短连接的选择 |
| HTTP/1.1 → HTTP/2 → HTTP/3 | 队头阻塞 → 多路复用 → QUIC(UDP) | REST → gRPC → WebSocket |
| DNS | 递归查询 + 缓存 | CDN, 服务发现 |

**练习方式**：追问一个你最常用的协议栈。
> 你写了一个 HTTP 请求 → 经历了什么？→ DNS → TCP → TLS → HTTP → 反向代理 → 应用

画出来，写出来。

#### 4. 分布式系统（30 年未变）

| 概念 | 核心理解 | 上层映射 |
|------|---------|----------|
| CAP 理论 | 三者不可兼得，但可以取舍和妥协 | 所有分布式中间件的架构选择 |
| 共识算法（Paxos/Raft） | 多个节点如何就一个值达成一致 | Zookeeper ZAB, etcd Raft, Redis Sentinel |
| 数据分片 + 复制 | 分片解决容量，复制解决可用性 | Kafka partition, Redis Cluster, MySQL 分库分表 |
| 二阶段提交 / TCC / Saga | 跨节点事务的三种保证级别 | Seata AT/TCC, 分布式事务选型 |
| 限流 / 熔断 / 降级 | 保护系统的三个层次 | Sentinel, Hystrix, Resilience4j |

**练习方式**：每个分布式中间件，问三个问题：
1. 它在 CAP 里选了哪两个？
2. 它的数据一致性保证到什么级别？
3. 它挂了之后会发生什么？

#### 5. 数据库原理（40 年未变）

| 概念 | 核心理解 | 上层映射 |
|------|---------|----------|
| ACID + MVCC | 隔离级别的实现原理 | MySQL InnoDB 事务，Spring @Transactional |
| B+Tree 索引 | 聚簇索引 vs 非聚簇索引，最左前缀 | 慢查询优化，explain |
| WAL（Write-Ahead Log） | 先写日志再写数据，崩溃恢复 | MySQL binlog/redo log, Redis AOF |
| 锁：行锁/间隙锁/临键锁 | 不同隔离级别下锁的范围不同 | 死锁排查，乐观锁 vs 悲观锁选型 |
| Buffer Pool | 内存缓存数据页，LRU 淘汰 | MySQL 内存参数调优 |

**练习方式**：每条 SQL 写完，强制跑一次 `EXPLAIN`。遇到慢查询不要直接加索引——先画出"为什么会走这个执行计划"的因果链。

#### 6. 编译与运行时（20 年未变）

| 概念 | 核心理解 | 上层映射 |
|------|---------|----------|
| 类加载机制 | 双亲委派，加载→链接→初始化 | Spring Boot 启动流程，热部署原理 |
| 字节码 | 中间表示，可被改写 | AOP 本质，Lombok, ASM, CGLIB |
| JIT 编译 | 热点代码编译为本地代码 | 性能优化，预热问题 |
| GC 算法 | 标记-清除 → 标记-整理 → 分代 → G1 → ZGC | JVM 调优，内存泄漏排查 |

**练习方式**：你的目的不是手写字节码，而是能从上层追下来。比如：
> @Transactional 怎么起作用的？→ Spring AOP → CGLIB 动态代理 → 生成子类字节码 → 类加载

### 六块知识的推进节奏

| 阶段 | 时间 | 重点 |
|------|------|------|
| 第 1-3 周 | 数据结构 + 数据库 | 跟 Java 面试直接挂钩，见效最快 |
| 第 4-6 周 | 操作系统 + 分布式 | 稍微抽象但权重极高 |
| 第 7-8 周 | 网络 + 编译运行时 | 面试频次略低，但学完会让前面四块的理解提升一个层次 |

## 柱子三：问题解决肌肉

### 目标

把这条链路练成本能：**复现 → 定位 → 假设 → 验证 → 修复**

不是靠"见过更多问题"，而是靠"任何问题来了都能拆解"的反应模式。

### 刻意训练方法

#### 1. 日常 Bug 训练（每周 3-5 次）

你在工作中遇到的每一个 bug，强制走完这条链路，不跳步：

```
1. 复现（最小化）
   - 不是"用户说 XX 不行"
   - 而是"我用 curl 发这个请求，返回了这个错误码和堆栈"
   - 写下来：输入是什么、期望输出是什么、实际输出是什么

2. 定位（缩小范围）
   - 从"这功能不行"缩小到"这个方法不行"再缩小到"这一行不行"
   - 工具：日志、断点、arthas、grep

3. 假设（穷举可能原因）
   - 至少列 2 个可能原因，按"最容易验证"排序，不按"最可能"排序
   - 反模式："我猜就是数据库慢了"（跳过验证直接修改）

4. 验证（最小实验）
   - 不是"我加个索引试试"
   - 而是"我单独跑这条 SQL，确认执行计划是全表扫描"

5. 修复（改最小）
   - 只改一行 → 跑测试 → 观察 → 再改下一行
   - 拒绝"顺便重构一下"

6. 复盘（5 分钟）
   - 这个问题的根因是什么？
   - 为什么我的第一次假设是错的？（这是最值钱的一步）
```

**关键规则**：不要搜"XX 报错怎么解决"。先自己跑完上述链路 15 分钟，卡死了再搜。搜到的答案不是终点——你要反过来追问：**"为什么这个答案的作者的排查链路和我的不一样？我漏看了什么信息？"**

#### 2. 模拟面试排查（每周 1 次）

找一个你还没掌握的故障场景（比如"Redis 缓存穿透导致数据库被打挂"），模拟面试回答：

1. 你看到什么现象？（用户自己脑补）
2. 你的排查顺序是什么？（按链路说出来）
3. 每一步你期望看到什么？（正常基准值）
4. 如果实际情况跟期望不符，你的下一步是什么？

把它说出来——不要在心里想，用嘴讲。讲不顺的地方就是你没掌握的排查分支。

#### 3. 排查日记（每周汇总）

每周五花 10 分钟，写下：

```
本周解决的 Bug：X 个
其中有几个是我第一次见到这种类型的？
哪些步骤我跳过了？（最常见的是跳到"假设"然后直接改）
哪个步骤下次可以更快？
```

30 次之后，翻回去看第一周的记录，你会看到这条肌肉是怎么长出来的。

## 每日落地节奏

以下是建议的 6 个月节奏，每天 2-3 小时：

### 工作日（约 2 小时）

| 时段 | 内容 | 时间 |
|------|------|------|
| 早晨 30 分钟 | 柱子一：跑一条流水线（6 步 SOP），训练一个新知识点 | 30 分钟 |
| 晚上 60 分钟 | 柱子二：深入学习六块底层知识中的一块（按推进节奏） | 60 分钟 |
| 随时 | 柱子三：工作中遇到 bug 走完整拆解链路 | 工作中穿插 |

### 周末（约 4-6 小时）

| 时段 | 内容 | 时间 |
|------|------|------|
| 上午 | 柱子一：复习本周所有知识点的空手写，保证一个都不丢 | 60 分钟 |
| 上午 | 柱子二：做一次完整的"为什么链"追踪（从框架追到底层） | 90 分钟 |
| 下午 | 柱子三：做一次模拟面试排查训练 | 30 分钟 |
| 下午 | 回顾 + 复盘点：本周卡在哪里，下周调整什么 | 30 分钟 |
| 下午 | 算法刷题（LeetCode，不在三根柱子范围内但不该停） | 60 分钟 |

## 阶段检查点

- [ ] 柱子二：数据库原理（ACID/MVCC/B+Tree/WAL）每一条都能追问到"为什么"

- [ ] 补充：Java 核心 L3 清单中的第一梯队 5 个点全部能空手写出

### 第三个月结束

- [ ] 柱子一：流水线已成为本能，学习新库/新框架的速度明显加快
- [ ] 柱子二：六块底层知识每块都有至少 3 条"为什么链"
- [ ] 柱子二：能从任何一个 Java 框架特性追到对应的底层原理
- [ ] 柱子三：排查链路在 80% 的情况下能完整走完，不跳步
- [ ] 补充：Java 核心 L3 清单中的第二梯队 8 个点全部能空手写出
- [ ] 补充：LeetCode 中等难度题 100 道

### 第六个月结束（面试前）

- [ ] 柱子一：**做**——任何一个新技术，能在一周内达到 L3

- [ ] 柱子三：**稳**——模拟面试中被问到线上故障排查，回答有结构、有边界、不瞎猜
- [ ] 补充：项目亮点梳理完成，每个项目都能讲出"我解决了什么技术难题?"
- [ ] 补充：独立完成至少 3 次模拟面试，录下来回看

## 最后一条

这份文档本身就是子弹，不是兵工厂。

如果你照着做完 6 个月，但全程只是执行我写的清单，那你还是什么都没变——只是从"索要我列的清单"变成了"索要我列的方案"。真正的变化发生在你自己发现"咦，我今天没看这个文档，但我还是跑完了流水线"的那一刻。

**从"我需要一个计划"到"我自己会做计划了"，这才是你要练的。**
