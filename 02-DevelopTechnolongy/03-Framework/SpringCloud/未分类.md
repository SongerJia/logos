## Spring Cloud 整体优先级

```
P0 必考（每个组件都要能说清场景和原理）：
  01 Nacos注册中心  >  03 Sentinel熔断限流  >  07 Seata分布式事务
  02 OpenFeign远程调用  >  04 Gateway网关

P1 高频问答（了解用法 + 能说出优缺点）：
  05 Nacos Config  >  06 RocketMQ消息驱动

P2 了解即可（能用 + 知道选型依据）：
  08 链路追踪
```

**推荐笔记顺序**：`01 → 02 → 04 → 03 → 05 → 07 → 06 → 08`

理由：先搞懂服务怎么注册和发现(01)，然后服务之间怎么调用(02)以及流量怎么从网关进入(04)，接着加保护(熔断限流)(03)，再解决配置管理(05)和数据一致性(07)问题，最后补充异步通信(06)和可观测性(08)。这条线就是一个微服务系统从 0 到 1 的搭建顺序。

## Spring Cloud 与前序模块的关键连接点

```
Spring Boot                          Spring Cloud
──────────                           ──────────
@SpringBootApplication              → 每个 Cloud 组件都是 Starter 形式引入
application.yml 配置                  → BootstrapConfig 加载优先于 application
@Conditional 条件注解                 → 各 AutoConfiguration 大量使用
RestTemplate                         → OpenFeign 封装了 RestTemplate（或 WebClient）
Actuator /metrics                    → Sentinel Dashboard 读取指标数据
CommandLineRunner                     → Seata Server 启动脚本类似思想

Spring MVC                          Spring Cloud
─────────                            ──────────
@RestController                      → Feign Client 接口的声明风格完全一样
@ControllerAdvice                    → Gateway 的 GlobalFilter 做统一异常处理
HttpMessageConverter                   → Feign 的 Encoder/Decoder 序列化
@Valid 参数校验                       → 网关层的 GlobalFilter 做参数校验

Java 并发                            Spring Cloud
────────                             ──────────
线程池                                → Feign 的 HttpClient 连接池
volatile 可见性                       → Nacos 配置动态刷新的可见性问题
锁                                   → Seata 全局锁 vs 本地数据库锁
```
