> 💡 **今日重点提示**：
> 1. **Java IO 体系**第一次系统考察。装饰器模式在 IO 中的体现是经典面试题（Reader → InputStreamReader → BufferedReader 是三层装饰器链）。NIO 的 Channel/Selector 在 Day11/Day18 提过 BIO/NIO/AIO，今天从 IO 流体系角度补充。大文件导出问的是实战经验，结合你的项目（营销活动数据导出？）来回答
> 2. **枚举深入**在 Day1 的手写题基础上展开。枚举单例的线程安全性来自 JVM 类加载机制，这个原理比 DCL 更简洁。EnumMap 用 ordinal 做数组下标是性能优势的核心。枚举策略模式是面试加分项，结合你组件化营销活动中的活动类型枚举来设计
> 3. **三数之和**是经典双指针题，比两数之和（Day3）难一档。核心是**排序 + 固定一个数 + 双指针找另外两个**。去重的关键在于排序后跳过相邻重复值。全 0 数组是高频边界追问
> 4. **MySQL JSON 类型**第一次出现。你的营销活动配置项不固定，如果当时用 JSON 列存储会比 EAV 模型简单很多。虚拟列 + 索引是面试重点——不能直接对 JSON 列加索引，需要提取成虚拟列再建索引
> 5. **RocketMQ 事务消息**在 Day7/Day10/Day26 提过分布式事务，今天从 RocketMQ 自身机制切入。half message → 本地事务 → commit/rollback → 回查，这条链路要能完整画出来。和 Seata AT 的对比是高频追问
> 6. **基金申赎系统设计**是今天的核心设计题。T+1 确认机制 = 申购单先落库（状态待确认）+ 次日批处理获取净值后计算份额。重点准备"净值算错了怎么回滚"和"100万笔申购怎么扛"这两个追问。对账机制是金融系统的标配，要能讲清楚对什么账、多高频率、不一致怎么处理
> 7. **基金业务知识**是你之前说过的短板方向。T+1、净值计算、申购赎回流程这些概念不复杂，但面试官会深挖"为什么"。准备思路：不要背概念，去理解"为什么 T+1"——因为净值要等收盘后算
