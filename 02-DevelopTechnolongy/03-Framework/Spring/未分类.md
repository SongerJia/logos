### 01 IOC 容器概述（6 个）— Spring 的根基

|知识点|笔记时重点写什么|
|---|---|
|**IOC 与 DI 区别**|IOC 是设计思想（控制反转），DI是实现方式（依赖注入）。IOC 不产生代码，DI 才是具体技术。面试常用来考概念清晰度|
|**BeanFactory vs ApplicationContext**|热 BeanFactory 是"懒加载"的（getBean 时才创建），ApplicationContext 是"饿汉式"预实例化（容器启动时创建所有单例 Bean）。ApplicationContext 继承了 MessageSource / EventPublisher / ResourceLoader，功能更丰富|
|**ApplicationContext 实现类对比**|ClassPathXmlAnnotationConfigApplicationContext（纯注解开发最常用）vs GenericWebApplicationContext（Spring MVC 用）vs FileSystemXmlApplicationContext。各自适用场景|
|**容器设计模式**|核 工厂模式（BeanFactory 创建 Bean）、单例模式（默认 Scope）、模板方法（AbstractApplicationContext.refresh() 定义骨架）、观察者（事件机制）、策略模式（多种 AOP 代理策略）|

> **笔记提示**：IOC 这一块是 Spring 的"第一印象"，建议用一张图展示 `ApplicationContext` 的继承体系——从 BeanFactory 一路到 ConfigurableWebApplicationContext，标注每个接口新增的能力。

### 02 Bean 的生命周期（10 个）— 面试绝对核心

这是 Spring Core 中被问最多的模块，几乎每轮必问：

|知识点|笔记时重点写什么|
|---|---|
|**完整生命周期流程**|热 **必须画成时序图**：实例化 → 属性填充 → Aware 回调 → BeanPostProcessor.postProcessBeforeInitialization → InitializingBean/@PostConstruct/init-method → BeanPostProcessor.postProcessAfterInitialization → 使用中 → DisposableBean/@PreDestroy/destroy-method|
|**BeanPostProcessor**|Spring 最强大的扩展接口。`postProcessBeforeInitialization` 和 `postProcessAfterInitialization` 各在什么时机触发？哪些内置处理器用了这个？（AutowiredAnnotationBeanPostProcessor 处理 @Autowired、CommonAnnotationBeanPostProcessor 处理 @Resource、AnnotationAwareAspectJAutoProxyCreator 创建 AOP 代理）|
|**InstantiationAwareBeanPostProcessor**|比 BPP 更强大，能干预**实例化前**和**属性赋值**过程。`postProcessBeforeInstantiation` 返回非 null 则跳过默认实例化（AOP 就是用这个提前返回代理对象的）。**这个接口是理解三级缓存的关键**|
|**三种初始化方式及顺序**|热 `@PostConstruct`(JSR-250) → `InitializingBean.afterPropertiesSet()` → `@Bean(initMethod="xxx")` 或 xml init-method。顺序不能乱！三种方式的来源不同（CommonAnnotation vs Spring 内部 vs 配置）|
|**@Autowired 注入时机**|核 发生在 `AutowiredAnnotationBeanPostProcessor.postProcessProperties()` 方法中，属于 populateBean 阶段。不是构造函数阶段！这个时序问题经常被拿来挖坑|
|**FactoryBean vs BeanFactory**|名字很像但完全不同。FactoryBean 是一种**工厂 Bean**（getObject() 返回你想要的实例），BeanFactory 是**容器本身**。MyBatis 的 SqlSessionFactory 就是 FactoryBean 的典型应用|

> **笔记技巧**：生命周期建议画一张**横向时间线图**，从左到右按执行顺序排列所有步骤，用不同颜色标注：蓝色=框架固定步骤、橙色=Aware 接口回调、绿色=BPP 扩展点、紫色=用户自定义。这张图背下来，生命周期题不会丢分。

### 03 依赖注入 DI（8 个）

|知识点|笔记时重点写什么|
|---|---|
|**三种注入方式对比**|热 构造器注入（推荐，保证不可变 + 必要依赖）、Setter 注入（可选依赖）、字段注入（简单但不推荐，不利于测试）。Spring 官方文档明确推荐构造器注入|
|**@Autowired 工作原理**|热 先 byType 查找 → 找到一个直接注入 → 找多个按 @Qualifier/byName 匹配 → 都匹配不上抛异常。required=false 允许不注入（设为 null）|
|**@Resource vs @Autowired**|热 @Resource 是 JSR-250 标准（JDK 自带），默认 byName；@Autowired 是 Spring 自有，默认 byType。支持度差异（@Resource 不能用于构造器参数）|
|**循环依赖与三级缓存**|热 **最高频源码题之一**。一级缓存 singletonObjects（成品）、二级缓存 earlySingletonObjects（半成品早期引用）、三级缓存 singletonFactories（ObjectFactory lambda）。解决单例 setter 注入循环依赖的完整链路要能手写出来|
|**构造器循环依赖为什么无法解决？**|核 构造器注入发生在实例化阶段，此时对象还没创建完成，无法放入任何缓存提前暴露。所以构造器循环依赖直接报 BeanCurrentlyInCreationException|

> **笔记提示**：三级缓存建议画一个**交互图**，A 依赖 B、B 依赖 A，每一步标注从哪个 Map 取/放数据。特别是第三级缓存为什么要存 ObjectFactory 而不直接存对象？（因为需要延迟判断是否需要创建代理）

### 04 AOP 面向切面编程（10 个）— Spring 的灵魂特性

|知识点|笔记时重点写什么|
|---|---|
|**五种通知类型**|热 Before（方法前）/ AfterReturning（正常返回后）/ AfterThrowing（异常后）/ After（finally 无论怎样都执行）/ Around（包围全流程，控制是否调用目标方法）。Around 功能最强但也最容易出错|
|**JDK 动态代理 vs CGLIB**|热 **必考对比题**。JDK 基于接口（Proxy.newProxyInstance），只能代理接口方法；CGLIB 基于继承（Enhancer.create 子类），可以代理类但不能代理 final 方法/class。Spring Boot 2.x 默认全部用 CGLIB（`spring.aop.proxy-target-class=true`）|
|**AOP 创建代理时机**|核 在 `AbstractAutoProxyCreator.postProcessAfterInitialization()` 中，也就是 Bean 初始化完成后、放入单例池之前。这就是为什么 BPP 的 postProcessAfterInitialization 能拿到代理对象|
|**Spring AOP 调用链路**|核 代理对象 invoke → ReflectiveMethodInvocation（责任链模式）→ 按序执行拦截器链（Interceptor）→ 到达目标方法。`proceed()` 方法如何递归调用链中的下一个拦截器|
|**同类方法调用不走 AOP**|热 类内部 this.methodB() 不会走代理！解决方案：注入自身（@Lazy 解决循环）或使用 AopContext.currentProxy()|
|**AOP 与循环依赖的关系**|三级缓存中的 ObjectFactory 就是给 AOP 准备的——如果 Bean 需要被代理，提前通过 getEarlyBeanReference() 创建代理对象暴露出去|

### 05 事务管理（9 个）— 工程高频考点

|知识点|笔记时重点写什么|
|---|---|
|**七种传播行为详解**|热 REQUIRED（默认，有事务加入无则新建）、REQUIRES_NEW（挂起当前事务新建一个）、NESTED（嵌套子事务基于 SavePoint）、SUPPORTS / NOT_SUPPORTED / MANDATORY / NEVER。每种给一个业务场景|
|**事务失效场景（6~8 种）**|热 **必背清单**：①同类方法调用不走代理 ②方法非 public ③异常被 catch 吞了没抛出 ④异常类型不在 rollbackFor 中 ⑤数据库引擎不支持事务（MyISAM）⑥未被 Spring 管理（没用 @Component 等）⑦传播行为设置不当 ⑧多线程调用|
|**事务底层原理**|热 本质就是 AOP！@Transactional → TransactionInterceptor（环绕通知）→ 开启事务（PlatformTransactionManager.getTransaction()）→ 执行目标方法 → 提交/回滚。**把 AOP 和事务串起来就是一条完整的知识链**|
|**NESTED 与 REQUIRES_NEW 的区别**|核 NESTED 是嵌套子事务（父事务回滚它也回滚，它可以独立回滚不影响父事务）；REQUIRES_NEW 是全新独立事务（两者完全无关）。底层实现也不同：NESTED 用 Savepoint，REQUIRES_NEW 挂起旧连接开新事务|

> **笔记技巧**：事务失效的场景强烈建议做成**检查清单（Checklist）**形式，每个场景配一段错误代码示例和正确修复方案。面试前扫一遍就能快速回忆。

### 06 IOC 容器启动流程（8 个）— 源码级深度

|知识点|笔记时重点写什么|
|---|---|
|**refresh() 十二大步**|热 prepareRefresh → obtainFreshBeanFactory → prepareBeanFactory → postProcessBeanFactory → invokeBeanFactoryPostProcessors → registerBeanPostProcessors → initMessageSource → initApplicationEventMulticaster → onRefresh → registerListeners → finishBeanFactoryInstantiation → lastStep。每步做什么要能说清|
|**BeanDefinition 加载注册**|核 ConfigurationClassPostProcessor 解析 @Configuration → ComponentScanAnnotationParser 扫描 classpath → ASM 读取类注解元数据 → 注册为 BeanDefinition（此时还未实例化！）→ invokeBeanFactoryPostProcessors 阶段执行|
|**doCreateBean 核心四步**|核 createBeanInstance（实例化）→ populateBean（属性赋值，含 Autowired 注入）→ initializeBean（初始化，含 Aware/BPP/initMethods）→ 注册 DisposableBean。这四步就是 Bean 诞生的全过程|
|**三级缓存完整流程**|核 A 创建 → 放入三级缓存(singletonFactories) → 填充属性发现依赖 B → B 创建 → 放入三级 → B 发现依赖 A → 从三级拿到 A 的 ObjectFactory 调用 getEarlyBeanReference()（可能创建代理）→ 放入二级(earlySingletonObjects) → 删除三级 → B 完成 → A 拿到 B 继续 → A 完成 → 移入一级(singletonObjects)|

> **笔记技巧**：启动流程这块信息密度极高，建议画成**纵向泳道图**或**决策树**。refresh() 作为主轴向下展开，每步右侧标注涉及的类和方法名。

### 07 Spring 设计模式（6 个）— 整合性总结

|知识点|说明|
|---|---|
|**工厂模式**|BeanFactory（简单工厂+抽象工厂）、FactoryBean（工厂方法）|
|**单例模式**|DefaultSingletonBeanRegistry 中 singletonObjects 的管理，double-check 加锁|
|**模板方法**|JdbcTemplate / JmsTemplate / RedisTemplate / RestTemplate 全家桶|
|**观察者模式**|ApplicationEventMulticaster 广播事件，ApplicationListener 接收处理|
|**适配器模式**|HandlerAdapter 让不同类型的 Handler 统一处理；AdvisorAdapter 让不同 Advice 适配统一接口|
|**策略模式**|InstantiationStrategy（CglibSubclassingInstantiationStrategy / SimpleInstantiationStrategy）；AopProxyFactory 选择 JDK 还是 CGLIB|

> **笔记提示**：设计模式这块不需要单独开一篇长文，而是应该作为**贯穿线索**穿插在前面的模块中。比如讲到 AOP 时提一下策略模式选择代理方式，讲事务时提一下模板方法的体现。最后在本模块做一张汇总表即可。
