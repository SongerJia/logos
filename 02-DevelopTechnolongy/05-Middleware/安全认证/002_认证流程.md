### 为什么这个模块重要

**认证是安全的入口**——搞不清认证流程就等于不知道"谁进来了"。面试高频考点集中在 AuthenticationManager 及其子类的工作机制。

### 知识点表

|序号|知识点|重要度|笔记三层建议|跨模块关联|
|---|---|---|---|---|
|2.1|**Authentication 接口设计**|🔴必背|① Authentication = 认证凭证（Principal 身份 + Credentials 凭证 + Authorities 权限列表 + authenticated 是否已认证）② 未认证状态：username/password 已填充但 authenticated=false；认证后：authenticated=true 且 credentials 通常被清空（安全考虑）③ 面试：Authentication 接口包含哪些信息？认证前后有什么变化？|→ UserDetails（UserDetailsService 返回值）|
|2.2|**AuthenticationManager & Provider 代理模式**|🔴🔴核心|① AuthenticationManager = 认证管理器接口，只有一个方法 `authenticate(Authentication)` ② ProviderManager = 默认实现，内部维护一组 AuthenticationProvider 列表，逐个尝试直到成功 ③ 为什么这样设计？因为可能有多种认证方式（用户名密码/OAuth/JWT/LDAP），每种对应一个 Provider ④ 面试：为什么用 Provider 代理模式而不是直接写在一个类里？（开闭原则 / 单一职责）|→ 设计模式（代理/策略模式）/ Spring MVC DispatcherServlet（类似分发逻辑）|
|2.3|**DaoAuthenticationProvider — 用户名密码认证**|🔴必背|① 流程：接收 UsernamePasswordToken → 调 UserDetailsService.loadUserByUsername() → 拿到 UserDetails → 用 PasswordEncoder.matches() 校验密码 → 成功则返回已认证的 Authentication ② PasswordEncoder：BCrypt（推荐）/ Pbkdf2 / SCrypt / NoOp（仅开发用）③ 面试：详细描述用户名密码登录的完整认证流程？BCrypt 为什么比 MD5 安全？|→ 密码学（哈希函数）/ Redis 缓存（可做缓存加速）|
|2.4|**UserDetailsService & UserDetails**|🟡应掌握|① UserDetailsService：只负责根据用户名查用户信息（loadUserByUsername）② UserDetails：返回的用户详情（username/password/authorities/accountNonExpired/credentialsNonLocked/enabled）③ 自定义实现：从 DB 查用户 + 角色 + 权限 ④ 面试：UserDetailsService 和 AuthenticationProvider 各自的职责是什么？|→ MyBatis-Plus（DB查询）/ RBAC 权限模型|
|2.5|**记住我（Remember Me）& 会话固定攻击防护**|🟡了解|① RememberMeServices：基于 Token 或持久化 Token（数据库存 token）② 会话固定攻击：攻击者拿到合法 session ID 后利用——Security 通过认证后重新生成 Session ID 来防御 ③ 面试：Remember Me 的实现原理是什么？什么是会话固定攻击？|→ Cookie / Session 管理|
