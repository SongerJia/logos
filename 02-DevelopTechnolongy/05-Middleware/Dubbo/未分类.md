## 推荐学习顺序

```
第一步：M1 架构&SPI(5点) 
   → 建立"Dubbo 整体架构"的认知（SPI 是灵魂）
         ↓
第二步：M2 远程调用&代理(5点) ★ 最高频
   → 理解"魔法"背后的原理（代理+Invoker链）
         ↓
第三步：M3 集群容错&路由(6点)
   → 高可用核心（六大容错+五大负载均衡）
         ↓
第四步：M6 Spring Cloud整合(5点)
   → 落地价值最高（实际项目怎么用）
         ↓
第五步：M4 序列化&协议(5点)
   → 性能优化基础（协议设计+序列化选型）
         ↓
[可选] M5 Dubbo 3.0(4点) → 按需要补充（体现技术前瞻性）
```

## ⚠️ 写笔记特别提醒

1. **M1.1（Dubbo 十层架构）+ M2.2（Invoker 调用链）+ M4.1（Dubbo 协议 16 字节头）** 这三个知识点**必须画图**！面试官最爱让你"画一下 Dubbo 的架构图"或"画一下 Dubbo 协议的二进制格式"
    
2. **M3.1（六大容错策略）+ M3.2（五大负载均衡）** 建议做成**对比表格**（类似 MQ 对比选型的方式），每个策略/算法都写上"适合场景"和"注意事项"
    
3. **和已有知识的关联是最大亮点**：
    
    - Dubbo SPI ↔ Spring Factories（类似机制，对标学习）
    - Dubbo 代理机制 ↔ Spring AOP 代理（JDK 动态代理 vs CGLIB）
    - Dubbo 集群容错 ↔ Nginx upstream 容错（对标）
    - Dubbo 协议设计 ↔ Netty 自定义协议（知识网络！）
    - Dubbo 服务发现 ↔ Spring Cloud Eureka/Nacos（应用级 vs 接口级）
4. **实战项目建议**：用 Dubbo + Nacos + Spring Boot 搭建一个简单的微服务（如订单服务 + 用户服务），实现服务发现、RPC 调用、负载均衡、熔断降级。这个项目能同时覆盖 Dubbo/Spring Cloud/Nacos/Sentinel 多个方向！

## Dubbo 与其他模块的关联网络

```
Dubbo 
  ←→ Netty (通信层底层，所有 RPC 调用都走 Netty)
  ←→ Spring Cloud (整合方案 / Feign vs Dubbo RPC)
  ←→ Nacos (注册中心 / 配置中心)
  ←→ Sentinel (熔断降级 / 限流)
  ←→ SPI 机制 (Dubbo 可扩展性的灵魂)
  ←→ 序列化 (Hessian2/Kryo/Protobuf 性能对比)
  ←→ gRPC (Triple 协议兼容 / 跨语言 RPC 对标)
  ←→ K8s (云原生集成 / Service Mesh)
  ←→ SkyWalking (链路追踪 / 服务治理可观测性)
```
