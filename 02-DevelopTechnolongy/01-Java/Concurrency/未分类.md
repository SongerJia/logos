AQS 是 `ReentrantLock`、`CountDownLatch`、`Semaphore` 的共同底座：

|知识点|笔记时重点写什么|
|---|---|
|**AQS 核心原理 CLH 变体队列**|state 变量 + Node 双向链表（head/tail），tryAcquire 模板方法模式，独占 vs 共享两条路径|
|**ReentrantLock 公平/非公平**|公平锁检查 hasQueuedPredecessors()，非公平直接 CAS 抢 state——写出两者的 acquire 入口差异|
|**synchronized vs ReentrantLock 对比**|**必考对比题**。可中断、超时获取、公平性、条件变量、性能（JDK6 后差距缩小）|
|**Condition await/signal 原理**|ConditionObject 内部维护等待队列，signal 时从 condition 队列转到 AQS 同步队列|
|**StampedLock 乐观读**|和 ReentrantReadWriteLock 的区别：乐观读不阻塞写，适合读多写少|

> **笔记技巧**：AQS 的 `acquire` 流程建议写成伪代码步骤：tryAcquire → 失败 → addWaiter 创建 Node → acquireQueued 自旋/CAS → 成功后 setHead。这个流程能覆盖 AQS 面试题的 80%。


|知识点|笔记时重点写什么|
|---|---|
|**CAS 原理与 Unsafe 类**|compareAndSwap 的底层实现（CPU 的 cmpxchg 指令），Unsafe 为什么不推荐直接用|
|**ABA 问题**|用"取钱"类比：100 → 200 → 100，中间发生了变化但你不知道。版本号解决方案|
|**LongAdder vs AtomicLong**|**高频考点**。分散热点：LongAdder 把 value 拆成 base + Cell[]，高并发下比 AtomicLong 快多少？什么时候选哪个？|
|**CAS 自旋开销**|高并发下大量线程空转浪费 CPU，这就是为什么还需要 synchronized（自适应自旋 + 升级）|

|知识点|笔记时重点写什么|
|---|---|
|**CountDownLatch vs CyclicBarrier**|一对多归零 vs 多方汇合；CountDownLatch 不能重置，CyclicBarrier 可以；各自典型场景（初始化加载 vs 多阶段计算）|
|**Semaphore 限流**|连接池限流的经典用法，acquire/release 配对，fair/unfair 选择|
|**Phaser 分阶段同步**|比 CyclicBarrier 更灵活，支持动态注册/注销 parties|
|**ThreadLocal 原理与内存泄漏**|核 Entry.key 是 WeakReference 但 value 是强引用，线程池复用时 Thread 不回收导致 Entry.value 泄漏。**必须写清楚 GC root 链路**|

> **笔记技巧**：ThreadLocal 内存泄漏建议画一条引用链：`Thread → ThreadLocalMap → Entry → value(强引用)`，标注哪里断不了、为什么 finally 要 remove()。这道题阿里系几乎必问。
