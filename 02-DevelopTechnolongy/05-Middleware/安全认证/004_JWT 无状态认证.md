### 为什么这个模块最重要

**JWT 是现代 Web 应用最主流的无状态认证方案**。几乎每个项目都在用，但很多人只知道"三段式"而不知道背后的安全问题和最佳实践。

### 知识点表

| 序号 | 知识点 | important度 | 笔记三层建议 | 跨模块关联 | |------|-------------|-------------|-----------| | 4.1 | **JWT 结构与原理** | 🔴🔴核心 | ① **Header**（Base64）：算法类型（HS256/RS256 等）② **Payload**（Base64）：声明（Claims）：iss/exp/sub/jti/自定义字段 ③ **Signature**：HMACSHA256(Header+"."+Payload, SecretKey) 或 RSA 签名 ④ **关键认知**：Payload 只是 Base64 编码，不是加密！任何人都能解码看到内容！⑤ 面试：JWT 由哪几部分组成？各部分的作用？Payload 能放敏感信息吗？ | → Base64 编码 vs 加密（概念区分）| | 4.2 | **JWT vs Session-Cookie 方案对比** | 🔴必背 | ① **Session-Cookie**：有状态（服务端存 Session），天然支持即时失效，但不适合分布式（需共享 Session）② **JWT**：无状态（服务端不存储），天然适合微服务和移动端，但无法主动注销（黑名单方案弥补）③ 对比维度：存储位置 / 可扩展性 / 安全性 / 性能 / 移动端适配 ④ 面试：JWT 和 Session-Cookie 各自优缺点？你们项目用的哪种？为什么？ | → Redis Session 共享（Session 方案解决分布式问题）| | 4.3 | **JWT 安全风险 & 防御措施** | 🔴必背 | ① **Token 泄露**：被 XSS 拿到 = 账号被盗；防御：Token 放 HttpOnly Cookie / 不放 LocalStorage（除非必须且做好 XSS 防护）② **Token 过期时间太长**：被盗后长期有效；防御：短有效期（15-30min）+ Refresh Token（7天）③ **签名密钥泄露**：攻击者可以伪造任意 Token； defense: 密钥轮换 / RS256（公私钥分离）④ **重放攻击**：防御：jti（唯一ID）+ nonce（一次性随机数）⑤ 面试：JWT 有哪些安全隐患？怎么防范？ | → HTTPS/TLS（传输层加密）/ OWASP Top 10 | | 4.4 | **Refresh Token 双 Token 机制** | 🔴必背 | ① **Access Token**：短效（15-30min），用于每次请求的身份验证 ② **Refresh Token**：长效（7-30天），用于换取新的 Access Token ③ 流程：登录 → 返回 AT+RT → AT 过期 → 用 RT 换取新 AT+RT → RT 也过期 → 重新登录 ④ RT 存储：DB / Redis（可随时作废） ⑤ 面试：为什么要双 Token 机制？只用一个长 Token 行不行？ | → Redis（RT 存储）/ S5 OAuth2（授权码流程对比）| | 4.5 | **Spring Security 整合 JWT 实战** | 🔴必背 | ① 自定义 JWT Filter（OncePerRequestFilter）：从请求头提取 Token → 解析验证 → 构建 Authentication → 设置到 SecurityContext ② 登录接口：生成 JWT 并返回 ③ 关键代码：`Jwts.parserBuilder().setSigningKey(key).build().parseClaimsJws(token)` ④ 面试：手写一个 JWT Filter 的核心逻辑？ | → S1 FilterChain（插入自定义 Filter 到链中）/ JJWT 库 |

> **🏗️ 架构追问**：如果你要设计一个"多端统一认证系统"（Web/App/小程序），JWT 方案需要怎么调整？提示：需要考虑不同端的 Token 存储差异（Cookie vs Storage）、设备指纹绑定、强制下线等需求。
