## 🔗 跨模块关联

```
SkyWalking
├── → Spring Cloud Alibaba：
│   ├── OpenFeign 调用 → SkyWalking 自动捕获 Exit Span + Entry Span
│   ├── Gateway 网关 → 入口 Trace 起点
│   └── Sentinel 熔断 → 配合 SkyWalking 定位触发熔断的慢调用
├── → RocketMQ/Kafka/RabbitMQ：
│   └── MQ 发送/消费 → SkyWalking Producer/Consumer Span 追踪消息流转
├── → MySQL / Redis / ES：
│   └── DB/Cache 操作 → Exit Span（SQL语句/Redis命令可见）
├── → Java JVM & 字节码：
│   ├── javaagent -jar = JVM TI (Tool Interface) 规范
│   ├── Byte Buddy = ASM 的高层封装
│   └── Class 文件结构（常量池/方法表）→ 增强
├── → 架构方向(待学)：
│   └── 高性能架构：APM 数据量巨大 → ES 存储 + 采样率控制
└── → 运维(待学)：
    ├── ELK Stack：SkyWalking 日志 + ELK 日志打通
    └── Prometheus + Grafana：SkyWalking Metric 导出给 Grafana 展示
```

## 💡 写笔记提醒

- **Agent 字节码增强**是整个 SkyWalking 最能体现技术深度的部分——面试官问"SkyWalking 原理"，标准回答就是 **Java Agent（JVM TI）+ Byte Buddy（字节码修改）+ 插件体系（SPI）** 三板斧。要能讲清楚"不侵入代码是怎么做到的"
- **Trace/Span/Segment 三层数据模型**要能手动画出来——特别是 Entry/Local/Exit 三种 Span 类型怎么构成一棵完整的调用树，以及 TraceID 怎么通过 HTTP Header 跨服务传递
- **实战排查场景**至少准备一个完整案例——"从用户投诉到定位根因"的完整排查过程，这是证明你真的用过而不是只看过文档的最佳方式
- **不需要深入学习 OAP 源码或自定义插件开发**（除非你面 SkyWalking 相关岗位），但要理解插件体系的存在——知道官方覆盖了哪些框架、哪些需要自己处理
- **与 Zipkin/Jaeger 的对比**重点在于：SkyWalking 是**自动埋点的**（Agent 方式），而早期 Zipkin 需要手动加注解（Brave SDK），这是最大的使用体验差异
