| 知识点                            | 笔记时重点写什么                                                                                                                                                                           |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **#{} vs ${} 区别**              | 热 **必考题**。`#{}` = PreparedStatement 预编译（? 占位符，防 SQL 注入）；`${}` = 字符串直接替换（不安全）。什么时候用 `${}`？Order by / 表名动态拼接时（因为预编译不支持这些位置用占位符）。面试标准答案必须包含"SQL 注入风险"                                 |
| **resultMap 映射详解**             | 热 当数据库字段名和 Java 属性名不一致时必须用 resultMap。支持嵌套结果（association 一对一 / collection 一对多）、嵌套查询（select 另一条 SQL 查关联数据）、discriminator（鉴别器，按某列值走不同映射）。**association 和 collection 的区别及 N+1 问题要写清楚** |
| **XML vs 注解开发对比**              | XML：复杂 SQL 可读性好、动态 SQL 支持完善、适合大型项目。注解（@Select / @Insert）：简单 SQL 更方便、但动态 SQL 写起来很痛苦（需要用脚本标签 `<script>`）。实际项目中混合使用：简单查询注解 + 复杂查询 XML                                                 |
| **TypeHandler 类型转换器**          | 数据库 JDBC 类型 ↔ Java 类型的双向转换。MyBatis 内置了大量 TypeHandler（IntegerTypeHandler、DateTypeHandler 等）。自定义场景：数据库存 JSON 字符串但 Java 端想用对象接收 → 继承 BaseTypeHandler 实现                               |
| **parameterType 与 resultType** | parameterType（入参类型，可省略 MyBatis 自动推断）、resultType（返回类型，全限定名或别名）。resultType 适用于字段名完全匹配的情况；resultMap 适用于复杂映射                                                                           |
| **N+1 问题与解决**                  | 热 查 1 条主表数据 + N 条子表数据 = 发出 1+N 条 SQL。解决方式：①嵌套结果（一条 SQL JOIN 查出来，用 resultMap 映射）②fetchType="lazy"（懒加载，按需查询子数据，但需要 `<settings>` 开启 lazyLoadingEnabled）                               |
