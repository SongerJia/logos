|知识点|说明|
|---|---|
|**慢查询日志**|`slowlog-log-slower-than`（阈值，默认 10ms）/ `slowlog-max-len`（最多保存多少条慢查询记录）。分析：`SLOWLOG GET [count]`。注意：慢查询只记录命令执行时间，**不包括网络传输和排队时间**|
|**Pipeline 管道**|热 客户端一次性发送多条命令，减少 RTT（Round Trip Time）。**Pipeline 不是事务**（不保证原子性），只是网络优化手段。与 Lua 脚本的区别：Pipeline 是批量发送，Lua 是服务端原子执行。**适合场景**：批量写入 / 批量读取，性能提升 5~10 倍|
|**Redis 6.0 多线程 IO**|Redis 6.0 之前是单线程（网络 IO + 命令执行 都在主线程）。6.0 引入多线程 IO（只负责网络读写，命令执行仍是单线程）。**为什么命令执行不改成多线程？** 因为 Redis 的核心瓶颈在网络 IO，不是 CPU 计算；且单线程避免了锁竞争，实现简单|
|**maxmemory 与生产环境配置**|推荐配置速查：`maxmemory 物理内存的 60%~70%` / `maxmemory-policy allkeys-lru` / `appendonly yes` / `appendfsync everysec` / `aof-use-rdb-preamble yes` / `timeout 300`（客户端空闲超时）/ `tcp-keepalive 60`。**分 4G/8G/16G/32G 内存给四套推荐配置**|
|**Redis 预热与熔断**|系统重启后缓存为空，大量请求打 DB → 预热（启动脚本批量加载热点数据）。缓存雪崩 → 熔断（Sentinel 配置 `@SentinelResource` 降级方法返回默认值）。**这两项是生产环境必须做的**|
