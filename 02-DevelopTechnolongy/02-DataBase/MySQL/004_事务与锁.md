
| 知识点                    | 笔记时重点写什么                                                                                                                                                                                                                 |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **ACID 四大特性详解**        | 热 不要只背定义。原子性（undo log 回滚）、一致性（ACID 共同目标）、隔离性（锁 + MVCC）、持久性（redo log 提交 + 双写机制）。**每个特性都要关联到底层实现机制**                                                                                                                       |
| **事务隔离级别四种**           | 热 Read Uncommitted（脏读）/ Read Committed（不可重复读）/ Repeatable Read（InnoDB 默认，幻读）/ Serializable（串行化）。**每种级别给一个具体业务场景说明会出现什么问题**。RR 下为什么解决了幻读？（MVCC + Next-Key Lock）                                                           |
| **MVCC 多版本并发控制**       | 热 **核心考点中的核心**。三个关键组件：隐藏字段（DB_TRX_ID 事务ID / DB_ROLL_PTR 回滚指针 / DB_ROW_ID 隐含主键）、Undo Log 版本链（每次更新产生旧版本，通过回滚指针串联成链表）、Read View 可见性判断（m_ids 活跃事务列表 / min_trx_id / max_trx_id）。RC 每次查询生成新 Read View，RR 只在第一次生成——这就是两者区别的根本原因 |
| **Read View 可见性算法**    | 核 拿到一行数据的 DB_TRX_ID 后如何判断是否可见？三条规则：①如果 trx_id < min_trx_id → 可见（事务已提交）②如果 trx_id > max_trx_id → 不可见（事务还没开始）③如果 min ≤ trx_id ≤ max → 看 trx_id 是否在 m_ids 中（在则不可见/不在则可见）。**配合 Undo 链逐版本比较**                                 |
| **InnoDB 锁的类型体系**      | 热 按粒度：表级锁（意向共享 IS / 意向排 IX / 自增锁 AUTO-INC）vs 行级锁（Record Lock 记录锁 / Gap Lock 间隙锁 / Next-Key Lock 临键锁）。按模式：共享锁 S（可并行读）vs 排他锁 X（互斥读写）。**画一张分类树状图**                                                                          |
| **Next-Key Lock 解决幻读** | 核 Record Lock（精确锁定索引记录）+ Gap Lock（锁定间隙，防止新插入）= Next-Key Lock（左开右闭区间锁）。RR 隔离级别下默认使用 Next-Key Lock。**举例**：`SELECT * FROM user WHERE age > 10 FOR UPDATE` 会锁住 (10, +∞) 的区间，其他事务无法插入 age > 10 的记录                            |
| **锁升级与死锁**             | 热 InnoDB **不会**锁升级（和 Oracle 不同，行锁不会升级为表锁）。死锁产生的四个必要条件（互斥/持有并等待/不可抢占/循环等待）。死锁检测机制：`innodb_deadlock_detect=on`（默认开启，等待超时后回滚代价最小的事务）。排查命令：`SHOW ENGINE INNODB STATUS`                                                       |
| **乐观锁 vs 悲观锁实现**       | 热 **必考实战题**。悲观锁：`SELECT ... FOR UPDATE`（X 锁）/ `SELECT ... LOCK IN SHARE MODE`（S 锁）。乐观锁：版本号方案（`UPDATE ... SET version=version+1 WHERE id=? AND version=?`，影响行数=0 则说明被改过）或者 CAS 更新时间戳。各自适用场景（写多→悲观 / 读多→乐观）                |
| **自增主键与雪花算法**          | 热 InnoDB 自增锁（AUTO-INC Locking）的三种模式：innodb_autoinc_lock_mode=0（传统，语句级别持锁）/=1（连续，批量插入预分配）/=2（交错，性能最好但可能不连续）。分布式场景下雪花算法（Snowflake）：41bit 时间戳 + 10bit 机器 ID + 12bit 序列号。**时钟回拨问题怎么解决？**                                     |
| **Gap Lock 使用注意事项**    | Gap Lock 只在 RR 隔离级别生效；RC 下不存在 Gap Lock 所以会有幻读问题。Gap Lock 之间是兼容的（两个事务可以同时持有同一间隙的 Gap Lock），但 Gap Lock 和 Insert 操作冲突（这也是死锁常见原因之一）                                                                                          |
