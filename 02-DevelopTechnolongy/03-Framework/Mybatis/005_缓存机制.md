|知识点|笔记时重点写什么|
|---|---|
|**一级缓存（Local Cache）**|热 **默认开启，SqlSession 级别**。同一个 SqlSession 内相同查询命中缓存（基于 statementId + 参数 + rowBounds + boundSql 组成的 key）。**一级缓存在哪些情况失效？**：①不同 SqlSession ②执行了 update/insert/delete ③手动 clearCache() ④两次查询中间有 rollback()|
|**一级缓存坑：Spring 集合下的问题**|核 Spring 中如果整合了 MyBatis 且开启了事务，**同一个事务内共用一个 SqlSession**（通过 SqlSessionTemplate/SqlSessionHolder）。这导致一次请求内的一级缓存可能返回脏数据（比如在 Service A 中 update 了但 Service B 中 select 还读到旧的）。解决方案：在 Mapper XML 中设置 `flushCache="true"` 或调整 Spring 的事务隔离级别|
|**二级缓存（Global Cache）**|热 **默认关闭，需手动开启**（`<setting name="cacheEnabled" true/>` + Mapper XML 加 `<cache/>`）。namespace 级别（同一个 Mapper 共享），跨 SqlSession 生效。底层也是 PerpetualCache（就是 HashMap 包装）。**关键：查询的对象必须实现 Serializable 接口（因为要序列化到磁盘/跨 session 传递）**|
|**二级缓存工作流程**|第一次查 → 查 DB → 结果放入二级缓存；第二次查（可能是另一个 SqlSession）→ 命中二级缓存直接返回 → 不再查 DB。**update/insert/delete 会清空对应 namespace 的缓存**。注意：二级缓存在 Executor 层被 CachingExecutor 装饰实现|
|**第三方缓存集成**|热 生产环境一般不用 MyBatis 自带的 PerpetualCache（内存易丢失、不支持分布式）。常用替代：**Redis 作为二级缓存**（mybatis-redis / mybatis-redis-cache 项目）、Ehcache（本地缓存框架）。实现方式：实现 `Cache` 接口的 `getObject / putObject / removeObject / clear` 四个方法|

> **连接点提醒**：一级缓存的底层数据结构是 `PerpetualCache`，它内部就是一个 `HashMap`——这直接链接到你集合篇的 HashMap 源码。笔记里标注一下这条线。
