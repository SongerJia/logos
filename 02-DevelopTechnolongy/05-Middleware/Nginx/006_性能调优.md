|#|知识点|重要度|笔记三层建议|跨模块关联|
|---|---|---|---|---|
|6.1|**worker_processes & worker_connections**|🔴 必背|① `worker_processes auto`（= CPU 核数）；`worker_connections 10240`（每个 Worker 最大连接数）② 总最大并发 = worker_processes × worker_connections / （如果是反向代理要除以 2，因为一个连接占两个 fd：client+upstream）③ 面试：一台 8 核服务器，Nginx 最大能支撑多少并发？|→ M1 进程模型、→ Linux ulimit（文件描述符限制）|
|6.2|**gzip 压缩配置**|🟡 应掌握|① `gzip on; gzip_types text/plain application/json; gzip_min_length 1k;` ② 注意：已压缩格式（jpg/png/mp4）不要再 gzip（压缩率低且浪费 CPU）③ 面试：开启 gzip 后接口响应体积减少了多少？怎么验证？|→ 前端打包压缩（webpack gzip）|
|6.3|**Buffer & Timeout 调优**|🟡 应掌握|① `proxy_buffering on`（缓冲后端响应再发给客户端，防止慢速客户端拖垮后端）；`proxy_buffer_size` / `proxy_buffers` ② `proxy_connect_timeout` / `proxy_read_timeout` / `proxy_send_timeout` ③ 面试：后端接口偶尔 504，你会从哪几个方向排查？（timeout + buffer + 后端慢查询）|→ M8 排障（504 问题分析）|
|6.4|**连接池（keepalive）与长连接**|🟡 应掌握|① `keepalive 64`（到 upstream 的连接复用，减少 TCP 握手开销）；`keepalive_requests` / `keepalive_timeout` ② HTTP/1.1 keep-alive vs upstream keepalive 的区别 ③ 面试：Nginx 到后端的连接池怎么配置？有什么效果？|→ TCP 连接、→ 数据库连接池（HikariCP 类比）|
|6.5|**系统级内核参数调优**|🟡 应掌握|① `net.core.somaxconn`（监听队列长度）、`net.ipv4.tcp_tw_reuse`（TIME_WAIT 复用）、`fs.file-max`（最大 fd 数）② `ulimit -n`（进程级别 fd 限制）③ 面试：上线高并发服务前，你需要调整哪些 Linux 内核参数？|→ M1 C10K/C100K、→ 运维方向（sysctl.conf）|

> **🏗️ 架构追问**：如果你们系统的瓶颈确实在网络 I/O 层面（Nginx 到后端带宽打满），除了常规调优外，你还能想到哪些架构层面的优化手段？
