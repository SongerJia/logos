|知识点|笔记时重点写什么|
|---|---|
|**5 种基本类型 + 3 种高级类型**|热 基本：String / Hash / List / Set / ZSet。高级：Bitmap（位图，签到/活跃用户）、HyperLogLog（基数估算，UV 统计）、GeoSpatial（地理位置，附近的人）。**每个类型给一个典型业务场景**|
|**String 三种编码**|核 int（整数，8 字节有符号）/ embstr（短字符串 ≤44 字节，embedded，连续内存）/ raw（长字符串，SDS 动态字符串）。**44 字节是分界点（Redis 5.0+），面试常问为什么是 44**|
|**List 底层：QuickList**|Redis 3.2+ 使用 QuickList（ ziplist + 双向链表 的混合结构）。之前是 ziplist（小数据）+ linkedlist（大数据），现在统一为 QuickList。理解 ziplist 的紧凑存储是理解 Redis 内存优化的关键|
|**Hash 两种编码**|热 ziplist（小 Hash，field 数 ≤ `hash-max-ziplist-entries` 默认 512，value 长度 ≤ `hash-max-ziplist-value` 默认 64 字节）/ hashtable（超大时转成字典）。**这就是为什么 Hash 适合存对象（相比 String 省内存）**|
|**Set 两种编码**|intset（纯整数且元素少时，有序紧凑数组，查找 O(log n) 二分）/ hashtable（其它情况）。intset 的升级机制：int16 → int32 → int64，一旦升级不降级。**给一个元素添加导致编码转换的例子**|
|**ZSet 两种编码（最高频）**|热 ** skiing + dict**（元素 ≤ `zset-max-ziplist-entries` 默认 128，value 长度 ≤ `zset-max-ziplist-value` 默认 64）→ **skiplist + dict**（超阈值时）。**跳表的结构必须能手画**：多层有序链表，每一层是下一层的"快速通道"，查询 O(log n)。为什么用跳表不用平衡树？（范围查询方便、实现简单、内存友好）|
|**BitMap 与 HyperLogLog 原理**|BitMap：本质是 String（最大 512MB = 2^32 bit），`SETBIT` / `GETBIT` / `BITCOUNT`。HyperLogLog：基数估算算法，标准误差 0.81%，固定用 12KB 内存估算 2^64 个不同元素。**两者都是"用精度换空间"的典型**|
|**键与值的内存结构**|每个 Redis 键是一个 redisObject（16 字节：type 4bit + encoding 4bit + LRU 24bit + refcount 4B + ptr 8B）。理解这个结构才能理解为什么 `TYPE key` 能返回类型、为什么 `OBJECT ENCODING key` 能看到底层编码|
