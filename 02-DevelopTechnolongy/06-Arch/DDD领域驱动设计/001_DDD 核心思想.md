|#|知识点|核心内容|面试追问|FlowPulse 对应|
|---|---|---|---|---|
|**7.1.1**|**DDD 的本质**|Eric Evans 2003年提出；核心理念：**领域专家和开发人员使用统一的语言(Ubiquitous Language)来构建软件模型**；模型≠UML图，模型=代码+语言+知识|"DDD和普通面向对象设计有什么区别？为什么要用DDD？"|FlowPulse工作流引擎的设计完全基于DDD——领域模型直接映射代码结构|
|**7.1.2**|**DDD 解决什么问题？**|传统开发痛点：①需求理解偏差(业务说A开发做成B)②领域逻辑散落各处(贫血模型/事务脚本)③难以应对复杂业务变化④团队沟通成本高|"你们项目用DDD解决了哪些具体问题？"|工作流引擎的复杂度(条件分支/并行网关/会签/子流程)必须用DDD才能管理|
|**7.1.3**|**DDD 适用场景判断 ★**|✅ 适合：业务逻辑复杂/领域有明确规则/长期演进的项目/多团队协作。❌ 不适合：简单CRUD/短期一次性项目/业务逻辑简单的系统|"什么样的项目不适合用DDD？硬用会有什么后果？"|**FlowPulse工作流引擎域** = 复杂业务逻辑 → 必须DDD / **文件上传服务** = 简单CRUD → 不需DDD|
|**7.1.4**|**DDD vs 传统分层 vs 领域模型驱动对比**|**事务脚本(Transaction Script)**：一个方法一个操作，逻辑在Service层，适合简单场景 → **表数据入口(Table Module)**：以表为中心的OO封装，半路出家 → **领域模型(Domain Model)**：丰富行为+充血模型，DDD的目标形态|"贫血模型和充血模型的本质区别是什么？"|FlowPulse采用**充血领域模型**：`ProcessDefinition.start()` 而非 `ProcessDefinitionService.start()`|

> **💡 三种业务逻辑组织方式对比**

```
┌─────────────────────────┐ ┌──────────────────────────┐ ┌────────────────────────────┐
│  Transaction Script     │ │  Table Data Gateway      │ │  Domain Model (DDD目标)    │
│  事务脚本模式            │ │  表数据入口模式           │ │  领域模式 (充血模型)         │
├─────────────────────────┤ ├──────────────────────────┤ ├────────────────────────────┤
│ Service.doXxx()          │ │ UserService extends       │ │ User.register() {         │
│   → 直接操作DB           │ │   BaseEntity {            │ │   validate();             │
│   → if-else满天飞        │ │     fields = DB columns   │ │   checkDuplicate();       │
│   → 业务逻辑散落          │ │     get/set only          │ │   encryptPassword();      │
│                         │ │   }                       │ │   save();                 │
│ 优点: 简单直观           │ │                           │ │   publishEvent();         │
│ 缺点: 难维护/难复用/     │ │ 优点: OO包装              │ │ }                        │
│      无法应对复杂变更      │ │ 缺点: 还是贫血/无行为     │ │                           │
└─────────────────────────┘ └──────────────────────────┘ │ 优点: 高内聚低耦合/易扩展   │
                                                缺点: 学习曲线陡峭/初期慢  │
                                                └────────────────────────────┘

FlowPulse 定位: 核心域(工作流引擎)=Domain Model / 边缘域(文件服务)=Transaction Script
```
