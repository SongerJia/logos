### 为什么这个模块是面试高频

**TCP 是流协议，没有消息边界**——这是网络编程第一课。Netty 提供了一套完整的解决方案，面试几乎必问："Netty 怎么解决粘包问题的？"

### 知识点表

|序号|知识点|重要度|笔记三层建议|跨模块关联|
|---|---|---|---|---|
|3.1|**TCP 粘包 & 拆包问题本质**|🔴必背|① 粘包：发送端两次 write 被接收端一次 read 收到（Nagle 算法合并小包）② 拆包：发送端一次 write 被接收端两次 read 收到（TCP 分段/MSS 限制）③ 根本原因是 TCP 是流，没有消息边界 ④ 面试：什么是 TCP 粘包？为什么会发生？|→ HTTP/1.1 Keep-Alive（类比）|
|3.2|**四种常用拆包器**|🔴🔴核心|① **LineBasedFrameDecoder**：按换行符 `\n` 拆分（文本协议）② **DelimiterBasedFrameDecoder**：按自定义分隔符拆分（如 `\r\n\r\n` 分割 HTTP 头）③ **FixedLengthFrameDecoder**：固定长度拆分（简单但浪费带宽）④ **LengthFieldBasedFrameDecoder**：最通用！在协议头里带长度字段 ⑤ 面试：你们项目用的什么拆包方式？为什么选这个？|→ HTTP 协议解析 / Dubbo 协议（16 字节头）|
|3.3|**自定义协议设计范式**|🔴必背|① 协议头设计：Magic（4字节）+ Length（4字节）+ RequestID（8字节）+ OpCode（1字节）② 协议体：Payload（变长）+ Checksum（校验和）③ 为什么需要 Magic？防止 TCP 乱序导致解析错误 ④ 面试：设计一个 RPC 协议的二进制格式，画出来|→ Dubbo 协议设计 / gRPC Protobuf|
|3.4|**编码器 & 解码器体系**|🔴必背|① **ByteToMessageDecoder**（入站解码）：字节 → 消息对象 ② **MessageToByteEncoder**（出站编码）：消息对象 → 字节 ③ **Codec**（编解码合一）：同时继承上面两个 ④ 面试：Netty 的编解码器是在 Pipeline 的哪个位置？多个编解码器怎么排序？|→ N4 Pipeline & Handler|
|3.5|**Protobuf & 序列化性能对比**|🟡应掌握|① Protobuf：Google 出品，二进制，体积小，序列化快，需要 IDL 定义 ② 对比：JSON（可读但体积大）/ Hessian（跨语言兼容好）/ Kryo（最快但不跨语言）/ FST（Kryo 替代品）③ Netty 集成 Protobuf：`ProtobufDecoder` / `ProtobufEncoder` ④ 面试：RPC 框架选什么序列化协议？考虑哪些因素？|→ gRPC（基于 Protobuf）/ Dubbo 序列化（多个协议支持）|
|3.6|**字符串 & HTTP 协议编解码**|🟢了解|① `StringDecoder` / `StringEncoder`：基于指定 Charset ② `HttpRequestDecoder` / `HttpResponseEncoder`：Netty 内置 HTTP 协议支持 ③ 可以用来实现高性能 HTTP Server（替代 Tomcat）④ 面试：Netty 能替代 Tomcat 做 Web 服务器吗？什么场景适合？|→ N7 WebSocket / Nginx（反向代理对比）|

> **🏗️ 架构追问**：LengthFieldBasedFrameDecoder 的参数有 5 个（maxFrameLength, lengthFieldOffset, lengthFieldLength, lengthAdjustment, initialBytesToStrip），你能完整解释每个参数的含义吗？这是面试手写题高频考点！
