| 知识点                                           | 笔记时重点写什么                                                                                                               |
| --------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **CAP 理论**                                    | 热 Consistency 一致性 / Availability 可用性 / Partition Tolerance 分区容错性。三者只能取二。注册中心的选型本质就是 CAP 的取舍                            |
| **Nacos AP vs CP 模式切换**                       | 热 默认 AP（Distro 协议，保证可用性，临时实例）；切换 CP（Raft 协议，保证一致性，持久实例）。`ephemeral=true/false` 控制切换。什么时候用哪种？                           |
| **Nacos 服务注册流程**                              | 客户端启动 → 发送 POST `/nacos/v1/ns/instance` 注册请求 → 服务端接收后存入内存 ConcurrentHashMap → 同步到其他节点（AP 用 Distro 异步同步，CP 用 Raft 日志复制） |
| **Nacos 服务发现/拉取机制**                           | 客户端定时轮询 GET `/nacos/v1/ns/instance/list` 拉取服务列表。**关键点**：客户端本地有缓存，轮询间隔默认 10s；如果开启了 UDP 推送，变更时服务端主动推送，实时性更高              |
| **Nacos 心跳与健康检查**                             | 客户端每 5s 发送心跳，服务端 15s 未收到则标记不健康，30s 未收到则剔除。心跳超时时间可配置 `beatInterval`                                                     |
| **Nacos 集群部署与高可用**                            | 至少 3 节点（奇数）。AP 模式下每个节点保存全量数据（Distro 协议）；CP 模式下 Leader 选举 + 日志同步。生产环境建议前置 Nginx/LVS 做负载均衡                               |
| **Nacos vs Eureka vs Consul vs Zookeeper 对比** | 热 做一张对比表：CAP 取向、一致性协议、健康检查方式、负载均衡、集成度、社区活跃度。Eureka 已停更（2.x 后闭源），国内 Nacos 是首选                                           |
| **服务分组与命名空间**                                 | namespace（环境隔离：dev/test/prod）→ group（业务组隔离）→ service → cluster（集群隔离）。四层隔离体系                                            |

> **笔记技巧**：注册中心这块的核心是"为什么选 Nacos"，笔记里要能回答三个问题：①它解决了什么问题（服务动态发现）②它怎么做到高可用的（集群 + AP/CP 切换）③和竞品比差在哪（集成了配置中心是杀手锏）。
