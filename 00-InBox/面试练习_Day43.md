**面试官：众安很多系统是高并发的，比如开门红活动期间投保请求会暴增。你们有没有用 Netty？Netty 和 Tomcat 有什么区别？**

**追问1：** 你提到 Netty 是基于 NIO 的，NIO 的核心组件有哪些？和 BIO 的区别是什么？

→ 你回答...（提示：BIO = 面向流 / 一个连接一个线程 / 阻塞 / NIO = 面向缓冲区 / Channel + Selector + Buffer / 多路复用 / 一个线程管理多个连接 / Selector 轮询就绪的 Channel）

**追问2：** Selector 的底层实现你了解吗？Linux 下用的是 epoll 还是 select？epoll 为什么比 select 高效？

→ 你回答...（提示：Linux 下 NIO 底层用 epoll / select 和 poll 每次都要传全部 fd 集合到内核 → O(n) 遍历 / epoll 用红黑树管理 fd + 就绪列表 / epoll_wait 只返回就绪的 fd → O(1) / epoll 边缘触发 ET vs 水平触发 LT / Netty 默认用 LT）

**追问3：** Netty 的线程模型你了解吗？Boss Group 和 Worker Group 分别做什么？

→ 你回答...（提示：Reactor 模式 / Boss Group 接收连接 → 把连接注册到 Worker / Worker Group 处理读写 / Boss 通常 1 个线程 / Worker 默认 CPU*2 / Netty 4.x 用 NioEventLoopGroup / 每个 EventLoop 绑定一个线程 + 一个 Selector）

**追问4：** Netty 解决了 JDK NIO 的哪些问题？为什么要用 Netty 而不直接用 NIO？

→ 你回答...（提示：JDK NIO 的痛点：①API 复杂易出错 ②epoll 空轮询 bug → CPU 100% ③半包/粘包处理麻烦 ④断线重连没有内置 / Netty 解决：①API 封装 ChannelHandler 责任链 ②修复空轮询 bug ③内置拆包器（LengthFieldBasedFrameDecoder 等）④IdleStateHandler 心跳检测）

**追问5：** Netty 的零拷贝你了解吗？它和操作系统层面的零拷贝是一回事吗？

→ 你回答...（提示：操作系统零拷贝 = mmap / sendfile / sendfile 减少内核态到用户态的拷贝 / Netty 零拷贝 ≠ OS 零拷贝 / Netty 零拷贝 = ①CompositeByteBuf 合并多个 ByteBuf 不拷贝 ②Unpooled.wrappedBuffer 包装 ③FileRegion 用 transferTo ④ByteBuf 池化减少 GC / Netty 零拷贝是"应用层零拷贝"）

**追问6：** ByteBuf 和 JDK 的 ByteBuffer 有什么区别？为什么要自己搞一套？

→ 你回答...（提示：ByteBuffer 单指针 / flip() 容易出错 / 固定容量不能动态扩展 / ByteBuf 读写双指针 / 不用 flip / 支持动态扩展 / 支持池化 PooledByteBufAllocator / 减少 GC 压力）

> 💡 **今日重点提示**：
> 1. **Netty 与 NIO**第一次系统考察。核心主线：BIO（阻塞/一连接一线程）→NIO（多路复用/Channel+Selector+Buffer）→Netty（封装 NIO/解决痛点）。epoll 比 select 高效的原因是"只返回就绪的 fd"而非遍历全部——这是面试核心回答。Boss Group 接连接、Worker Group 干活是 Reactor 模式的核心。Netty 零拷贝是"应用层零拷贝"（CompositeByteBuf 合并不拷贝），和 OS 层面的 mmap/sendfile 不同。ByteBuf 双指针 + 池化是优于 ByteBuffer 的核心
> 2. **ZooKeeper**第一次系统考察。数据结构：树形 ZNode，4种节点类型。Watcher 一次性触发是高频坑——需要重新注册。分布式锁方案：临时顺序节点+监听前一个节点，避免羊群效应。ZAB 协议和 Raft 的区别要知道：ZAB 专为 ZK 设计，Raft 是通用共识。Nacos 替代 ZK 时：服务发现用 AP，配置管理用 CP
> 3. **合并有序链表**是经典基础题，核心是 dummy 虚拟头节点简化代码。k 个链表合并用最小堆 O(N log k) 是面试加分项。递归写法简洁但生产环境别用（栈溢出风险）
> 4. **OAuth 2.0/JWT**第一次系统考察。授权码模式"先返回码再换 Token"是安全设计核心——Token 不经过浏览器。JWT 三段式 Header.Payload.Signature 要能画出来。双 Token 方案（Access + Refresh）是解决 Token 过期的标准方案。JWT Payload 是 Base64 编码不是加密——不能放敏感信息是高频考点
> 5. **Java 8 函数式编程**深入。四个核心接口：Function/Consumer/Supplier/Predicate 要能区分。map vs flatMap 是高频题：map 一对一，flatMap 一对多展开。parallelStream 共享 ForkJoinPool 是坑——不要在里面做 IO。toMap 重复 key 抛异常需要合并函数也是高频追问
> 6. **保险业务**是继银行/证券/基金/期货/外汇之后的新领域。核心链路：投保→核保→承保→保全→理赔→结案。保险和银行最大的区别：银行是确定金额的存取，保险有审核判断和赔付计算。理赔系统设计结合了工作流引擎、规则引擎、AI 模型、资金安全多方知识
> 7. **保险理赔系统设计**是今天的核心设计题。6个追问覆盖：①材料存储（OSS+CDN）②智能初审（规则引擎+AI）③任务流转（工作流引擎+状态机）④资金安全（试算→复核→执行+对账）⑤高并发（限流+异步+弹性扩容+降级）⑥数据分析（数仓+Flink+特征工程）。这六个维度可以套到任何金融系统设计题
> 8. **线上问题排查**是方法论题。"先止血再修复"是核心原则——止血手段（限流/回滚/重启/扩容/切流/人工兜底）要能脱口而出。故障复盘 5 步法要背熟。RTO/RPO 是金融行业面试的高频概念，RTO 管"多快恢复"RPO 管"丢多少数据"
