### 为什么这个模块重要

**分布式系统的核心问题就是"部分节点会挂掉"**。Dubbo 的集群容错机制决定了你的系统在故障时的表现，是面试区分"会用"和"懂原理"的关键。

### 知识点表

|序号|知识点|重要度|笔记三层建议|跨模块关联|
|---|---|---|---|---|
|3.1|**六大集群容错策略**|🔴必背|① **Failover**（默认）：失败自动切换（适合读操作） ② **Failfast**：快速失败（适合写操作，避免重复） ③ **Failsafe**：失败安全（忽略异常，适合日志） ④ **Failback**：失败自动恢复（适合消息通知） ⑤ **Forking**：并行调用多个节点（适合实时性要求高的读） ⑥ **Broadcast**：广播调用所有节点（适合缓存更新） ⑦ 面试：详细解释六大容错策略，分别适合什么场景？|→ RocketMQ 消费重试（类比）/ Nginx upstream 容错|
|3.2|**负载均衡五大策略**|🔴必背|① **Random**（默认）：加权随机 ② **RoundRobin**：加权轮询（支持预热） ③ **LeastActive**：最少活跃调用数（性能最优） ④ **ConsistentHash**：一致性 Hash（相同参数发同一节点） ⑤ **ShortestResponse**：最短响应时间（Dubbo 2.7+） ⑥ 面试：详细解释五大负载均衡策略，一致性 Hash 有什么坑？（节点上下线导致数据倾斜）|→ Nginx upstream 负载均衡（对标）/ 一致性 Hash（算法基础）|
|3.3|**路由策略（Router）**|🟡应掌握|① **条件路由**：基于 IP/参数/方法 的路由规则 ② **标签路由**：基于 Tag 的路由（灰度发布/环境隔离） ③ **脚本路由**：基于脚本（Groovy/JS）的自定义路由 ④ 面试：怎么做 Dubbo 的灰度发布？用什么路由策略？|→ Spring Cloud Gateway 路由（对标）/ Nacos 标签路由|
|3.4|**服务降级 & 熔断**|🔴必背|① **Mock 降级**：配置 `mock="true"` 或 `mock="fail:return null"` ② **熔断**：Dubbo 2.7+ 集成 Sentinel（推荐）或 Hystrix（旧版） ③ **熔断策略**：慢调用比例/异常比例/异常数 ④ 面试：Dubbo 怎么做服务降级和熔断？和 Spring Cloud Hystrix/Sentinel 有什么区别？|→ Sentinel（熔断限流）/ Hystrix（旧版方案）|
|3.5|**Directory & 动态感知**|🟡应掌握|① **Directory**：Invoker 列表的动态目录（从注册中心订阅更新） ② **NotifyListener**：监听注册中心的服务变更事件 ③ **动态下线**：提供者下线后，消费者自动感知并移除 Invoker ④ 面试：Dubbo 消费者怎么感知提供者上/下线的？|→ 注册中心（Nacos/ZK）的 Watch 机制|
|3.6|**优雅停机机制**|🟡应掌握|① 提供者：停止接收新请求 → 处理完存量请求 → 反注册服务 → 关闭 Netty → 释放资源 ② 消费者：不再发起新调用 → 等待进行中调用完成 → 关闭连接 ③ 面试：Dubbo 的优雅停机是怎么实现的？会不会丢请求？|→ Spring Boot 优雅停机（对标）/ Netty EventLoop 优雅关闭|
