## 话题一：Java 异常体系（10分钟）

**面试官：Java 的异常体系是怎样的？Error 和 Exception 的区别是什么？**

你回答（Throwable → Error / Exception、Error不可恢复、Exception可处理）...

**追问1：** CheckedException 和 UncheckedException 的区别？分别举几个例子。为什么 IOException 是 Checked 的？

你回答（编译期检查、RuntimeException及其子类是Unchecked、IOException需要显式处理）...

**追问2：** try-catch-finally 中，如果 catch 里 return 了，finally 还会执行吗？finally 里 return 会怎样？

你回答（finally会执行、finally里return会覆盖catch的return、不建议在finally里return）...

**追问3：** try-with-resources 是怎么实现的？它的本质是什么？

你回答（语法糖、AutoCloseable接口、编译后生成try-catch-finally、自动调用close()）...

**追问4：** 如果 try 块和 finally 块都抛了异常，最终抛出的是哪个？另一个异常会丢吗？

你回答（finally的异常会覆盖try的异常、try的异常被抑制、Java 7的addSuppressed）...

**追问5：** 你们项目里异常是怎么处理的？全局异常处理器怎么做的？自定义异常一般继承哪个类？

你回答（@ControllerAdvice + @ExceptionHandler、自定义业务异常继承RuntimeException）...

## 话题二：ThreadLocal 深入（12分钟）

**面试官：ThreadLocal 的原理是什么？每个线程的变量存在哪里？**

你回答（ThreadLocalMap、Thread对象里的threadLocals字段）...

**追问1：** ThreadLocalMap 的 key 是弱引用，value 是强引用，为什么要这么设计？如果不这么设计会怎样？

你回答（key弱引用防止ThreadLocal对象泄漏、value强引用因为线程还需要用）...

**追问2：** 那 value 为什么会内存泄漏？ThreadLocal 已经被回收了，value 还在，怎么办？

你回答（线程池场景线程不销毁、ThreadLocalMap的Entry中key=null但value还在、remove()清理）...

**追问3：** ThreadLocal 的 get() 方法里，如果找到的 Entry 的 key 是 null，它会做什么？

你回答（清理过期Entry、expungeStaleEntry、向后扫描清理）...

**追问4：** InheritableThreadLocal 是什么？它和 ThreadLocal 有什么区别？能实现父子线程传值吗？

你回答（子线程可继承父线程的值、Thread的inheritableThreadLocals字段、创建子线程时复制）...

**追问5：** 如果是用线程池，InheritableThreadLocal 还能正常工作吗？为什么？有什么替代方案？

你回答（不能、线程池复用线程、提交任务时不是创建新线程、TransmittableThreadLocal）...

## 话题三：手写代码 - 环形链表判断（8分钟）

**面试官：给你一个单链表，判断它有没有环。写一下。**

你在纸上/白板上写代码...

```java
public class ListNode {
    int val;
    ListNode next;
    ListNode(int val) { this.val = val; }
}

// 判断链表是否有环
public boolean hasCycle(ListNode head) {
    // 你来实现
}
```

**追问1：** 你用的是什么方法？快慢指针为什么一定能相遇？如果有环，快指针会不会跳过慢指针？

你回答（Floyd判圈法、快指针走两步慢指针走一步、每步差距缩小1必定相遇）...

**追问2：** 时间复杂度是多少？空间复杂度呢？有没有空间复杂度更低的方案？

你回答（O(n)时间、O(1)空间、快慢指针已经是最优空间）...

**追问3：** 如果要找到环的入口节点呢？怎么算？

你回答（相遇后让一个指针从头走、两个指针同速再次相遇点就是入口、数学推导）...

**追问4：** 如果不用快慢指针，用 HashSet 记录访问过的节点，可以吗？优缺点是什么？

你回答（可以、时间O(n)空间O(n)、简单但空间开销大）...

## 话题四：Spring 事件机制（10分钟）

**面试官：Spring 的事件机制了解吗？ApplicationEvent 和 ApplicationListener 是什么？**

你回答（观察者模式、发布订阅、ApplicationContext作为事件总线）...

**追问1：** Spring 4.2 之后，发布事件和监听事件的方式有什么变化？

你回答（不需要继承ApplicationEvent、任意对象可作为事件、@EventListener注解）...

**追问2：** @EventListener 标注的方法，是同步执行还是异步执行？如果想异步怎么办？

你回答（默认同步、加@Async异步、需要配置线程池）...

**追问3：** 如果有多个监听同一个事件的 Listener，它们的执行顺序是怎样的？能控制顺序吗？

你回答（按注册顺序、@Order注解控制优先级、实现Ordered接口）...

**追问4：** 你们项目里有没有用过 Spring 事件机制？用来做什么？和直接调用方法有什么区别？

你回答（解耦、存款活动完成后发通知、不需要等通知返回）...

**追问5：** Spring 事件机制和消息队列（RocketMQ/Kafka）都能做异步解耦，什么场景用哪个？区别在哪？

你回答（Spring事件是进程内、MQ是跨进程、可靠性要求高用MQ、简单解耦用Spring事件）...

## 话题五：MySQL 执行计划实战（12分钟）

**面试官：你简历上写了 MySQL 慢SQL优化经验，说说 explain 的结果里你最关注哪些字段？**

你回答（type、key、rows、Extra）...

**追问1：** type 字段的值有哪些？从好到差排一下。const 和 ref 有什么区别？

你回答（system > const > eq_ref > ref > range > index > ALL、const主键或唯一索引等值、ref非唯一索引等值）...

**追问2：** Extra 字段里出现 `Using filesort` 是什么意思？什么情况会触发？怎么优化？

你回答（无法用索引完成排序、需要额外排序、加排序字段的索引、限制排序数据量）...

**追问3：** Extra 里 `Using index` 和 `Using where; Using index` 的区别是什么？

你回答（Using index是覆盖索引不需要回表、Using where; Using index是覆盖索引但需要过滤）...

**追问4：** 给你一条 SQL：`SELECT * FROM orders WHERE user_id = 100 AND status = 1 ORDER BY create_time DESC LIMIT 10`，联合索引该怎么建？为什么？

你回答（(user_id, status, create_time)、等值查询在前、排序字段在后、覆盖索引避免回表）...

**追问5：** 如果这条 SQL 的 orders 表有 5000 万条数据，即使有索引还是很慢，你会怎么进一步优化？

你回答（分库分表、冷热分离、ES搜索、游标分页替代limit）...

## 话题六：Redis Stream 与消息队列（10分钟）

**面试官：Redis 5.0 引入了 Stream，你了解吗？它和 Redis 的 Pub/Sub 有什么区别？**

你回答（Stream持久化、支持消费者组、Pub/Sub不持久化发完即弃）...

**追问1：** Stream 的消费者组是什么概念？怎么保证一条消息只被一个消费者处理？

你回答（XGROUP CREATE、XREADGROUP、pending list、消息分配给组内消费者）...

**追问2：** 如果一个消费者处理消息时宕机了，这条消息怎么办？怎么重新分配？

你回答（消息留在pending list、XPENDING查看、XCLAIM转移给其他消费者）...

**追问3：** Stream 和 RocketMQ/Kafka 相比，能替代专业 MQ 吗？什么场景适合用 Stream？

你回答（不能完全替代、消息量小且已有Redis、不要求高吞吐、轻量级场景）...

**追问4：** Stream 的消息怎么确认消费完成？如果忘记确认会怎样？

你回答（XACK确认、不确认会留在pending list、不会删除、需要定期清理）...

**追问5：** 你们项目里用 Redis 做过消息队列吗？用的什么方式？为什么不用专业 MQ？

你回答（List + BRPOP、或Stream、简单场景轻量级、不需要额外部署MQ）...

## 话题七：项目深挖 - 滑动窗口限流（10分钟）

**面试官：你简历上写了滑动窗口限流，具体是怎么实现的？窗口大小和阈值怎么定的？**

你回答（时间窗口划分、计数器滑动、结合业务压测确定阈值）...

**追问1：** 你的滑动窗口和固定窗口有什么区别？解决了固定窗口的什么问题？

你回答（固定窗口临界突刺、滑动窗口平滑过渡、窗口越细越精确但开销越大）...

**追问2：** 你这个限流是单机的还是分布式的？如果是分布式怎么做？

你回答（单机用本地计数、分布式用Redis + Lua脚本原子操作）...

**追问3：** 限流之后被拒绝的请求怎么处理？直接返回错误还是有其他策略？

你回答（直接拒绝返回429、或排队等待、或降级返回缓存数据、看业务场景）...

**追问4：** 你和 Sentinel 的滑动窗口比，有什么区别？为什么没有直接用 Sentinel？

你回答（Sentinel功能更全、自己实现更轻量可定制、项目当时不需要Sentinel全部功能）...

**追问5：** 如果现在让你重新设计这个限流方案，你会怎么改进？

你回答（引入Sentinel、自适应限流、多维度的限流规则、监控告警）...

## 二面话题一：高并发库存扣减设计（12分钟）

**面试官：假设你设计一个证券打新系统，同一只新股可能有几十万人同时申购，怎么保证不超卖？**

你回答（分布式锁、Redis预扣减、数据库乐观锁）...

**追问1：** 如果用 Redis 预扣减库存，Redis 挂了怎么办？库存数据丢了怎么办？

你回答（Redis持久化、主从切换、数据库兜底、对账修复）...

**追问2：** Redis 扣减和数据库扣减不在同一个事务里，怎么保证一致性？扣了Redis但数据库失败了怎么办？

你回答（最终一致性、消息队列异步扣减数据库、对账补偿、幂等设计）...

**追问3：** 如果是几十万并发同时打到一个数据库上做库存扣减，数据库扛不住怎么办？

你回答（Redis挡住大部分请求、数据库分库分表、排队削峰、异步落库）...

**追问4：** 申购结果什么时候返回给用户？同步返回还是异步通知？如果异步，用户体验怎么保证？

你回答（同步返回受理成功、异步通知最终结果、前端轮询或推送、设置合理预期）...

**追问5：** 打新结束后，怎么对账确保数据准确？如果发现 Redis 扣减数和数据库不一致，怎么修复？

你回答（定时对账、差异修复脚本、人工介入阈值、日志链路追溯）...

你回答（分布式事务、Seata AT、消息最终一致性、TCC）...

**追问1：** 你们实际用的是哪种方案？为什么选这种？遇到过什么问题？

你回答...

**追问2：** Seata AT 模式的原理是什么？它对数据库有什么要求？为什么有些场景不能用 AT？
