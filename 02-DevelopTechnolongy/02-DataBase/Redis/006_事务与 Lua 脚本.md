|知识点|笔记时重点写什么|
|---|---|
|**MULTI/EXEC 事务**|热 `MULTI` 标记事务开始 → 命令入队（不执行，返回 QUEUED）→ `EXEC` 一次性执行所有命令 → `DISCARD` 取消事务。**关键**：Redis 事务**不支持回滚**（语法错误会导致 EXEC 失败，但运行时错误如类型不匹配不会回滚，会继续执行后续命令）。这不是 Bug 是设计选择（简单且快速）|
|**WATCH 乐观锁**|热 `WATCH key1 key2` 监视 key，如果在 `EXEC` 之前任何被监视的 key 被其他客户端修改了，则 `EXEC` 返回 `nil`（事务失败）。**这是 Redis 实现乐观锁的方式**，类似于数据库中 `WHERE version=?` 的 CAS 机制|
|**Lua 脚本：原子性保证**|热 **Lua 脚本在 Redis 中是原子执行的**（执行期间不会插入其他命令），这是实现复杂原子操作的首选方式。**经典场景**：限流（令牌桶）、分布式锁释放（先 GET 再 DEL，用 Lua 保证原子性）、库存扣减（先查再减，避免超卖）|
|**EVAL/EVALSHA 执行脚本**|`EVAL script numkeys key [key ...] arg [arg ...]` 直接执行脚本；`EVALSHA sha1 numkeys key [key ...] arg [arg ...]` 通过脚本的 SHA1 摘要执行（先 `SCRIPT LOAD` 加载脚本到 Redis）。**生产环境推荐 EVALSHA**（减少网络传输脚本内容）|
|**Lua 脚本的坑**|核 ①脚本不能写死循环（会阻塞 Redis，`lua-time-limit` 默认 5s 强制终止）②脚本中不能访问外部网络（纯计算 + Redis 命令调用）③集群模式下 Lua 脚本操作的 key 必须落在同一个 slot（用 `{}` hash tag 保证）|
