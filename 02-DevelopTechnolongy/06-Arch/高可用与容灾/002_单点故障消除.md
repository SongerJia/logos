|**4.2.1**|**SPOF 识别方法**|Single Point of Failure：系统中任何一个组件故障都会导致整体不可用的节点；识别方法：画架构图逐个问"如果这个挂了会怎样？"|数据库 / 缓存 / 注册中心 / 消息队列 / 对象存储 / 网关 / 外部依赖(短信/邮件)|"你项目中有哪些潜在的单点？怎么排查的？"|**FlowPulse SPOF 清单** ↓|
|**4.2.2**|**负载均衡 LB 消除应用单点**|Nginx(L4/L7) / F5 / 云厂商LB；算法：轮询/加权/最少连接/IP Hash/一致性Hash；健康检查机制|"Nginx upstream 的 fail_timeout 和 max_fails 怎么配合使用？"|**K8s Service(ClusterIP)** 作为内部LB + **Nginx** 作为外部入口LB||
|**4.2.3**|**数据库高可用消除存储单点**|MySQL主从复制(Master-Slave) + VIP漂移 / MGR组复制 / ProxySQL中间件路由；读写分离减轻主库压力|"MySQL主从切换过程中数据可能丢失吗？半同步复制能解决吗？"|**MySQL MGR 单主模式**：3节点组复制 + ProxySQL自动路由读请求||
|**4.2.4**|**缓存高可用消除缓存单点**|Redis Sentinel(哨兵模式：监控+自动故障转移) / Redis Cluster(去中心化分片+槽位迁移)；持久化(RDB/AOF)防数据丢失|"Redis Cluster的槽位迁移过程对业务有影响吗？MOVED和ASK区别？"|**Redis 7 Sentinel 模式**：1主2从 + 3个Sentinel监控 + 自动故障转移(<10s)||
|**4.2.5**|**消息队列高可用消除MQ单点**|RocketMQ Broker集群(NameServer发现 + Master-Slave同步/异步刷盘 + Dleger Raft选主)|"RocketMQ的Broker Master挂了Slave怎么接管？消息会丢吗？"|**RocketMQ 2Master-2Slave 同步双写**：NameServer集群发现 + DLedger自动选主||
