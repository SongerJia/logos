## 推荐学习顺序

```
01 倒排索引（理解ES的核心原理）
    ↓
02 Mapping（知道数据怎么存）
    ↓
03 DSL查询（学会怎么查）
    ↓
04 分布式架构（理解集群怎么工作）
    ↓
05 写入流程（理解NRT和数据一致性）
    ↓ （01-05是理论地基，必须扎实）
08 选型对比（建立全局视角）
    ↓
06 Java API（开始动手写代码）
    ↓
07 调优运维（进阶，有了项目经验再深入）
```

> **注意**：如果面试岗位不是搜索/日志方向，01~~05 + 08 够用了。06~~07 可以作为加分项。

## 🔗 跨模块关联

```
Elasticsearch
├── → MySQL：
│   ├── ES 无事务支持，MySQL是SoT(System of Truth)
│   ├── Canal binlog同步 → ES（数据一致性桥梁）
│   └── B+树 vs 倒排索引 vs Hash索引（三种索引思想对比）
├── → Redis：
│   ├── ES搜索结果缓存到 Redis（加速热查询）
│   └── Redis 不适合复杂查询，ES 补位
├── → 分库分表：
│   └── 分库后全局搜索困难 → 引入 ES 统一检索层
├── → RocketMQ/Kafka：
│   └── 异步写入 ES 解耦（搜索数据非强一致场景）
├── → JVM：
│   └── ES 底层跑在 JVM 上，GC停顿直接影响查询延迟
│   ├── Heap ≤31G 规则（Compressed Oops）
│   └── G1GC 调参（MaxGCPauseMillis）
├── → Java 并发：
│   └── 多线程并发写入 ES 的并发控制
└── → 运维（待学）：
    ├── ELK Stack（Elasticsearch + Logstash + Kibana）
    └── Docker/Kubernetes 部署 ES 集群
```

## 💡 写笔记提醒

- **倒排索引的四层结构**一定要手动画出来——TermIndex(FST) → TermDictionary → PostingList → Document，这是整个 ES 知识体系的基石
- **text vs keyword** 是第一大坑，面试官最爱拿这个设陷阱（用 term 查 text 字段查不到结果）
- **深分页**问题要准备完整的三种方案对比表，能说出每种方案的局限性和适用场景
- **Write 完整链路**的时序图是第二大高频考点，从客户端到 ACK 每一步都不能少
- **ES vs MySQL 数据同步**是实战必问，Canal 方案要能讲清楚端到端流程
- **不需要背所有 DSL 语法**，理解 bool 查询结构和 Query/Filter 区别就够了，语法可以查文档
