### 为什么这个模块最重要

**这是 Dubbo 的核心价值**：让远程调用像本地调用一样简单。理解代理机制和 Invoker 链，就理解了 Dubbo 的"魔法"所在。

### 知识点表

|序号|知识点|重要度|笔记三层建议|跨模块关联|
|---|---|---|---|---|
|2.1|**代理机制：JDK 动态代理 vs Javassist**|🔴必背|① 默认用 Javassist（性能更好，字节码生成） ② 代理对象：把接口方法调用转换成 Invocation 对象 ③ 面试：Dubbo 用的是 JDK 动态代理还是 CGLIB？为什么？|→ Spring AOP（代理机制对比）/ MyBatis Mapper（代理模式）|
|2.2|**Invoker 调用链设计**|🔴🔴核心|① Invoker：Dubbo 的核心模型，封装了执行体（可以是本地/远程/集群） ② 调用链：MockInvoker → FailoverInvoker → DirectoryInvoker → RouterInvoker → ClusterInvoker → Invoker ③ 类似责任链，每个 Invoker 做一件事 ④ 面试：解释 Dubbo 的 Invoker 调用链设计，它和责任链模式有什么关系？|→ Netty Pipeline（责任链类比）/ 责任链模式（GoF）|
|2.3|**Consumer 引用服务流程**|🔴必背|① 配置解析 → 连接注册中心 → 订阅服务 → 生成代理 → 注入 Spring 容器 ② 关键类：ReferenceBean（配置）→ RegistryProtocol（注册）→ InvokerInvocationHandler（代理） ③ 面试：详细描述消费者引用服务的完整流程|→ Spring Bean 生命周期（注入过程）|
|2.4|**Provider 暴露服务流程**|🔴必背|① 配置解析 → 绑定 IP+端口 → 打开 Netty Server → 注册到注册中心 → 暴露服务 URL ② 关键类：ServiceBean → ServiceConfig → RegistryProtocol.export() ③ 面试：详细描述提供者暴露服务的完整流程|→ Netty Server 启动（NIO 绑定端口）|
|2.5|**异步调用 & CompletableFuture**|🟡应掌握|① Dubbo 2.7+ 支持异步调用：`async() + thenApply()` ② `CompletableFuture` 返回类型 ③ `AsyncContext` 管理异步上下文 ④ 面试：Dubbo 怎么做异步调用？和同步调用的线程模型有什么区别？|→ Java CompletableFuture（并发编程）/ Reactive 编程|

> **🏗️ 架构追问**：如果让你设计一个"支持 Reactive Streams（响应式流）"的 RPC 框架，你会怎么改造 Invoker 链？提示：需要在 Invoker 层面支持背压（Backpressure）。
