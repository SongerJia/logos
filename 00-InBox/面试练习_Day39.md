**追问2：** 类型擦除会带来什么问题？你有没有在代码里遇到过泛型的"坑"？

## 话题二：ThreadLocal 原理与内存泄漏（10分钟）

**面试官：你在项目里用过 ThreadLocal 吗？什么场景下用的？**

→ 你回答...

**追问1：** ThreadLocal 的底层实现原理是什么？每个线程的数据是怎么存的？

→ 你回答...（提示：每个 Thread 有一个 ThreadLocalMap / ThreadLocalMap 的 key 是 ThreadLocal 对象的弱引用 / value 是强引用 / `ThreadLocal.set()` 实际是往当前线程的 ThreadLocalMap 里放）

**追问2：** key 是弱引用，value 是强引用，这会导致什么问题？

→ 你回答...（提示：ThreadLocal 对象被回收后 key 变成 null / 但 value 还被 Entry 强引用 / value 无法回收 → 内存泄漏）

**追问3：** ThreadLocal 设计者不知道这个问题吗？他们做了什么补救措施？

→ 你回答...（提示：`set()`/`get()`/`remove()` 操作时会清理 key 为 null 的 Entry（expungeStaleEntry）/ 但如果之后不再调用任何方法，value 还是泄漏 / 所以必须手动 `remove()`）

**追问4：** `InheritableThreadLocal` 你了解吗？它和普通 ThreadLocal 有什么区别？子线程能拿到父线程的 ThreadLocal 值吗？

→ 你回答...（提示：普通 ThreadLocal 子线程拿不到 / InheritableThreadLocal 在创建子线程时复制父线程的值 / 但线程池场景下复用线程，不会重新复制 → 用 `TransmittableThreadLocal`（阿里 TTL）解决线程池传递问题）

**追问5：** 你们项目里 ThreadLocal 有没有用来做链路追踪的 traceId 传递？如果用了线程池，traceId 能传到子线程吗？

→ 你回答...（提示：普通 ThreadLocal 在线程池场景下传不了 / 需要用 TTL 或者在提交任务时手动传递 / 链路追踪框架如 SkyWalking 用字节码增强解决）

> 💡 **今日重点提示**：
> 1. **Java 泛型深入**第一次系统考察。类型擦除是核心——Java 泛型只在编译期检查，运行时 `List<String>` 和 `List<Integer>` 是同一个类型。PECS 原则（Producer Extends Consumer Super）是高频追问，理解"为什么 extends 只读、super 只写"比背口诀重要。不能 `new T()` 的原因是类型擦除后 T 是什么类型运行时不知道
> 2. **ThreadLocal**在 Day6/Day14/Day16 提过线程安全和线程池，但没深入 ThreadLocal 的底层数据结构。核心记住：Thread → ThreadLocalMap → Entry(弱引用key, 强引用value)。内存泄漏的根因是 key 被回收但 value 还在。线程池场景下 ThreadLocal 传不了，这是 InheritableThreadLocal 和 TTL 存在的原因
> 3. **合并有序链表**是经典递归/迭代题，比前面的排序题简单。重点在追问——合并 K 个链表用小顶堆是面试区分度题。如果链表大到放不进内存，就变成了外部归并排序的问题
> 4. **Kafka 分区**在 Day9/Day26 提过 Kafka，今天从分区和消费者组角度切入。Rebalance 是 Kafka 的痛点——Stop The World 式暂停。金融场景选 RocketMQ 还是 Kafka 是高频追问，核心论据：RocketMQ 有事务消息、同步刷盘、更成熟的金融级保障
> 5. **CompletableFuture**是 Java 异步编程的核心。Future 的三个局限（阻塞、不能链式、不能组合）是出发点。默认线程池 ForkJoinPool 共享的问题在生产环境必须避免。`thenApply` vs `thenCompose` vs `thenCombine` 的区别是高频考点，类比 `map` vs `flatMap` vs `zip`
> 6. **期货业务知识**是新的业务领域。和股票/基金的核心区别：保证金制度（杠杆）、每日无负债结算（盯市）、强行平仓、T+0 双向交易。保证金比例 10% = 10 倍杠杆是面试官验证你懂不懂的快速检查点
> 7. **期货交易清算系统设计**是今天的核心设计题。重点准备四个追问：①盈亏计算用 BigDecimal 不用 double ②清算差 1 分钱怎么排查（手续费/结算价/精度策略）③强平未成交怎么办（追加强平/穿仓风险）④几十万客户 2 小时清算完（分片并行+批量写入）。这四个追问覆盖了金融清算系统最核心的技术挑战
> 8. **分布式锁**在 Day7/Day15/Day19/Day34 提过 Redisson 分布式锁，今天做方案对比。重点掌握：SETNX 的问题 → SET NX PX → Redisson 看门狗 → Lua 脚本保证原子性 → Redlock 争议。金融场景锁选型：一致性要求高用 ZK，性能要求高用 Redis，简单场景用数据库行锁
