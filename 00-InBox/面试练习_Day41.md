## 话题二：Java SPI 机制与 Dubbo SPI（10分钟）

**面试官：你简历上写了"了解 Dubbo RPC 框架"。Dubbo 的扩展机制你了解吗？它和 Java 原生 SPI 有什么区别？**

→ 你回答...（提示：Service Provider Interface / META-INF/services/ 目录下放接口全限定名文件 / 内容是实现类全限定名 / `ServiceLoader.load()` 加载 / JDBC Driver 就是 SPI / Spring Boot 自动配置也借鉴了 SPI 思想）

**追问5：** 如果你要在自己公司内部做一个组件框架，让各业务线接入时自动注册实现，你会用 SPI 还是 Spring Boot 自动配置？怎么选？

## 话题四：ConcurrentHashMap 原理深入（10分钟）

→ 你回答...

**追问1：** JDK 7 和 JDK 8 的 ConcurrentHashMap 实现有什么区别？

→ 你回答...（提示：JDK 7 分段锁 Segment / 默认 16 段并发度 16 / JDK 8 放弃分段锁改用 CAS + synchronized 锁单个桶 / Node 数组 + 链表/红黑树 / 并发度 = 桶数量）

**追问2：** JDK 8 的 ConcurrentHashMap，put 操作的流程是怎样的？怎么保证线程安全？

→ 你回答...（提示：key hash 定位桶 / 桶为空 CAS 写入 / 不空 synchronized 锁桶头节点 / 链表长度 >= 8 转红黑树 / 扩容时多线程协助迁移）

**追问3：** ConcurrentHashMap 的 size() 是怎么计算的？多线程并发 put 时 size 准确吗？

→ 你回答...（提示：`baseCount` + `CounterCell` 数组累加 / 类似 LongAdder 的思想 / 分段计数减少竞争 / size 大致准确但不是强一致 / 并发场景 size 可能略有偏差）

**追问4：** ConcurrentHashMap 的扩容和 HashMap 的扩容有什么区别？

→ 你回答...（提示：HashMap 先扩容再迁移单线程 / ConcurrentHashMap 多线程协助迁移 / `transfer` 方法 / 每个线程认领一段桶迁移 / `ForwardingNode` 标记已迁移的桶 / 读操作遇到 ForwardingNode 走新表）

**追问5：** ConcurrentHashMap 能不能存 null key 或 null value？为什么？

→ 你回答...（提示：不允许 null key 和 null value / HashMap 允许 / 原因：`containsKey` 歧义——返回 null 可能是值为 null 也可能是 key 不存在 / 单线程可以 `containsKey` 二次确认 / 多线程下两次调用之间可能被修改 / 用 null 会导致 NPE 难排查）

> 💡 **今日重点提示**：
> 1. **MyBatis 插件机制**第一次系统考察。核心是"动态代理 + 责任链"——拦截四大组件（Executor/StatementHandler/ParameterHandler/ResultSetHandler），层层包裹。PageHelper 就是最经典的插件实现。一级缓存在 Spring 下几乎不生效是高频追问，原因是每次查询新建 SqlSession
> 2. **Java SPI**第一次出现。核心链路：`META-INF/services/` → `ServiceLoader.load()` → 按需实例化。Dubbo SPI 的改进（按 key 加载、自适应扩展、IOC/AOP）是体现你对 Dubbo 理解深度的加分项。Spring Boot 自动配置和 SPI 的关系是把 SPI 思想应用到 Spring 生态
> 3. **二叉树层序遍历**是 BFS 经典题。核心是"队列 + 按层处理"。锯齿形变体不改变 BFS 逻辑只改收集顺序。注意追问"树很深时 BFS 内存"——这考的是你对算法的空间复杂度理解
> 4. **ConcurrentHashMap**在 Day1/Day11 提过 HashMap 源码，今天从并发安全角度深入。JDK 7 分段锁 → JDK 8 CAS + synchronized 是核心演进。不允许 null 是因为多线程下 `containsKey` 二次确认有竞态条件。size 用分段计数（类似 LongAdder）是大致准确不是强一致
> 5. **Redisson 高级组件**在 Day39 做了分布式锁对比，今天扩展到布隆过滤器、限流器、读写锁、延迟队列。布隆过滤器的"存在不一定存在，不存在一定不存在"是核心记忆点。Redisson 读写锁的分布式实现比 Java 读写锁多了网络交互，但语义一致
> 6. **证券行情推送系统设计**是今天的核心设计题。重点准备：①50万连接怎么扛（Netty NIO + 多实例 + 负载均衡）②Level-2 数据量控制（服务端聚合 + 按订阅推送）③断线重连和补全机制（序号 + 快照恢复）④行情和交易系统隔离。Netty 不需要深入源码但要知道"NIO + 单线程管多连接"的核心思想
> 7. **技术选型**是二面的软实力题。面试官想看的是你的判断力——什么时候引入新技术、怎么评估、后悔了怎么处理。核心原则：业务价值驱动而非技术驱动，引入前做 POC 验证，灰度引入而非一步到位。诚实说"后悔了"比说"从没选错过"更可信
