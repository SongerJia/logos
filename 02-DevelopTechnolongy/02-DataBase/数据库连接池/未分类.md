## 🔗 跨模块关联

```
数据库连接池
├── → MySQL：maxLifetime < wait_timeout（MySQL系统变量）
├── → Redis：Lettuce/Jedis 也有连接池概念，但Redis客户端自带
├── → Spring 事务：@Transactional 如何影响连接的获取和释放
├── → 分库分表：ShardingSphere 下每个物理库独立连接池
├── → JVM：连接是重量级对象（持有Socket/Buffer），涉及堆外内存
├── → Java 并发：ConcurrentBag 无锁设计 / ThreadLocal 缓存
└── → 监控运维：Druid SQL监控 → Prometheus/Grafana 可视化
```

- **HikariCP 的无锁 ConcurrentBag** 是整个连接池知识体系的灵魂，画一张 borrow/return 的状态流转图
- **连接池耗尽排查** 是面试最爱问的场景题，准备 2-3 个真实案例（慢SQL占住 / 泄漏 / max太小）
- **参数调优公式**要背下来，面试官直接问你"你们项目连接池配多少？为什么？"就能答上来
- **Druid 和 HikariCP 不冲突**——很多公司用 Druid 做 SQL 监控，底层连接池还是 HikariCP
