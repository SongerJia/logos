|知识点|笔记时重点写什么|
|---|---|
|**8 种淘汰策略**|热 **必背清单**：`noeviction`（不淘汰，写满报错，默认）/ `allkeys-lru`（全局 LRU）/ `volatile-lru`（设有过期时间的 key 中 LRU）/ `allkeys-random` / `volatile-random` / `volatile-ttl`（剩余 TTL 最短的先淘汰）/ `allkeys-lfu`（4.0+，全局 LFU）/ `volatile-lfu`。**LRU vs LFU 的区别：LRU 看最近访问时间，LFU 看访问频率（更适合突发热点）**|
|**LRU 与 LFU 实现原理**|核 Redis 的 LRU 是**近似 LRU**（采样 `maxmemory-samples` 个 key 淘汰最久未访问的，默认采样 5 个，不是严格 LRU）。LFU 用 8bit 计数器（高 4bit 是访问频率对数，低 4bit 是衰减时间），**理解 LFU 的衰减机制（随时间降低频率）才能理解为什么它能更好处理突发热点**|
|**键过期删除策略**|热 **三种策略**：定时删除（设定时器，CPU 压力大，不推荐）/ 惰性删除（访问时检查是否过期，对内存不友好）/ **定期删除（默认每 100ms 抽查一批， Redis 实际用的方案）**。Redis 实际是**惰性删除 + 定期删除**组合使用|
|**内存碎片整理**|`activedefrag yes` 开启主动碎片整理（4.0+）。碎片率 = `used_memory_rss / used_memory`，> 1.5 就需要关注。整理原理：将占用连续内存的小键值对重新排列，释放碎片空间。**这是一个后台线程，不阻塞主线程**|
|**bigkey 大键问题**|热 定义：String > 10KB / Hash/List/Set/ZSet > 5000 个元素。**危害**：网络阻塞（DEL 大 key 阻塞主线程）、内存不均（Cluster 模式下某些 slot 数据过多）。**排查**：`redis-cli --bigkeys` / `MEMORY USAGE key`。**解决**：拆分（大 Hash 拆成多个小 Hash）/ 异步删除（`UNLINK` 命令，4.0+，后台线程删除）|
|**hotkey 热键问题**|热 定义：某个 key 访问频率极高（如热点新闻、秒杀商品）。**危害**：该 key 所在节点 CPU 飙高，成为瓶颈。**解决方案**：①本地缓存（JVM 级 Caffeine / Guava Cache）②备份（key 加上后缀 `_copy1` / `_copy2` 分散到不同节点）③读写分离（读从节点，但注意数据延迟）|
