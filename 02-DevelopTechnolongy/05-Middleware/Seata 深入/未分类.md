### 推荐学习顺序

```
M1 基础架构(5点) → M2 AT模式(7点)★ → M3 TCC模式(5点)
→ M7 Spring整合(5点) → M8 调优排障(6点)

```

### 面试最高频 Top 5 考点

1. **AT 模式两阶段流程** + Undo Log 结构 — 几乎必问
2. **全局锁 vs 本地锁** 的设计权衡 — 区分候选人的分水岭
3. **脏写 / 悬挂 / 空回滚** 三大异常防御机制
4. **TCC 的空回滚 / 悬挂 / 幂等** 问题及解决方案
5. **@GlobalTransactional** 底层执行流程源码级分析

### Seata 与其他模块的关联网络

```
Seata ←→ MySQL (事务/锁/MVCC/Undo Log 思想同源)
     ←→ Redis (分布式锁对比全局锁)
     ←→ RocketMQ (事务消息 vs AT/TCC 方案选型)
     ←→ Spring Cloud (Feign XID传播 / AOP拦截 / 自动装配)
     ←→ SkyWalking (分布式事务链路追踪)
     ←→ Nacos (TC注册发现/配置中心)
```

### ⚠️ 写笔记特别提醒

1. **AT 模式的 2.2(Undo Log) + 2.3(全局锁) + 2.5(三大异常)** 这三个知识点，建议画完整的时序图，不要只记文字。面试官最喜欢让你"在白板上画出一次 AT 分布式事务的完整执行过程"
2. **M3 TCC** 强烈建议手写一个完整的「账户转账」TCC 示例（含幂等表、防悬挂检查），这是能直接展示编码能力的加分项
3. **M2 架构追问**：每个核心知识点都加了第四层"如果是我来设计"，这是拉开差距的关键
