| 知识点                                   | 笔记时重点写什么                                                                                                                                                    |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **核心概念**                              | Trace（一次完整请求调用链，全局唯一 TraceId）、Span（一个工作单元，有 SpanId 和 ParentSpanId）、Annotation（事件标记：CS 客户端发送 / SR 服务端接收 / SS 服务端发送 / CR 客户端接收）                               |
| **SkyWalking vs Zipkin vs Jaeger 对比** | SkyWalking（国产，中文文档好，对 Java Agent 支持强大，监控+追踪一体）、Zipkin（Twitter 出品，轻量级，与 Spring Cloud 集成好）、Jaeger（CNCF 毕业，UI 好，云原生生态好）。**国内项目首选 SkyWalking**                  |
| **TraceId 透传机制**                      | 核 第一个服务生成 TraceId → 通过 RPC 框架的上下文（Feign 的 RequestInterceptor / Dubbo 的 RpcContext）传给下游 → 每个下游服务继续传递 → 最终汇聚到追踪后端。**如果用了消息队列，TraceId 要放到 Message Header 中传递** |
| **采样率与性能影响**                          | 全量采集对性能有影响（通常 5%~15% 开销）。生产环境设置采样率（如 10%~20%，按需调整）。SkyWalking 默认采样率可在 agent 配置中设置                                                                           |
| **链路追踪与日志关联**                         | 热 把 TraceId 打入日志（Logback MDC 注入），这样在追踪界面上看到某次请求慢 → 直接拿 TraceId 去日志平台搜对应日志。**排查问题的标准流程**                                                                     |
