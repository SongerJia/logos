### 为什么这个模块

**池化是性能优化的核心手段**。Netty 4+ 的 PooledByteBufAllocator 是教科书级的内存池实现，理解它对理解"高性能中间件"的设计哲学很有帮助。

### 知识点表

|序号|知识点|重要度|笔记三层建议|跨模块关联|
|---|---|---|---|---|
|6.1|**为什么需要池化？**|🟡应掌握|① 堆外内存分配成本高（系统调用 `malloc`/`free`）② 频繁 GC 会导致停顿 ③ 池化：预先分配一大块内存，按需切分，用完后归还池子 ④ 面试：池化 ByteBuf 相比非池化，性能提升在哪？|→ 数据库连接池（HikariCP 池化思想）/ Redis 内存管理|
|6.2|**PooledByteBufAllocator 内部结构**|🟡应掌握|① **Chunk**：分配的基本单位（16MB），内部用伙伴算法（Buddy Allocation）管理 ② **Page**：Chunk 内的分配单元（8KB）③ **SubPage**：小于 8KB 的分配，进一步细分 ④ 面试：Netty 内存池的 Chunk/Page/SubPage 分别是什么？|→ 操作系统内存管理（Buddy System 伙伴算法）|
|6.3|**ThreadLocal 缓存机制**|🟢了解|① 每个线程（EventLoop 线程）有自己的内存池缓存，减少竞争 ② `PoolThreadCache`：分配和回收都先走 ThreadLocal 缓存 ③ 这种设计与 ConcurrentHashMap 的 ThreadLocalRandom 优化思路类似 ④ 面试：Netty 内存池怎么减少多线程竞争？|→ Java ThreadLocal / JMH 并发性能测试|
|6.4|**直接内存溢出排查**|🟴必背（实战）|① 现象：`OutOfDirectMemoryError` 或堆外内存缓慢增长不释放 ② 原因：ByteBuf 没释放（忘了 `release()` 或异常路径没 `try-finally`）③ 排查：启用 `-Dio.netty.leakDetection.level=advanced` + 分析 GC 日志 + NMT（Native Memory Tracking）④ 面试：Netty 应用出现了直接内存泄漏，你怎么排查？|→ JVM 直接内存 / NMT 工具使用|
