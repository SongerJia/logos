### MVC 架构与组件（6 个）— Spring MVC 的骨架

|知识点|笔记时重点写什么|
|---|---|
|**DispatcherServlet 前端控制器**|热 整个 Spring MVC 的唯一入口，继承自 HttpServlet。`init()` 时初始化九大组件，`service()` → `doDispatch()` 处理请求。理解它是 Front Controller 模式的体现|
|**九大组件及其职责**|热 不需要背全部，但核心的 **5 个**必须熟：HandlerMapping（找 Handler）、HandlerAdapter（执行 Handler）、ViewResolver（解析视图）、HandlerExceptionResolver（处理异常）、MultipartResolver（文件上传）。其余了解即可|
|**doDispatch 完整流程**|热 `getHandler()` 查处理器映射 → `getHandlerAdapter()` 获取适配器 → `applyPreHandle()` 执行拦截器前置方法 → `ha.handle()` 执行 Controller → `applyPostHandle()` 拦截器后置方法 → `processDispatchResult()` 渲染视图 + afterCompletion。**这是面试最常要求画的流程图之一**|

> **笔记技巧**：画一张"请求从浏览器到返回"的全链路时序图，纵向分层：浏览器 → Tomcat/Servlet 容器 → Filter 链 → DispatcherServlet → Interceptor 链 → Controller → Service → DAO → 数据库，标注每层做了什么。

### 02 请求映射与参数绑定（9 个）— 日常开发最常用

|知识点|笔记时重点写什么|
|---|---|
|**@RequestMapping 注解详解**|热 6 大属性：value(路径)、method(GET/POST等)、params(请求参数条件)、headers(请求头条件)、consumes(Content-Type)、produces(Accept)。`consumes = "application/json"` 表示只接受 JSON 请求|
|**五大参数注解区别**|热 @PathVariable（URL 路径变量 `/user/{id}`）、@RequestParam（查询参数 `?name=xx`）、@RequestBody（请求体 JSON/XML）、@RequestHeader（请求头）、@CookieValue（Cookie）——做一个对比表：来源位置、是否必填、默认值、数据类型|
|**参数绑定原理**|热 WebDataBinder 是核心：String → 目标类型的转换过程。Converter 做通用类型转换（String→Date），Formatter 做本地化格式化（String→LocaleDate）。DataBinder 内部有 BindingResult 收集绑定错误|
|**HttpMessageConverter 体系**|核 **连接前后端的关键桥梁**。请求进来：`@RequestBody` 触发 readWithMessageConverters() 反序列化；响应出去：`@ResponseBody` 触发 writeWithMessageConverters() 序列化。内置转换器：MappingJackson2HttpMessageConverter（JSON）、StringHttpMessageConverter、ByteArrayHttpMessageConverter 等|
|**@Valid 参数校验**|JSR-303 Bean Validation 规范，Hibernate Validator 实现。校验失败后 BindingResult 接收错误信息，配合全局异常处理统一返回。常用注解：@NotNull / @NotBlank / @Size / @Pattern / @Email|

> **笔记提示**：参数注解那块建议做一张**速查卡片**，5 行 4 列：注解名、取值来源、典型用法示例、注意事项。面试前扫一遍就能回忆起来。

### 03 拦截器与过滤器（8 个）— 必考对比题

|知识点|笔记时重点写什么|
|---|---|
|**Filter vs Interceptor 区别**|热 **最高频对比题之一**。Filter 是 Servlet 规范级别的（在 DispatcherServlet 之前）；Interceptor 是 Spring MVC 的（在 DispatcherServlet 之后、Controller 之前）。Filter 能修改 request/response 对象，Interceptor 能获取 Handler 方法信息。Filter 由 Servlet 容器管理，Interceptor 由 Spring IOC 管理（可注入 Bean）|
|**HandlerInterceptor 三大方法**|热 preHandle（Controller 前，return false 则中断后续所有流程）、postHandle（Controller 后、视图渲染前，可修改 ModelAndView）、afterCompletion（视图渲染后 finally 式清理）。注意 postHandle 在 @ResponseBody 场景下不执行（因为直接写出响应了）|
|**preHandle 返回 false 后续流程**|热 当前拦截器的 preHandle 返回 false → **逆向执行已通过的所有拦截器的 afterCompletion** → 直接返回。不会执行后续拦截器的 preHandle/postHandle/afterCompletion，也不会执行 Controller|
|**完整执行链路**|核 `Tomcat → FilterChain.doFilter() → DispatcherServlet.doDispatch() → Interceptor1.preHandle() → Interceptor2.preHandle() → Controller.handle() → Interceptor2.postHandle() → Interceptor1.postHandle() → View.render() → Interceptor2.afterCompletion() → Interceptor1.afterCompletion()`|

> **笔记技巧**：多个拦截器的执行顺序是高频考点。建议画一个**横向时间线图**，两个拦截器 A 和 B，标注 preHandle(A)→preHandle(B)→Controller→postHandle(B)→postHandle(A)→afterCompletion(B)→afterCompletion(A)，以及 A.preHandle=false 时的短路情况。

### 04 返回值处理与视图解析（6 个）

|知识点|笔记时重点写什么|
|---|---|
|**Controller 返回值类型**|热 String（逻辑视图名，走 ViewResolver 解析）、ModelAndView（同时携带数据和视图名）、void（默认用 URL 作为逻辑视图名）、Object/@ResponseBody（直接序列化为 JSON 写出）。现在前后端分离项目基本只用最后一种|
|**@ResponseBody 与 @RestController 原理**|热 @ResponseBody 触发 HttpMessageConverter 将返回值序列化到 Response Body；@RestController = @Controller + @ResponseBody（类级别生效）。底层由 RequestResponseBodyMethodProcessor 处理|
|**视图解析器 ViewResolver**|InternalResourceViewResolver（JSP，拼接 prefix + viewName + suffix）、ThymeleafViewResolver（Thymeleaf 模板）、FreeMarkerViewResolver。前后端分离项目中这块权重降低，但面试仍可能问到原理|
|**转发 vs 重定向**|forward（服务器端跳转，URL不变，共享 request 域）vs redirect（客户端重定向 302，URL 变换，request 域丢失）。Spring 中 `"forward:/path"` 和 `"redirect:/path"` 前缀|

### 05 异常处理机制（6 个）— 工程实践重点

|知识点|笔记时重点写什么|
|---|---|
|**@ControllerAdvice + @ExceptionHandler**|热 全局异常处理的黄金组合。@ControllerAdvice 可以指定 basePackages / annotations / assignableTypes 来限定作用范围。@ExceptionHandler 标注具体处理的异常类型|
|**异常匹配优先级规则**|热 最精确匹配优先（子类 > 父类）、同一类异常按方法定义顺序。如果定义了 `@ExceptionHandler(Exception.class)` 和 `@ExceptionHandler(SQLException.class)`，SQL 异常会走后者|
|**统一返回结果封装 R<T>**|企业级项目的标准做法：code + message + data 三段式结构。在全局异常处理器中将各种异常统一转为 R.error(code, msg)，前端只需判断 code 是否为 success|

> **笔记技巧**：异常处理模块强烈建议直接写成**代码模板**形式——一个完整的 GlobalExceptionHandler 类骨架，包含常见异常的处理方式（参数校验异常、业务自定义异常、数据库异常、未知异常），这样笔记既是有结构的知识清单也是可以直接用的代码参考。

### 06 源码深度与扩展（7 个）— 拉开差距

|知识点|笔记时重点写什么|
|---|---|
|**doDispatch() 源码分析**|核 这是 Spring MVC 的心脏方法，约 80 行代码。核心 4 步：mappedHandler = getHandler(request) → HandlerAdapter ha = getHandlerAdapter(handler) → mv = ha.handle(processedRequest, response, mappedHandler.getHandler()) → processDispatchResult(processedRequest, response, mappedHandler, mv, exception)。每一步涉及的类要能说出来|
|**HandlerMapping 工作原理**|核 RequestMappingHandlerMapping 在容器启动时扫描所有 @RequestMapping 注解，生成一个 `Map<HandlerMethod, RequestMappingInfo>` 映射表。运行时根据 URL 匹配找到对应的 HandlerMethod（封装了 Controller 方法、参数、注解等信息）|
|**HandlerAdapter 工作原理**|核 为什么需要 HandlerAdapter？因为 Handler 可以是任意类型（Controller / HttpRequestHandler / Servlet / POJO），适配器模式让调用方无需关心具体类型。RequestMappingHandlerAdapter 通过反射调用 HandlerMethod 并完成参数绑定和返回值处理|
|**异步请求处理**|DeferredResult（超时/回调触发返回）、Callable（自动提交到 TaskExecutor 异步执行）、WebAsyncTask（带超时的 Callable）。适用于长耗时场景（如支付回调等待、第三方 API 调用）|

## Spring MVC 整体优先级

```
第一梯队（必考源码级）：
  01 doDispatch 流程  >  03 过滤器 vs 拦截器

第二梯队（高频问答+应用）：
  02 参数绑定  >  04 返回值/@RestController  >  05 全局异常处理

第三梯队（理解+扩展）：
  06 源码深度（大厂/高级岗才深挖）
```

**推荐笔记顺序**：`01 → 06 → 02 → 03 → 05 → 04`

理由：先建立 MVC 全景图和 doDispatch 流程(01+06)作为骨架，再学日常开发最常用的参数绑定(02)，然后是必考的过滤器/拦截器对比(03)，接着是工程必备的全局异常处理(05)，最后补充返回值和视图(04)。

## Spring Core 与 Spring MVC 的关键连接点

```
Spring Core                          Spring MVC
─────────                            ─────────
IOC 容器创建 Bean                    → DispatcherServlet 本身是一个 Bean
BeanPostProcessor                   → RequestMappingHandlerAdapter 用 BPP 初始化
AOP 动态代理                         → Controller 默认不被代理（CGLIB 可选）
@Transactional 事务                  → @Transactional 加在 Controller 上也能生效（但不推荐）
FactoryBean                         → ViewResolver 的实现类本质是工厂
事件机制 ApplicationEvent            → ServletContextInitializedEvent
```

这些交叉点是你在整理两份笔记时要刻意标注的地方——**不是两座孤岛，而是一张网的两个区域**。
