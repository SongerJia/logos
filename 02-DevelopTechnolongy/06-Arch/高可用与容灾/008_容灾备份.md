|#|知识点|核心内容|关键指标|面试追问|FlowPulse 规划|
|---|---|---|---|---|---|
|**4.8.1**|**RPO / RTO 指标**|**RPO**(Recovery Point Objective)：最多容忍丢失多少数据(时间维度)；**RTO**(Recovery Time Objective)：最多容忍多久不能服务|RPO≈0(金融) / RPO<5min(一般业务)；RTO<5min(关键) / RTO<30min(一般)|"你们系统的RPO和RTO目标分别是多少？"|**V1.0**: RPO<1h(每日冷备) / RTO<30min(手动恢复) → **V2.0**: RPO<5min / RTO<5min(异地热备)|
|**4.8.2**|**冷备 vs 温备 vs 热备**|冷备(定时备份/离线存储/恢复慢但便宜) → 温备( standby 系统运行但不接流量/恢复较快) → 热备( active-active 或 active-standby 实时同步/切换快)|成本：冷 << 温 < 热；恢复速度反之|"温备和热备的本质区别是什么？"|**V1.0 冷备**：MySQL mysqldump每日全量 + binlog增量 / **V2.0 温备**：异地Standby实时同步|
|**4.8.3**|**异地多活 Geo-Redundancy**|跨地域部署(如杭州+上海)；用户DNS就近接入；数据CDC双向同步；任一地域灾难不影响全局服务|成本极高(双倍基础设施+专线带宽+数据同步复杂性)；适合大规模业务|"异地多活最大的技术难点是什么？数据冲突怎么解决？"|**远期规划(V3.0)**：杭州主 + 上海备，用户就近接入，Canal CDC双向同步|
