### 1.4 mini 组件切片顺序（以 mini-Spring 举例，前 3 天）

- **Day 1**：clone spring-framework，跑 `spring-petclinic`，在 `SpringApplication.run()` 打断点，只看调用栈形状（见森林）。
- **Day 2**：只追一个问题——**"bean 到底存在哪？"**，找 `DefaultListableBeanFactory` / `BeanDefinition` / `getBean()`，追完一次链路，忽略其余 90%。
- **Day 3**：自己写 80 行 `MyContainer` 跑通即胜利。

**mini-Spring 80 行起步骨架（照着抄→改→写）：**

```java
// MyContainer.java —— IOC 容器核心（约 80 行，跑通即胜利）
public class MyContainer {
    private final Map<String, Class<?>> beanDefinitions = new HashMap<>();
    private final Map<String, Object> singletonObjects = new ConcurrentHashMap<>();

    /** 注册：把类登记进容器（对应 Spring 的 BeanDefinition 注册） */
    public void register(Class<?> clazz) {
        String name = lowerFirst(clazz.getSimpleName());
        beanDefinitions.put(name, clazz);
    }

    /** 获取：实例化并缓存单例（对应 getBean 主链路） */
    public Object getBean(String name) throws Exception {
        // 1) 已存在直接返回（单例缓存）
        if (singletonObjects.containsKey(name)) return singletonObjects.get(name);
        // 2) 取出类定义
        Class<?> clazz = beanDefinitions.get(name);
        if (clazz == null) throw new RuntimeException("No bean named " + name);
        // 3) 实例化（此处先简单 new，后续切片加依赖注入）
        Object instance = clazz.getDeclaredConstructor().newInstance();
        // 4) 缓存并返回
        singletonObjects.put(name, instance);
        return instance;
    }

    /** 第二周切片：@Autowired 依赖注入 —— 反射扫描字段，递归 getBean 填充 */
    private void autowire(Object bean) throws Exception {
        for (Field f : bean.getClass().getDeclaredFields()) {
            if (f.isAnnotationPresent(Autowired.class)) {
                f.setAccessible(true);
                f.set(bean, getBean(lowerFirst(f.getType().getSimpleName())));
            }
        }
    }

    /** 第三周切片：@PostConstruct 初始化回调 */
    private void invokeInit(Object bean) { /* 反射找 @PostConstruct 方法并执行 */ }

    private String lowerFirst(String s) { return s.substring(0,1).toLowerCase()+s.substring(1); }
}
```

之后每个切片都能独立跑通：第 2 周加 `@Autowired`，第 3 周加 `@PostConstruct`……

**mini-RPC 切片顺序**：① 同进程 JDK 动态代理 → ② 加 Socket 跨进程 + JSON 序列化 → ③ 加注册中心（Map 模拟）→ ④ 加负载均衡。
**mini-MQ 切片顺序**：① 进程内 `BlockingQueue` 收发 → ② 独立 broker + 持久化文件 → ③ 消费者组/重试。

### 1.5 抄→改→写三周法（治"看得懂但写不出"）
- **第 1 周·抄**：手敲（不是复制）源码里的核心类，逼自己注意"这字段为什么存在"。
- **第 2 周·改**：改一个行为（如把 `ConcurrentHashMap` 换成自己写的容器），理解耦合点。
- **第 3 周·写**：功能等价地从零写，**不看源码**；写不出 = 没真懂，回去看。

### 1.6 "吃透"的硬标准（自我检验）
1. **画得出**架构图与时序图（靠理解推，不靠记忆）。
2. **写得出**该维度的迷你核心实现（能跑通主链路）。
3. **讲得清**设计取舍：为什么用推不用拉？为什么 RocketMQ 用文件而不是 DB？

## 2. 模块 B：业务全貌 —— 三张图方法

### 2.1 从哪 4 个入口入手（别从代码入手！）
代码是业务的"倒影"，倒影永远比本体模糊。正确顺序：先吃透本体（业务），再看倒影（代码）。
1. **一条端到端用户旅程**（最优先）：把自己当用户走一遍。
2. **核心实体的状态机**（业务的脊椎）：每个核心实体都有生命周期。
3. **领域术语表**（统一语言）：90% 看不懂是词汇混乱。
4. **角色与权限**：谁在用？划出业务能力边界。

### 2.2 4 层模型 + 3 张必画图
- **4 层（由外到内）**：① 业务流程（泳道图）② 领域模型（ER/类图）③ 规则与状态机 ④ 数据模型（表结构）。
- **3 张图齐了全貌就出来**：流程图（泳道）、领域模型图（ER）、状态机图。

### 2.3 以 mall 电商为例（模板，可套任何业务）

**订单状态机（核心实体脊椎）：**
```
        [待支付]
       /        \
   取消          支付成功
     |             |
  [已取消]      [已支付/待发货]
                  |  (未发货也可取消→退款)
              发货 |
                  v
            [已发货/待收货]
              /          \
         收货确认      申请退款
            |             |
        [已完成]      [退款中] → [已退款]
```

**今日 5 步（通用）**：① 找 1 份 PRD/需求文档画泳道图 → ② 开库逆向核心 ER、标状态字段 → ③ 列核心实体状态 + 转换条件画状态机 → ④ 写 1 页术语表 → ⑤ 找人用你画的图"对图"校准。

## 3. 模块 C：银行资管（理财）业务

### 3.1 切口收窄
银行体系：负债（存款）/ 资产（贷款）/ 支付清算 / **资产管理（推荐入口：银行理财）**。
资管 = 银行理财 + 公募基金 + 信托 + 保险资管。**银行理财最贴合你说的"资金资管"且自成闭环。**

### 3.2 统一语言（先记词，雾散一半）

| 术语 | 人话定义 |
|---|---|
| 受人之托、代人理财 | 你出钱，机构替你投，赚亏都归你（打破刚兑） |
| 净值化 | 不再保本保收益，份额净值随底层波动（2024 净值化率 98.5%） |
| 摊余成本法 / 市值法 | 两种估值口径；监管已叫停"伪净值"，中债/中证估值成主流 |
| 破净 | 净值跌破 1；破净率 >5% 易触发集中赎回 |
| R1~R5 / C1~C5 | 产品风险等级 / 投资者承受能力，KYC 适当性匹配 |
| T 日 / T+1 | 交易确认与资金交收时点 |
| 托管行 | 保管资产、监督投向、核算净值的独立第三方 |
| 业绩比较基准 | **不是预期收益率**，须挂钩指数/策略并说明测算 |

### 3.3 资管产品全生命周期（泳道）

```
[监管/发起]    [理财公司]      [托管行]        [投资者/代销]
    |             |              |               |
 报备/注册 ──→ 产品设计 ──→ 签订托管协议 ──→ 风险测评(KYC)
    |             |              |               |
    |         募集期(申购)──────────────────────→ 买入
    |             |              |               |
    |         运作期(投资)──→ 估值/核算 ──→ 净值披露
    |             |              |               |
    |         开放期(赎回)←───────────────────── 赎回
    |             |              |               |
    |         终止/清盘 ──→ 清算报告 ──→ 收益分配
```

生命周期三阶段（对应 2025《资管信披办法》10 号令）：**募集期（看得清）→ 存续期（厘得清）→ 终止期（算得清）**，2026-09-01 施行。

### 3.4 两个核心状态机
**产品状态机：**
```
[筹备/报备] → [募集期] → [存续运作期] → [终止清算] → [产品终止]
                ↑ 未募满可延长        │
                └────────────────────┘(到期/提前终止)
```
**申赎订单状态机：**
```
[待确认(T)] → [已确认(T+1)] → [份额可用]
                                  │
        [赎回申请] ──→ [赎回在途] ──→ [资金到账]
                                  │
        [巨额赎回] ──→ [部分确认/延期支付]
```
> **真实踩坑**：巨额赎回（赎回申请超前一日总份额 10%）可启动"延期支付"，直接决定订单状态机和清算分支怎么写。

### 3.5 4 层模型套用资管
业务流程（上图）/ 领域模型（产品、份额、投资人、托管行、投资组合、底层资产、净值、费用）/ 规则与状态机（KYC、估值方法选择）/ 数据模型（`product / share / order / nav / position`）。

### 3.6 举一反三（监管维度，和电商最大不同）
- 强监管塑形：每条业务线都有"上位法"，法就是需求源头。
- 适当性（KYC）是不可绕过的模块，电商没有这硬约束。
- 资金安全 > 体验：托管隔离、对账、清算优先级永远最高。
- 反直觉：银行最难的是**对账、清算、计息、估值、幂等、冲正**，比业务功能难十倍。

## 4. 模块 D：银行资金业务（货币市场 + 央行工具）

### 4.1 总览图（所有工具的内核）
本质都是"钱/券在谁手里、以什么担保、什么期限、什么价格"的管道：

```
                资金盈余方 ──┐
                (大行/货基)   │
                            ├─→ [回购] ← 最大量日常融资(以债换钱,有质押)
                            ├─→ [拆借] ← 纯信用头寸调剂(无抵押)
                            ├─→ [同业存款/同业存单] ← 主动负债/存放
                            └─→ [债券借贷] ← 借券不借钱(融券)
                资金缺口方 ──┘

        [央行] ──(再贷款/MLF/SLF/PSL/OMO逆回购)──→ 商业银行  ← 最后贷款人/基础货币投放
        [债券] ← 既是回购/借贷的标的，也是现券与央行操作的对象
        [即期/远期/掉期] ← 管汇率/利率风险的衍生品(跨期交换)
```

### 4.2 逐个拆（参与者 / 怎么流转 / 干嘛用 / 细节）

**① 同业拆借**：金融机构间**纯信用、无抵押**短期借钱，调隔夜/7 天头寸。利率锚 SHIBOR。超支触发监管罚则；钱荒时利率飙升。
```
[头寸缺口] → 拆入方报价 → 拆借成交(T) → 资金交割(T+0/T+1) → 到期还本付息(最长≤1年,隔夜为主)
```

**② 同业存借**：`同业存款`（线下存款合同）、`同业存单 NCD`（可转让定期存款凭证，主动负债核心，上清所托管）、`同业借款`（有合同可约期）。直接关系 **LCR（流动性覆盖率）/ NSFR（净稳定资金比率）**——ALM 命脉。

**③ 央行再贷款 & 货币政策工具**（最后贷款人 / 基础货币投放）：

| 工具 | 期限 | 用途 |
|---|---|---|
| OMO 逆回购 | 7/14天 | 日常公开市场吞吐流动性（最常用） |
| SLF 常备借贷便利 | 1-3月 | 央行给银行的"雨天备用伞"，利率是上限 |
| MLF 中期借贷便利 | 3-12月 | 中期基础货币投放，利率是政策利率中枢 |
| PSL 抵押补充贷款 | 3-5年 | 定向（棚改、基建）长期资金 |
| 再贷款/再贴现 | 不定 | 结构性定向支持 |

**④ 债券工具**：`现券买卖`（配置/交易盘核心）；`央行债券操作`（正/逆回购、现券买卖、央票；2024 起央行公开市场买卖国债强化利率传导）。债券是回购和借贷的底层标的。

**⑤ 回购（货币市场绝对主角）**：`质押式`（融入方质押债券，占银行间本本币交易量 80%+，利率 R007/DR007）、`买断式`（所有权转移）。托管在中债登/上清所，交割用 **DVP 券款对付**。
```
[首期结算] 融出方付钱 ←→ 融入方交券(质押/DVP)
   ↓ 持有期间
[到期结算] 融入方付本息 ←→ 融出方解押还券  （质押券跌价要追保/margin call）
```

**⑥ 债券借贷**：借**券**不是借钱，约期还同种同量券并付费。用途：卖空、套期、做市补券、套利。与回购方向相反、互补。

**⑦ 即期 / 远期 / 掉期**：`即期`（T+2 交割）、`远期`（锁定未来汇率/利率）、`掉期`（两笔反向不同期交易，如即期买美元+远期卖美元，套息/管错配）。属**风险管理维度**，和 ①~⑥ 的"融资/流动性"不同维。

### 4.3 统一框架：在银行账上怎么摆

| 工具 | 银行视角 | 业务属性 |
|---|---|---|
| 拆借/回购/同业存款 | 资产or负债（拆出/拆入） | 短期流动性调剂 |
| 同业存单/再贷款/MLF | 负债（主动/央行） | 负债管理 |
| 债券现券 | 资产 | 资产配置 |
| 债券借贷 | 表外/融券 | 做市与套利 |
| 即远掉 | 衍生品头寸 | 汇率/利率风险管理 |

串起一切的是 **ALM（资产负债管理）**：期限错配、流动性指标(LCR/NSFR)、利率风险——这些工具就是 ALM 调节"久期"和"头寸"的旋钮。

**系统实现真实踩坑**：① 回购 **DVP 结算失败**违约；② 债券借贷**到期还券违约**（借的券卖出后跌了/没了）；③ 计息基准混淆 **ACT/360 vs ACT/365**（银行间多用 ACT/360，差一点全年利息对不上）；④ 节假日/营业日惯例（T+1 遇节假日顺延）算错交割日。

## 5. 模块 E：表内 / 表外 与资本约束

### 5.1 一句话
**"表"= 资产负债表。** 表外 = 不直接写进资产负债表、不体现为资产或负债，但可能产生"或有风险"或只是做中介服务。

### 5.2 表长啥样（复习）
```
              资产负债表（银行）
   资产（钱变成了什么）      负债+权益（钱是谁的）
   · 现金/准备金            · 存款
   · 贷款                  · 同业拆入 / 回购负债
   · 债券持仓              · 央行借款 / MLF
   · 同业拆出              · 同业存单(NCD)
   · 固定资产              · 所有者权益
   恒等式：资产 = 负债 + 所有者权益
   表内 = 直接动上面几块（动规模、动资本）
   表外 = 不进上面，但可能变"或有负债"或只是代理
```

### 5.3 表内 vs 表外 对照

| | 表内 | 表外 |
|---|---|---|
| 是否进资产负债表 | 是 | 否（记备忘科目或干脆不入） |
| 是否占用资本 | 是（RWA→资本充足率） | 多数不占/少占，或按 CCF 折算后占 |
| 是否动规模 | 动 | 不动表内规模 |
| 典型例子 | 存款、贷款、拆借、回购、债券持仓、NCD、央行借款 | 承兑汇票、信用证、保函、贷款承诺、衍生品、**债券借贷**、代客理财/托管 |

### 5.4 为什么银行和你都要 care
1. **资本约束**：表内每笔资产算 RWA 吃掉资本充足率；表外是轻资本扩张通道。
2. **隐性风险显性化**：承兑汇票（表外）企业违约 → 银行垫付 → 变表内不良。
3. **监管套利高发地**：旧时代信托/理财挪表外绕约束（"影子银行"）；**资管新规核心之一就是把这股风堵死**。

### 5.5 回扣前面的工具映射
- **回购（质押式）**：表内。融入方记"卖出回购金融资产款"（负债），债券仍挂自己账（资产）只是被质押。
- **债券借贷**：表外。借券不买卖，不终止确认、不形成资产负债，资本占用极低。
- **即远掉**：表外。衍生品不进资产负债，按公允价值计量，损益进利润表（"表外但损益入表"）。
- **理财子公司产品**：真正独立表外（钱不进银行表，只收管理费），与旧时代资金池本质不同。

**系统建模踩坑**：① 承兑汇票垫款：状态机须有"显性化"分支自动转表内不良并计提；② CCF 折算错（贷款承诺常 20%~50%）→ 资本充足率算错 → 监管报送翻车；③ 反直觉：表外"看不见"但风险不一定小（2008 CDO/SIV 全是表外变表内）。

## 8. 举一反三 & 真实踩坑汇总（面试弹药库）

- **技术反直觉**："大而全"业务项目看 1~2 个就够（骨架同质）；真正拉差距的是中间件源码深度。
- **业务反直觉**：银行最难的是对账/清算/计息/估值/幂等/冲正，不是 CRUD。
- **金融踩坑集**：回购 DVP 失败、债券借贷还券违约、ACT/360 计息错、T+1 节假日顺延错、承兑汇票显性化缺失、CCF 折算错、巨额赎回延期支付分支。
- **监管维度**：学银行任何一条线先学它的"法"——资管=资管新规+理财公司办法+信披10号令；支付=支付机构条例；信贷=商业银行法。法=需求源头。
