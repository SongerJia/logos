| 5.1 | **Dubbo vs Spring Cloud Feign** | 🟡 应掌握 | ① Dubbo：RPC 框架（基于 Netty + 序列化），长连接高性能；Spring Cloud Feign：声明式 HTTP 客户端，基于 REST ② Dubbo 3.0 兼容 Spring Cloud 生态（Dubbo Spring Cloud）③ 面试：Dubbo 和 Feign/Ribbon 怎么选？（内部微服务间高性能 RPC 用 Dubbo，对外/跨语言用 REST）                                                                                      | ↔️ gRPC（下一条）                            |
| 5.2 | **gRPC & Protocol Buffers**     | 🟡 应掌握 | ① Google 出品：基于 HTTP/2 + Protobuf 序列化的高性能 RPC 框架 ② 四种通信模式：一元（Unary）/ 服务端流 / 客户端流 / 双向流 ③ vs REST：二进制传输体积小 + 多路复用 + 强类型 IDL 定义接口 ④ 面试：gRPC 和 RESTful 各自适用场景？                                                                                                                              | ↔️ Dubbo / ↔️ Feign                     |
| 5.3 | **JWT / OAuth2 / SSO 认证体系**     | 🟡 应掌握 | ① **JWT**：JSON Web Token（Header.Payload.Signature），无状态认证，自包含用户信息 ② **OAuth2**：授权框架（四种模式：授权码/密码/客户端/隐式），Spring Security OAuth2 已废弃改用 Spring Authorization Server ③ **SSO**：单点登录（CAS / OAuth2 + JWT），一处登录处处访问 ④ 面试：JWT 和 Session-Cookie 方案的区别？JWT 安全隐患怎么缓解？（短有效期 + Refresh Token + HTTPS） | ↔️ Spring Security                      |
| 5.4 | **Caffeine 本地缓存**               | 🟡 应掌握 | ① Caffeine：Spring Boot 2.x 默认缓存替换 Guava Cache，基于 W-TinyLFU 淘汰算法 ② vs Redis：本地缓存（毫秒级但不共享）vs 分布式缓存（网络开销但全局一致）③ 两级缓存架构：L1(Caffeine) → L2(Redis)，热点数据走本地 ④ 面试：项目中用了 Caffeine 吗？和 Redis 怎么配合？                                                                                                | ↔️ Redis 缓存、↔️ Guava Cache              |
| 5.5 | **Service Mesh（Istio/Envoy）概念** | 🟢 了解  | ① Sidecar 模式：每个服务旁部署代理（Envoy），负责服务发现/负载均衡/熔断/限流/追踪/鉴权 ② 价值：将基础设施能力从业务代码中解耦出来 ③ 现状：国内大规模使用的还不多，但面试体现前瞻性 ④ 面试：你了解 Service Mesh 吗？和 Spring Cloud Gateway 有什么关系？                                                                                                                            | ↔️ Spring Cloud Gateway / ↔️ SkyWalking |
| 5.6 | **ChaosBlade & 混沌工程入门**         | 🟢 了解  | ① 混沌工程：主动制造故障验证系统韧性（Netflix Chaos Monkey 开创）② ChaosBlade：阿里巴巴开源混沌工程工具，支持 JVM / 网络 / 磁盘等多层次故障注入 ③ 常见实验场景：CPU 满载 / 网络延迟 / 进程杀死 / 磁盘满 ④ 面试：你们有做故障演练吗？（答"了解过混沌工程理念"已经加分）                                                                                                                    | ↔️ 高可用容灾（架构方向 M4）                       |
