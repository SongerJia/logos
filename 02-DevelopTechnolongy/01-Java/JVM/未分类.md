### 01 JVM 内存结构（11 个）— 整张 JVM 知识网的骨架

这是所有后续知识的地基，必须先画清楚全貌：

|知识点|笔记时重点写什么|
|---|---|
|**运行时数据区总览**|画一张大图：线程隔离的（PC/栈/本地方法栈）vs 线程共享的（堆/方法区），标清每个区域存什么、大小可调吗|
|**虚拟机栈 & 栈帧结构**|热 栈帧四部分：局部变量表（Slot 概念）、操作数栈（基于栈的解释器）、动态链接、返回地址。StackOverflowError vs OOM 各在什么条件下触发？|
|**堆 Heap 分代模型**|核 新生代（Eden : S0 : S1 = 8:1:1）→ 老年代 → 元空间。JDK8 之后永久代移到本地内存变成 Metaspace，这个变化是必考点|
|**方法区 / 元空间**|存什么？（类信息 / 常量池 / 静态变量 / JIT 编译后的代码）。为什么 JDK8 要从堆移出去？（避免 Full GC 扫描类信息 + 大小不受 -Xmx 限制）|
|**字符串常量池位置变迁**|JDK6 在永久代 → JDK7 移到堆 → JDK8 在堆中独立区域。`new String("abc")` 创建了几个对象？`intern()` 在不同版本的行为差异|

> **笔记技巧**：这一整块就是一张"JVM 运行时数据区全景图"，建议作为你 JVM 笔记的第一页。这张图能覆盖至少 5 道面试基础题。

### 02 垃圾回收 GC（13 个）— JVM 最重的模块

GC 是面试中 JVM 板块的绝对核心：

|知识点|笔记时重点写什么|
|---|---|
|**判断对象存活**|引用计数法（循环引用问题）vs 可达性分析（GC Roots 作为起点）。GC Roots 有哪几类？——静态变量、常量、栈中引用、JNI 引用|
|**四种引用类型**|强引用（不回收）→ 软引用（内存不够才回收，适合缓存）→ 弱引用（下次 GC 必收，WeakHashMap 底层）→ 虚引用（无法获取对象，用于跟踪回收）。每种给一个实际场景|
|**三种垃圾收集算法**|标记-清除（碎片）、复制（浪费一半空间但无碎片）、标记-整理（移动对象开销大但紧凑）。各自优缺点和适用分代|
|**分代收集理论**|**弱分代假说**：大多数对象朝生夕灭。Minor GC 频繁但快，Major GC 少但慢。对象年龄怎么晋升？动态年龄判定（Survivor 中相同年龄对象总和 > Survivor 一半）|
|**Minor / Major / Full GC 区别**|热 触发条件各是什么？Full GC 触发的 5 种场景（System.gc() / 老年代空间不足 / 方法区不足 / CMS GC 时 promotion failed / 统计得到的 Minor GC 晋升平均大小 > 老年代剩余）|
|**Serial / Parallel / CMS / G1 / ZGC 对比**|热 做一张对比表：线程数、STW 时间、适用场景、是否支持并发标记、JDK 默认版本变化|

> **笔记技巧**：GC 算法的对比建议做成一张表格，列包含：算法名称、是否移动对象、是否有碎片、适用分代、时间复杂度。这张表面试前反复看三遍就够。

### 03 类加载机制（9 个）— 中等频率

|知识点|笔记时重点写什么|
|---|---|
|**类加载五步过程**|加载（二进制流→方法区→堆中Class对象）→ 验证（文件格式/字节码/符号引用）→ 准备（static 变量赋零值！注意不是初始值）→ 解析（符号引用→直接引用）→ 初始化（clinit() 执行 static 赋值和静态块）|
|**双亲委派模型**|热 AppClassLoader → ExtClassLoader → BootstrapClassLoader。为什么要这样设计？（安全性：防止自定义 java.lang.String）。loadClass 源码流程|
|**打破双亲委派**|SPI（DriverManager 用 ContextClassLoader 加载实现类）/ Tomcat（WebAppClassLoader 优先加载自己目录下的类）/ OSGi（网状委托）|
|**准备阶段 vs 初始化阶段赋值差异**|`public static int value = 123;` —— 准备阶段 value=0，初始化阶段才变为 123。但 `public final static int value = 123;` —— 准备阶段直接就是 123（ConstantValue 属性）|

### 04 字节码与执行引擎（8 个）— 理解型为主

这块偏底层，面试问得相对少但能拉开差距：

|知识点|笔记时重点写什么|
|---|---|
|**解释执行 vs JIT 编译**|核 解释器逐条执行字节码；JIT 把热点方法编译成本地机器码。C1（Client 编译器，简单优化+快速编译）vs C2（Server 编译器，深度优化）。分层编译：解释 → C1 → C2|
|**热点代码探测**|方法调用计数器（默认 1500 次）+ 回边计数器（循环体）。计数器衰减机制（半衰期冷却）|
|**编译优化技术**|内联（消除方法调用开销）→ 逃逸分析（对象没逃出方法就不分配在堆上）→ 标量替换（对象拆成基本类型变量）→ 锁消除（同步块内对象不逃逸则去掉 synchronized）。**这些优化是理解"为什么 Java 可以这么快"的关键**|

> **笔记提示**：如果你时间有限，04 和 08 这两个模块可以优先级放低，先把 01~03、05、06、07 写扎实。字节码这块在理解锁消除、逃逸分析时会回过头来补上。

### 05 JVM 调优与故障排查（10 个）— 工程价值最高

这块是你真正在生产环境用得上的，也是面试官最喜欢问实战经验的：

|知识点|笔记时重点写什么|
|---|---|
|**常用 JVM 启动参数**|热 `-Xms/-Xmx`（堆初值最大值要相等避免扩容抖动）、`-Xmn`（新生代大小）、`-Xss`（栈深度，默认 1MB）、`-XX:MaxMetaspaceSize`、`-XX:+HeapDumpOnOutOfMemoryError`、`-XX:SurvivorRatio`。整理成速查表|
|**OOM 各场景排查**|热 堆 OOM（对象太多 / 内存泄漏）、Metaspace OOM（动态代理/CGLIB 生成大量类）、StackOverflowError（递归太深）、DirectMemory OOM（Netty/ByteBuffer 未释放）。**每种给一个错误日志截图模板**|
|**jps/jstack/jmap/jstat/jinfo 命令**|热 jps（看进程列表）、jstack（看线程状态/死锁）、jmap（dump 堆/histogram）、jstat（看 GC 频率/S0S1 晋升率）、jinfo（运行时修改参数）。每个命令给一个最常用的用法示例|
|**CPU 飙高排查思路**|热 top 找高 CPU 进程 → top -Hp 找高 CPU 线程 → jstack 看 16 进制 nid 对应的线程栈 → 定位到代码行。**写成固定排查脚本步骤**|
|**VisualVM / MAT 工具使用**|热 MAT 的 Dominator Tree 找大对象 → Retained Heap vs Shallow Heap 区别 → GC Root 分析链路 → OQL 查询语法|
|**生产环境参数最佳实践**|4G/8G/16G/32G 机器各给一套推荐参数模板，标注每行为什么这么设。比如 8G 机器典型配置：`-Xms6g -Xmx6g -Xmn2g -XX:MetaspaceSize=256m -XX:+UseG1GC`|

> **笔记技巧**：调优这块强烈建议按**"问题 → 排查步骤 → 解决方案"**的结构来写，而不是罗列知识点。比如单独开一篇 "OOM 排查手册"和一篇 "CPU 飙高排查手册"，这种笔记你在跳槽前翻两遍就能应对大部分现场面试题。

### 06 内存模型与对象创建（7 个）

|知识点|笔记时重点写什么|
|---|---|
|**对象创建全过程**|new 指令 → 类加载检查 → 分配内存（指针碰撞/空闲列表）→ 初始化零值 → 设置对象头 → 执行 init 方法|
|**指针碰撞 vs 空闲列表**|堆内存规整用指针碰撞（Compact 整理后），不规整用空闲列表（有碎片时）。HotSpot 用哪种？取决于 GC 是否有压缩整理能力|
|**TLAB 本地线程分配缓冲**|核 多线程在 Eden 分配对象时竞争同一个指针怎么办？每个线程预分配一小块 TLAB，减少 CAS 竞争。默认占 Eden 的 1%|
|**对象头 Mark Word**|64 位 JVM 下 Mark Word 结构：25bit hashcode + 4bit 分代年龄 + 1bit偏向锁标志 + 2bit 锁状态位 + ...。**这和并发篇的锁升级直接关联**|

> **连接点提醒**：Mark Word 结构在并发篇（synchronized 锁升级）和 JVM 篇（对象内存布局）都会出现，建议只在一个地方详细写，另一处用链接引用。重复写容易不一致。

### 07 垃圾收集器详解（8 个）— GC 的落地实现

|知识点|笔记时重点写什么|
|---|---|
|**CMS 收集器**|核 四个阶段：初始标记（STW 短）→ 并发标记（与用户线程并行）→ 重新标记（STW 修正）→ 并发清除。三个致命缺陷：浮动垃圾、Concurrent Mode Failure（晋升失败退化 Serial Old）、内存碎片|
|**G1 收集器**|核 **当前默认首选**。Region 化布局（不再物理分代）、RSet 记住跨 Region 引用、SATB 写屏障处理并发标记、Young GC + Mixed GC 两步走。可预测停顿时间（`-XX:MaxGCPauseMillis`）|
|**ZGC**|染色指针（指针高位存储颜色标记）、读屏障（Load Barrier）、几乎不停顿（停顿 < 1ms）。适用超大内存（>100G）低延迟场景|
|**收集器选择策略**|小内存/客户端 → Serial；吞吐量优先 → Parallel；低延迟要求 → G1；超大内存超低延迟 → ZGC。JDK9 默认 G1，JDK21 可能转向 ZGC|

> **笔记技巧**：CMS vs G1 的对比是高频题，建议做一张详细的对比卡片：STW 次数、是否分代、是否碎片化、内存占用、适用堆大小范围。

### 08 高级专题（6 个）— 加分项

| 知识点                     | 说明                                                                                                  |
| ----------------------- | --------------------------------------------------------------------------------------------------- |
| **安全点 SafePoint**       | 热 GC 时所有线程必须到达的安全位置。哪些指令会生成安全点？（方法调用/循环跳转/异常跳转）。安全区 SafeRegion（native 代码中线程已经在安全区不需要等待）             |
