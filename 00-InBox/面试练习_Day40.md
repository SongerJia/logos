## 话题二：并发工具类实战（10分钟）

**面试官：Java 并发包里除了锁和线程池，还有几个工具类你用过吗？CountDownLatch、CyclicBarrier、Semaphore 你了解吗？**

→ 你回答...

**追问1：** CountDownLatch 和 CyclicBarrier 有什么区别？看起来都是等一组线程完成，它们能互换吗？

→ 你回答...（提示：CountDownLatch 一次性用完即弃 / CyclicBarrier 可重置重用 / CountDownLatch 是一个线程等多个 / CyclicBarrier 是多个线程互相等待 / 内部实现不同 AQS vs Condition）

**追问2：** 你在项目里有没有实际用过 CountDownLatch？什么场景？

→ 你回答...（提示：多线程并行查询汇总 / 服务启动时等待依赖组件初始化 / 批量任务等所有子任务完成 / 不能复用）

**追问3：** 如果你要实现"3个线程都准备好后同时开始执行"，用 CountDownLatch 行不行？为什么 CyclicBarrier 更合适？

→ 你回答...（提示：CountDownLatch 是"等其他人做完我继续" / CyclicBarrier 是"大家都到了才走" / 同时开始 = 互相等待 → CyclicBarrier 的 barrier action 回调）

**追问4：** Semaphore 是干什么用的？和你们用的 Sentinel 限流有什么关系？

→ 你回答...（提示：Semaphore = 许可证 / acquire 获取 release 释放 / 限流本质就是控制并发数 / Semaphore 是单机版 / Sentinel 是分布式限流 + 熔断 + 降级更全面 / 但底层思想类似）

**追问5：** Semaphore 的 `fair` 参数是什么意思？公平和非公平有什么区别？底层用的什么机制？

→ 你回答...（提示：fair=true 排队 FIFO / fair=false 允许插队吞吐量高 / 底层都是 AQS 共享模式 / 公平锁 hasQueuedPredecessors 判断队列是否有前驱节点）

> 💡 **今日重点提示**：
> 1. **Java 序列化机制**第一次系统考察。核心对比：Java 原生序列化（不安全不推荐）→ JSON（可读性好但体积大）→ Protobuf（紧凑高效但需 IDL）→ Hessian（Dubbo 默认）。`serialVersionUID` 必须显式声明，否则改一个字段就反序列化失败。`transient` + `writeObject/readObject` 自定义序列化是加分项
> 2. **并发工具类**是 Day39 ThreadLocal 的延伸。CountDownLatch vs CyclicBarrier 的区别是高频考点：一次性 vs 可复用、一个等多个 vs 多个互相等待。Semaphore 和 Sentinel 限流的关系能把新知识和已有知识串联起来。AQS 共享模式是底层，在 Day5/Day16 提过 AQS，今天从工具类角度再看
> 3. **LRU 缓存**是手写题的经典，比前面的链表/排序题综合性更强——考的是**数据结构组合能力**（HashMap + 双向链表）。面试官想看你能不能把两个基础数据结构拼出 O(1) 的复合结构。线程安全追问是区分点：从全局锁到读写锁到分段锁，体现你对并发的理解深度。LinkedHashMap 的 accessOrder + removeEldestEntry 是现成方案但要知道它的局限
> 4. **MySQL 主从复制**在 Day5/Day16/Day36 提过索引和死锁，今天从复制架构角度切入。binlog 三种格式（Statement/Row/Mixed）是核心——金融系统推荐 Row 格式保证数据准确性。半同步复制解决的是"主库写入后从库还没同步主库就挂了"的数据丢失问题，代价是降低写性能。读写分离后主从延迟导致读旧数据是高频追问，四个方案都要能说出
