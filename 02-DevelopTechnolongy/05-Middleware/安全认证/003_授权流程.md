### 为什么这个模块

**认证回答"你是谁"，授权回答"你能做什么"。** 后端工程师必须能聊清楚 RBAC 模型和方法级权限控制。

### 知识点表

|序号|知识点|重要度|笔记三层建议|跨模块关联|
|---|---|---|---|---|
|3.1|**RBAC 权限模型（用户-角色-权限）**|🔴必背|① 三层模型：User → Role → Permission（多对多关系）② 扩展：RBAC + 组织部门 + 数据权限（行级权限）③ 实现方案：五张表（user / role / permission / user_role / role_permission）④ 面试：设计一个 RBAC 的数据库表结构？如果要做数据权限（如只能看自己部门的订单）怎么扩展？|→ MySQL 多表关联 / ShardingSphere 分库分表|
|3.2|**基于 URL 的权限配置**|🟡应掌握|① `.requestMatchers("/admin/**").hasRole("ADMIN")` ② `.requestMatchers("/api/user/**").hasAnyRole("USER","ADMIN")` ③ `.anyRequest().authenticated()` ④ 面试：怎么配置不同 URL 的访问权限？|→ Spring Cloud Gateway 路由鉴权（网关层拦截）|
|3.3|**方法级权限注解 @PreAuthorize**|🔴必背|① `@PreAuthorize("hasRole('ADMIN')")` ② `@PreAuthorize("@permissionService.hasPermission('order:create')")` — 自定义 SpEL 表达式调用业务方法 ③ 开启：`@EnableGlobalMethodSecurity(prePostEnabled = true)`（旧版）/ `@EnableMethodSecurity`（新版 Spring Security 6.x）④ 面试：@Secured / @RolesAllowed / @PreAuthorize 有什么区别？|→ Spring AOP（注解底层原理）/ SpEL 表达式|
|3.4|**自定义 AccessDecisionVoter & PermissionEvaluator**|🟡应掌握|① 自定义 Voter：实现 AccessDecisionVoter 接口，编写自己的投票逻辑（如动态权限）② PermissionEvaluator：配合 SpEL 使用 `@PreAuthorize("hasPermission('order','read')")` ③ 面试：如何实现动态菜单/按钮权限（从数据库加载权限规则）？|→ AOP 动态代理 / 数据库权限表设计|
|3.5|**异常处理：401/403/AccessDeniedHandler**|🟡应掌握|① AuthenticationEntryPoint：未认证时触发（401）→ 重定向到登录页或返回 JSON ② AccessDeniedHandler：无权限时触发（403）→ 返回友好错误信息 ③ 自定义处理：实现这两个接口并注册到 HttpSecurity ④ 面试：Security 的 401 和 403 分别在什么时候抛出？怎么自定义处理？|→ Spring MVC 异常处理器（@ControllerAdvice）|

> **🏗️ 架构追问**：如果让你设计一套"微服务统一认证中心"，你会怎么做？提示：认证集中到 Auth Service → 其他服务通过 Gateway 鉴权 → Token 透传。
