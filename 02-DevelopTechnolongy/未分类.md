#  中间件方向 — 全景规划

## 先说清楚：什么是"中间件"

```
你的代码(业务逻辑)
    ↓ 调用
┌─────────────────────────────────────┐
│            中间件层                    │
│                                     │
│  "不直接产生业务价值，但没有它业务跑不起来" │
│  "你写的Service是砖，中间件是水泥和钢筋"   │
│                                     │
│  特征：通用性 / 解耦 / 基础设施性质      │
└─────────────────────────────────────┘
    ↓ 依赖
操作系统 / 网络 / 硬件
```

## 🎯 推荐的中间件知识体系结构

综合以上，我建议把中间件整理成 **6个独立模块**：

|#|模块|包含内容|知识点预估|必要性|
|---|---|---|---|---|
|**M1**|**消息队列三件套**|RocketMQ + Kafka + RabbitMQ + 选型对比|~130|🔴 必须|
|**M2**|**分布式任务调度**|XXL-JOB 为主 + PowerJob/Elastic-Job对比|~25|🔴 必须|
|**M3**|**分布式链路追踪**|SkyWalking 核心原理 + Zipkin/Jaeger对比|~20|🔴 必须|
|**M4**|**Seata 分布式事务深入**|AT/TCC/SAGA/XA 四种模式完整拆解|~30|🟡 强烈推荐|
|**M5**|**Nginx**|反向代理/负载均衡/缓存/限流原理与实践|~20|🟡 强烈推荐|
|**M6**|**其他常用中间件扫盲**|Canal/OSS-MinIO/Prometheus+Grafana/ZooKeeper 各一个模块|~35|🟡 按需学习|

**合计：~260 个知识点**

> 其中 M1~~M3 是**必须详细展开**的核心模块，M4~~M5 是强烈推荐的进阶模块，M6 可以每个技术只写"核心原理+使用场景+与其他方案的对比"三层笔记就够。

### P0 强烈建议新增（3 个）— 🔴 不补会有明显短板

#### N1 网络编程：Netty 深入 (~40 点)

|维度|分析|
|---|---|
|**为什么必须**|杭州大厂后端面试 **Top 5 必考**。RocketMQ/Elasticsearch/RPC/网关 全是 Netty 写的。不懂 Netty = 只会"用"中间件，不会"懂"中间件|
|**和现有知识的关系**|Java NIO 的直接延伸 → Reactor 模型贯穿所有异步框架 → 零拷贝/ByteBuf 对标 JVM 内存管理|
|**核心模块规划**|架构&Reactor模型(6) / ByteBuf&零拷贝(6) / 编解码&粘包拆包(6) / Pipeline&Handler链(7) / WebSocket实战(4) / 与Tomcat对比(4) / 性能调优(7)|
|**一句话定位**|从"会用 Nginx 做代理"升级到"理解所有中间件的通信底层"|

#### N2 安全认证：Spring Security + 认证授权体系 (~25 点)

|维度|分析|
|---|---|
|**为什么必须**|后端工程师**不能说"安全不是我的事"**。JWT/OAuth2 几乎每个项目都用，Spring Security 是事实标准|
|**和现有知识的关系**|S5 扫盲只提了一行 JWT/OAuth2，远远不够；与 Spring Cloud Gateway（鉴权过滤器）直接关联|
|**核心模块规划**|Spring Security架构(5) / 认证流程FilterChain(5) / JWT无状态认证(4) / OAuth2授权码流程(3) / 密码加密&安全实践(4) / SSO单点登录(4)|
|**一句话定位**|从"知道 JWT 三个部分叫什么"到"能独立设计一套认证授权方案"|

#### N3 RPC 服务调用：Dubbo 深入 (~30 点)

|维度|分析|
|---|---|
|**为什么必须（尤其阿里系）**|Dubbo 是阿里开源招牌产品，Dubbo 3.0 支持 Spring Cloud 生态融合。杭州大厂（阿里/蚂蚁/字节/网易）**Dubbo 问的概率极高**|
|**和现有知识的关系**|与 Feign/Ribbon 对标学习 → SPI 机制对标 Java SPI / Spring Factories → 服务治理概念复用 Nacos|
|**核心模块规划**|整体架构&SPI(5) / 远程调用&代理(5) / 集群容错&路由(6) / 序列化&通信协议(5) / Dubbo 3.0新特性(4) / 与Spring Cloud整合(5)|
|**一句话定位**|从"只会 Feign 调接口"到"能聊透 RPC 框架设计原理"|

> **P0 合计：~95 个知识点，高性价比**

### P1 建议考虑（3 个）— 🟡 有则加分明显，没有不致命但可能被问住

#### N4 设计模式深入 (~28 点)

|为什么需要|设计模式在 Spring Core 里已经覆盖了一些（工厂/代理/模板方法/策略），但**不够深、不够系统**。大厂面试喜欢问："手写一个线程池"、"手写一个简单 RPC"，本质在考模式应用能力|
|---|---|
|**和现有的区别**|之前的设计模式散落在 Spring 各模块里作为附带知识点，这里需要**系统性整理 GoF 23 + 并发设计模式 + 架构模式**，并且每个都要有 **Java 手写实现**|
|**核心内容**|创建型(单例/工厂/建造者)/结构型(适配器/代理/装饰器/组合)/行为型(策略/模板/观察者/责任链/状态) + 并发模式(Future/Promise/Actor/Balking) + 架构模式(CQRS/EventSourcing/CDC)|

#### N5 算法与数据结构（按题算）

|为什么需要|大厂笔试**硬门槛**。不管你项目多牛，算法不过关连面试机会都没有|
|---|---|
|**注意**|这个不太适合用"知识点清单"的方式组织——更适合 **LeetCode 刷题计划**（如 Hot 100 / 剑指 Offer）。如果要列知识点，应该列的是「题型分类 + 解题模板」而非单个知识点|
|**建议处理方式**|列一个 **刷题路线图**（优先级排序的题单 + 每类题的解题套路），而不是 ~N 个知识点的形式。要不要单独做这个？|

#### N6 Linux & 工具链 (~20 点)

|为什么需要|日常排查问题的基本功。"线上 CPU 飙高了你怎么查？"答不上来很减分|
|---|---|
|**核心内容**|Linux 常用命令(top/vmstat/jstat/jmap/arthas) / Shell 脚本基础 / Git 高级操作(rebase/cherry-pick) / Maven 多模块 & 依赖冲突排查 / CI/CD 流水线概念(Jenkins/GitLab CI)|
